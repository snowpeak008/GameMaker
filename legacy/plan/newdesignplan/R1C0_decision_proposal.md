# R1-C0 内容宪章决策提案

状态：已签署  
日期：2026-07-15  
约束：R1 固定为 2D、单人、离线、authored 内容；PVZ 只用于验证玩法结构，不复制名称、角色、美术或关卡。

签署结果：用户于 2026-07-16 明确同意推荐组合 **A + M + P1 + V2**。

## 1. 决策原则

R1 的目标不是用最多内容证明“能生成很多文件”，而是用一份完成度足够高的垂直切片证明：设计、资产、代码、集成、测试和打包能够形成真实可玩的闭环。

因此推荐**中等内容量 + 高完成度**。继续扩大关卡和单位数量主要增加生产成本，不能等比例增加对通用系统的验证价值。

## 2. 三个成套方向

### 方案 A：微缩生态穹顶（推荐）

- 概念：玩家在横向通道中部署原创生态守卫，抵御失控孢群，恢复穹顶稳定。
- 体验重心：清晰克制、资源时机、波次压力、单位组合。
- 美术方向：明亮手绘 2D，轮廓优先，生态材质与工业 UI 形成对比；不使用任何现有游戏角色或造型。
- 优点：通道与阵营的视觉辨识度高，图像生成容易建立统一风格锚点，也能充分验证角色、特效、UI 和背景资产链。
- 风险：必须主动控制“植物防守”联想，角色结构、色彩语言和世界观需要保持原创。
- 相对生产成本：`1.0x`（比较基准）。

### 方案 B：星港能源阵线

- 概念：玩家部署模块化无人设备，保护多条能源传输通道免受异常机械群侵入。
- 体验重心：模块搭配、能量网络、护盾与穿透关系。
- 美术方向：清晰硬表面 2D、功能色编码、工业控制台 UI。
- 优点：原创边界最清楚，系统信息易于图标化。
- 风险：机械单位的形态一致性、透视和细节密度更难稳定，图像返工概率高于方案 A。
- 相对生产成本：约 `1.25x`。

### 方案 C：深海研究站

- 概念：玩家在海底设施的多条压力管线部署防御生物与设备，抵御深海异常体。
- 体验重心：视野、压力风险、环境事件与防线维护。
- 美术方向：高对比深海场景、生物荧光、仪表式 UI。
- 优点：视觉差异化最强，能测试环境表现与氛围质量。
- 风险：暗场可读性、透明特效和复杂背景会显著提高资产与 UI 验收难度。
- 相对生产成本：约 `1.5x`。

## 3. 完成度档位

### S：技术型切片

- 单一场景、少量单位、一个完整胜负循环、基础 UI 和音效。
- ProductEnvelope：`small / small / small / small`。
- 成本：约为 M 的 `40%`。
- 判断：能证明技术链，但不足以证明系统能产出有内容质量的游戏，不推荐。

### M：高完成度垂直切片（推荐）

- 多个连续阶段，完整教学、资源循环、单位克制、普通/精英/终局压力、轻量阶段解锁。
- 主菜单、阶段选择、游戏 HUD、暂停、结果、设置均完整；关键操作有动画、音效和状态反馈。
- 单次完整流程约 20–30 分钟，既能重复游玩，也能在验收时间内走完。
- ProductEnvelope：`medium / medium / medium / medium`。
- 成本：比较基准 `1.0x`。
- 判断：同时验证玩法、内容、资产一致性、保存、UI、测试和打包，是 R1 信息收益最高的档位。

### L：内容型试玩版

- 在 M 基础上扩大阶段、阵容、敌人、事件和局外成长。
- ProductEnvelope：至少三项 `large`。
- 成本：约为 M 的 `2.5–4.0x`，主要增长来自批量内容和美术，不是基础系统。
- 判断：适合 R1 通过后的产品扩展，不适合作为首次停止门。

## 4. 人工与自动边界

### 策略 P1：质量优先、可回放自动化（推荐）

| 节点 | 策略 |
|---|---|
| R1-C0 宪章、D4 规格冻结、Step14 对外发布 | `attended`，必须人工签署 |
| Step07 风格锚点与主角/核心 UI | `attended`，逐项确认 |
| Step07/12 同系列批量资产 | `sample(n)`；硬门禁全检，人工按资产家族抽样 |
| 高风险规格补丁、包络变化、保护字段 | `attended`，逐项确认 |
| 低风险规格补丁 | 默认 `attended` 批量确认；仅在显式批准路径上允许 `auto_accept` |
| Step08–10 确定性编译、Step11 执行与有界重试、Step13 测试 | `unattended`，全程审计、可停止、可续跑 |
| Step11 修正队列 | `attended` |

这个策略会真实测试无人值守能力，但不拿不可逆决策或美术品味冒险。

### 策略 P2：全程人工看护

- 所有 AI 补丁和资产逐批确认。
- 风险最低，但不能充分验证计划要求的自动流程化。
- 相对人工成本约为 P1 的 `1.8–2.5x`。

### 策略 P3：自动化优先

- 低/中风险补丁和大部分资产自动接受，仅关键锚点人工确认。
- 能较快验证吞吐量，但在 R1 尚无稳定质量基线时返工与漂移风险最高，不推荐作为首次垂直切片。

## 5. “真正可玩”的验收强度

### 验收 V1：闭环可运行

- 能开始、游玩、胜利、失败、重试和退出；无阻塞崩溃。
- 判断：只比 R0 强一层，不能代表可交付质量。

### 验收 V2：完整垂直切片（推荐）

- V1 全部成立；教学能让首次玩家完成基础操作。
- 资源产出/消耗、部署冷却、单位克制、波次升级和终局压力均有可执行正向与失败场景。
- 所有计划内单位、敌人、阶段、UI、音频和保存状态真实接入，不允许孤儿资产或占位成功。
- 关键反馈可读；无缺图、错误引用、不可达按钮、调试文字或静默 fallback。
- 最大设计负载下通过性能、暂停恢复、保存重载和完整流程回归。
- 所有机器场景通过；品味项按已签风格锚点人工复核。

### 验收 V3：外部试玩标准

- V2 基础上追加更长内容、更多平衡轮次和外部玩家测试。
- 成本显著依赖参与者与迭代轮数，适合 R1 通过后的产品验证，不作为自动生产系统的首个停止门。

## 6. 推荐组合

推荐签署：**A + M + P1 + V2**。

理由：该组合不是最小方案，也不靠无效堆量追求“大”；它把成本集中在最能暴露系统问题的地方：原创视觉一致性、完整玩法闭环、资产真实绑定、可信测试、保存/恢复、UI 与音频完成度，以及可审计的自动执行。
