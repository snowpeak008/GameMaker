# R1-C0 签署内容宪章

状态：已签署  
签署日期：2026-07-16  
签署来源：用户在当前开发会话中明确回复“同意 R1-C0 推荐组合 A + M + P1 + V2”。

## 1. 签署组合

- 内容方向：A，微缩生态穹顶。
- 完成度档位：M，高完成度垂直切片。
- 确认策略：P1，质量优先、可回放自动化。
- 验收强度：V2，完整垂直切片。

本宪章是 R1 垂直切片的产品合同。签署后如需变更题材、范围、确认策略或验收强度，必须记录修订理由、影响范围和重新签署时间。

## 2. 产品定义

R1 产物是一款原创 2D 单人离线通道防守游戏。玩家在多个横向通道中部署生态守卫，抵御失控孢群并恢复穹顶稳定。

R1 明确不复制任何现有游戏的名称、角色、美术造型、关卡文本或商业标识。PVZ 只作为“通道防守结构能否覆盖”的验证样例，不作为内容设计来源。

## 3. 范围边界

- 固定范围：2D、单人、离线、authored 内容。
- 完成度：多阶段连续流程、完整教学、资源循环、单位克制、普通/精英/终局压力、轻量阶段解锁。
- UI：主菜单、阶段选择、游戏 HUD、暂停、结果、设置均完整。
- 反馈：关键操作必须有动画、音效和状态反馈。
- 时长：单次完整流程约 20 到 30 分钟。
- 禁止范围：联网、多人、账号、付费、程序化生成承诺、开放世界、3D 生产链、外部实时服务依赖。

## 4. ProductEnvelope

机器层 ProductEnvelope 固定为：

```json
{
  "sceneScale": "medium",
  "systemComplexity": "medium",
  "assetScale": "medium",
  "contentVolume": "medium"
}
```

该包络进入冻结规格哈希。A05 之后任何扩大包络、绕过包络或把本机执行预算写入 GameSpec 的变更，都视为高风险变更。

## 5. 人工与自动边界

| 节点 | 策略 |
|---|---|
| R1-C0 宪章、D4 规格冻结、Step14 对外发布 | `attended`，必须人工签署 |
| Step07 风格锚点与主角/核心 UI | `attended`，逐项确认 |
| Step07/12 同系列批量资产 | `sample(n)`；硬门禁全检，人工按资产家族抽样 |
| 高风险规格补丁、包络变化、保护字段 | `attended`，逐项确认 |
| 低风险规格补丁 | 默认 `attended` 批量确认；仅在显式批准路径上允许 `auto_accept` |
| Step08-10 确定性编译、Step11 执行与有界重试、Step13 测试 | `unattended`，全程审计、可停止、可续跑 |
| Step11 修正队列 | `attended` |

AI 只允许产生候选补丁、候选资产或候选说明。AI 不能直接提交 canonical GameSpec，不能裁决验收，不能绕过人工确认策略。

## 6. 可玩标准

R1 必须满足 V2 完整垂直切片：

- 能开始、游玩、胜利、失败、重试、暂停、恢复、保存、重载和退出。
- 教学能让首次玩家完成基础操作。
- 资源产出/消耗、部署冷却、单位克制、波次升级和终局压力都有可执行正向与失败场景。
- 所有计划内单位、敌人、阶段、UI、音频和保存状态真实接入。
- 不允许孤儿资产、缺图、错误引用、不可达按钮、调试文字或静默 fallback。
- 最大设计负载下通过性能、暂停恢复、保存重载和完整流程回归。
- 品味项按 Step07 已签风格锚点人工复核，机器场景全部通过。
