# 美术资源后处理流水线计划索引

## 背景与问题定位

当前流水线（`deal/` 计划）已完成：
- Step04：资源需求合同（`asset_spec_contract`、`asset_registry`、`unity_asset_mount_plan`）
- Step12：美术生产报告（`art_production_report`、`audio_placeholder_manifest_runtime`）
- Step13：场景装配（Camera、Canvas、EventSystem、InputRouter、ObjectiveTracker）

**尚未解决的两层问题：**

1. AI 生成图像只是概念图/气氛图，不是可消费资产
   - 缺少规格校验（尺寸、透明通道、视角、命名）
   - 缺少切片规格定义（按钮/面板/图标/背景/九宫格各自的切片规则）

2. 从图片到程序功能绑定的链路未建立
   - 缺少完整 Unity TextureImporter 配置生成
   - 缺少 SpriteAtlas 归档计划
   - 缺少 UGUI Prefab 自动拼装规范
   - 缺少 UIController/InputRouter/GameState 与资产的绑定合同
   - Step14 当前只验证对象存在，缺少实际可见性和交互的美术验收

## 流水线扩展位置

```

  └── Step04-Art-A  图像规格校验合同（定义可消费资产的标准）
  └── Step04-Art-B  UI切片规格合同（定义每类 UI 图片的切割规则）

  └── Step14-Art-A  美术验收扩展（可见性/交互/状态推进的图像层验证）
```

## 与 deal/ 计划的关系

- 本目录计划是 `deal/` 计划的**扩展**，不替代
- 依赖 `deal/11_Step04` 产出的 `asset_spec_contract.json` 和 `asset_registry.json`
- 依赖 `deal/20_Step12` 产出的 `art_production_report.json`
- 依赖 `deal/10_Step03` 产出的 `program_requirements_contract.json` 和 `program_structure_spec.json`
- 不改变 `deal/` 计划中已定义的 artifact 路径、schema 名称、registry 条目

## 执行顺序

必须在对应的 `deal/` 原子计划完成后才能开始对应的 art 扩展：

```
deal/11（Step04完成）→ art/01 → art/02
deal/20（Step12完成）→ art/03 → art/04 → art/05
deal/12+20（Step08+Step12完成）→ art/06
deal/13+art/06完成 → art/07
```

标准化开发时采用新顺序：

```
art/08 总设计确认
  → art/09 代码结构与合同标准确认
  → art/10 Art-00 到 Art-11 逐项实现
```

## 总体验收标准

所有 art 计划完成后，系统必须满足：

1. AI 图像进入流水线前必须通过规格校验（尺寸/透明度/命名）
2. 每个 UI 类型图像有明确的切片规格，不依赖人工猜测
3. 所有资产有完整 Unity TextureImporter 配置，不只是 3 个字段
4. 相关 UI 资产归入 SpriteAtlas，目录结构符合 Unity 项目规范
5. 每个 `ui_flow_contract.screens` 条目有对应的 UGUI Prefab 层级规范
6. UIController、InputRouter、GameState 与各 Prefab 的绑定关系有合同记录
7. Step14 能验证指定 UI 资产在 Play 后可见，且点击后有状态变化
