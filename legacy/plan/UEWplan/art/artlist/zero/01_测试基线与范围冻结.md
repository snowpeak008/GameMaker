# 01 测试基线与范围冻结

## 目标

在任何代码修改前记录测试基线，冻结本轮开发范围，避免把历史遗留失败、旧计划清理、Unity 环境问题混入美术资产管线实现。

## 修改范围

```text
plan/UEWplan/art/artlist/test_baseline_before_art_pipeline.md
plan/UEWplan/art/artlist/zero/
```

本原子计划原则上不修改运行时代码。

## 执行步骤

1. 运行完整测试基线：

```powershell
python -m pytest core/tests/ --tb=no -q > plan/UEWplan/art/artlist/test_baseline_before_art_pipeline.md 2>&1
```

2. 记录当前失败项：
   - 标记为历史问题、环境问题、本轮相关问题。
   - 本轮只处理与 art pipeline 直接相关的问题。

3. 确认当前真实 pipeline 路径：
   - `pipeline/step_04_art_requirements/plugin.py`
   - `pipeline/step_09_art_plan/plugin.py`
   - `pipeline/step_12_art_production/plugin.py`
   - `pipeline/step_13_scene_assembly/plugin.py`
   - `pipeline/step_14_integration_validation/plugin.py`

## 验收标准

- 测试基线文件存在。
- 基线失败项不被误认为本轮新增失败。
- 不创建 `step_09_art_planning` 或 `step_14_playable_acceptance` 重复目录。
- 不修改业务代码。

## 禁止事项

- 不清理旧存档。
- 不顺手修 unrelated 历史失败。
- 不改动 `core/engines/generation.py`。
