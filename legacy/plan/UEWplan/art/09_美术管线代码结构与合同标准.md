# 美术管线代码结构与合同标准

## 目标

本文件定义标准代码结构、合同边界、registry 更新和测试要求。实现时不能把逻辑继续堆进 `core/engines/generation.py`，也不能只在 pipeline plugin 中写零散函数。美术资产管线需要独立服务层，pipeline step 只负责装配输入、调用服务、写 artifact、处理状态。

## 核心模型

### `AssetLifecycleRecord`

必需字段：

```json
{
  "asset_id": "ui.start_button",
  "asset_kind": "control",
  "priority": "P0",
  "lifecycle_state": "processed",
  "raw_path": "outputs/artifacts/stage_12/generated_raw/ui.start_button.png",
  "processed_path": "outputs/artifacts/stage_12/processed/ui.start_button.png",
  "unity_target_path": "Assets/AutoDesign/Art/Processed/UI/ui.start_button.png",
  "source_refs": [
    "stage_02.ui_flow_contract:screens.main_menu.controls.start",
    "stage_04.asset_registry:ui.start_button",
    "stage_09.art_production_task_contract:ART-001"
  ],
  "blocking_issues": []
}
```

### `AssetIssue`

必需字段：

```json
{
  "issue_id": "ART-BLOCK-0001",
  "asset_id": "ui.start_button",
  "severity": "blocking",
  "code": "INVALID_IMAGE_DIMENSIONS",
  "message": "Expected 512x128, got 1024x1024.",
  "stage": "Step12-Art-02",
  "repair_action": "regenerate",
  "source_refs": []
}
```

### `ArtPipelineResult`

所有服务返回统一结构，不能只返回 dict。

```json
{
  "status": "passed",
  "records": [],
  "issues": [],
  "artifacts": [],
  "metrics": {}
}
```

允许状态：

- `passed`
- `completed_with_review`
- `blocked`
- `environment_blocked`
- `failed`

## Pipeline Step 职责

### Step04

职责：

- 从 Stage02 UI/runtime/input/objective contracts 和 asset requirement 生成资产消费规格。
- 不能只输出资产列表。
- 必须输出 `image_consumable_spec.json`、`ui_slice_spec_contract.json`、`unity_import_policy.json`、`asset_usage_binding_seed.json`。

测试：

- 无 UI flow 时，不生成 UI Prefab 需求，但仍生成非 UI 资产规格。
- 有 UI flow 时，每个 screen/control 至少有一个 asset usage 或明确无需美术资源。

### Step09

职责：

- 将资产规格转换为可执行美术任务。
- 每个任务必须携带技术规格、语义规格、切片规格、目标挂载点、返工策略。

测试：

- P0 资产缺 prompt 或 acceptance criteria 时 blocked。

### Step12

职责：

- 调用 `ArtProductionOrchestrator`。
- 执行 raw intake、technical validation、semantic validation、normalization、slicing、import planning、prefab planning、handoff。
- 写所有 Step12 artifacts。
- 根据 blocking issues 决定 step 状态。

测试：

- 概念图 marker 进入 Step12 时，P0 资产必须 blocked。
- 图片尺寸不符合要求时，P0 资产必须 blocked。
- UI button 没有 normal/pressed/disabled 或没有 fallback 时，必须进入 review 或 blocked。
- handoff `ready_for_step13=false` 时，Step13 不能继续。

### Step13

职责：

- 强消费 `art_handoff_manifest.json`。
- 生成 Unity Editor request。
- 写入 Unity 工程资产。
- 通过 Unity Editor Script 执行导入、切片、Prefab 和绑定。
- 读取 Editor Script 输出并写报告。

禁止：

- 不允许只生成 JSON 后宣称挂载完成。
- 不允许 runtime `Find()` 代替序列化绑定，除非合同明确标记为临时诊断路径且不进入正式验收。

测试：

- handoff missing 时 blocked。
- Prefab generation report 中缺 screen prefab 时 failed。
- serialized field 未赋值时 failed。

### Step14

职责：

- 合并 art acceptance 和 playable acceptance。
- 验证上层设计需求是否被真实 UI/场景/输入/状态满足。

测试：

- 首屏没有任何 enabled Graphic 时 failed。
- Button 点击后 action 不触发时 failed。
- Data binding 无变化且设计要求变化时 failed。

## Unity Editor Script 标准

Editor Script 由 Step13 写入 Unity 项目的 `Assets/AutoDesign/Editor/`，并通过 batchmode 调用。所有自动生成资源统一使用 `Assets/AutoDesign/` 作为根目录；`Assets/Scenes/DemoScene.unity` 只作为场景路径，不是生成资产根。

首次写入 Editor Script 后，Unity 需要先完成编译，不能立即假设 `-executeMethod` 可用。标准启动序列是：

```powershell
Unity.exe -batchmode -projectPath <generated_unity_project> -quit -logFile compile.log
Unity.exe -batchmode -projectPath <generated_unity_project> -executeMethod AutoDesignAssetImporter.Run
Unity.exe -batchmode -projectPath <generated_unity_project> -executeMethod AutoDesignPrefabBuilder.Run
Unity.exe -batchmode -projectPath <generated_unity_project> -executeMethod AutoDesignSceneBinder.Run
```

如果复用已有 `Assets/Editor/AutoDesignMaker/PlayableSceneBootstrapBuilder.cs` 一类预编译 bootstrap，必须在 `unity_editor_request.json` 中记录 bootstrap 路径和 execute method。

### `AutoDesignAssetImporter`

职责：

- 读取 `unity_import_settings_manifest.json`。
- 设置 `TextureImporter`。
- 应用 `SpriteMetaData` 和 border。
- 保存并重新导入资源。
- 输出 `unity_art_import_report.json`。

### `AutoDesignPrefabBuilder`

职责：

- 读取 `ugui_prefab_contract.json`。
- 创建 Canvas、Prefab、UI 节点。
- 给 Image/Button/Text/TMP/Slider 赋值。
- 保存 Prefab。
- 输出 `unity_prefab_generation_report.json`。

### `AutoDesignSceneBinder`

职责：

- 读取 `program_asset_binding_contract.json`。
- 创建或更新 RuntimeBootstrap、UIController、InputRouter、ObjectiveTracker。
- 注入 serialized fields。
- 保存 Scene。
- 输出 `unity_scene_mount_report.json`。


- `raw_generated_asset_manifest.json`
