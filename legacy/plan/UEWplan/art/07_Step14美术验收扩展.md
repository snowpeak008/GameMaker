# Step14 美术验收扩展（Step14-Art-A）

> 路径说明：本文是早期拆分计划。最终实现路径以 `artlist/01_标准化美术资产管线开发计划.md` 为准，自动生成美术和 UI 资产统一写入 `Assets/AutoDesign/`。本文中旧的 `Assets/Art/...` 示例不得作为实现路径。

## 目标

在现有 Step14 四级验证（静态结构/EditMode/PlayMode/像素）基础上，增加美术资产专项验收：
- 校验已绑定资产在 Play 后实际可见
- 校验按钮点击后状态有变化（不是空壳）
- 校验 Atlas 正确加载（无 Missing Sprite）
- 校验 UI 数据绑定实际更新（数字变化）

## 当前 Step14 的局限

`deal/14_Step14可玩集成验证原子计划.md` 定义了 4 级验证：
- Level 1：Entry Scene 存在、Camera、Canvas、InputRouter、ObjectiveTracker
- Level 2：Unity batchmode 编译通过
- Level 3：PlayMode 状态变化
- Level 4：摄像机渲染非空

**缺少：**
- Level 3 没有验证 UI 数据绑定（只验证"有没有"，不验证"对不对"）
- 没有验证资产是否 Missing Sprite（有 Image 组件但 Sprite 未赋值）
- 没有验证按钮点击后 UI 状态变化（只验证 GameState 变化）
- 没有验证 `serialized_field_manifest` 中的字段实际被赋值

## 美术专项验收检查类型

### `sprite_assigned`（Level 1 静态）
验证 Image/SpriteRenderer 组件的 sprite 字段不为 null：
```json
{
  "check_id": "sprite_hud_resource_panel",
  "check_type": "sprite_assigned",
  "target_path": "UIRoot/Screen_GameHUD/ResourcePanel",
  "expected": "sprite != null",
  "blocking": true,
  "validation_level": 1
}
```

### `ui_visible_on_start`（Level 3 PlayMode）
验证 `visible_on_start = true` 的 Screen 在进入 Play 后 GameObject 为 activeSelf：
```json
{
  "check_id": "visible_game_hud",
  "check_type": "ui_visible_on_start",
  "target_path": "UIRoot/Screen_GameHUD",
  "expected": "activeSelf == true",
  "blocking": true,
  "validation_level": 3
}
```

### `button_triggers_state`（Level 3 PlayMode）
模拟点击按钮后，对应 GameState 字段发生变化：
```json
{
  "check_id": "btn_build_opens_menu",
  "check_type": "button_triggers_state",
  "target_path": "UIRoot/Screen_GameHUD/Btn_Build",
  "expected": "Screen_BuildMenu.activeSelf changes from false to true after click",
  "blocking": true,
  "validation_level": 3
}
```

### `data_binding_updates`（Level 3 PlayMode）
等待 N 秒后，数据绑定的文本显示值有变化：
```json
{
  "check_id": "db_iron_updates",
  "check_type": "data_binding_updates",
  "target_path": "UIRoot/Screen_GameHUD/ResourcePanel/IronOreLabel",
  "expected": "TMP_Text.text changes within 10s (initial state not preserved)",
  "blocking": false,
  "validation_level": 3
}
```

### `atlas_no_missing_sprite`（Level 2 EditMode）
检查 `sprite_atlas_plan.json` 中所有 Atlas 对应的 Sprite 文件实际存在：
```json
{
  "check_id": "atlas_buttons_complete",
  "check_type": "atlas_no_missing_sprite",
  "target_path": "Assets/AutoDesign/Art/Atlas/UIAtlas_Buttons.spriteatlasv2",
  "expected": "all included_assets files exist at their unity_target_path",
  "blocking": true,
  "validation_level": 1
}
```

### `serialized_field_assigned`（Level 2 EditMode）
通过 `program_asset_binding_contract.json` 的 `serialized_field_manifest`，验证指定字段在对应 Prefab 上已赋值：
```json
{
  "check_id": "uic_resource_panel_assigned",
  "check_type": "serialized_field_assigned",
  "target_path": "UIController (on GameManager)",
  "expected": "field 'resourcePanel' != null",
  "blocking": true,
  "validation_level": 2
}
```

## 从已有合同生成 art_checks 的规则

```python
def build_art_acceptance_contract(
    ugui_prefab_spec,
    program_asset_binding_contract,
    sprite_atlas_plan,
    image_spec_validation_contract,
) -> dict:
    checks = []
    
    # 1. 为每个有 sprite_asset_id 的节点生成 sprite_assigned 检查
    for screen in ugui_prefab_spec["screens"]:
        for node in walk_nodes(screen["root_object"]):
            if node.get("sprite_asset_id"):
                checks.append(sprite_assigned_check(node, screen))
    
    # 2. 为 visible_on_start=True 的 screen 生成 ui_visible_on_start 检查
    for screen in ugui_prefab_spec["screens"]:
        if screen["visible_on_start"]:
            checks.append(ui_visible_check(screen))
    
    # 3. 为每个 event_listener binding 生成 button_triggers_state 检查
    for binding in program_asset_binding_contract["bindings"]:
        if binding["binding_type"] == "event_listener":
            checks.append(button_triggers_state_check(binding))
    
    # 4. 为每个 data_binding 生成 data_binding_updates 检查（非阻断）
    for binding in program_asset_binding_contract["bindings"]:
        if binding["binding_type"] == "data_binding":
            checks.append(data_binding_check(binding, blocking=False))
    
    # 5. 为每个 Atlas 生成 atlas_no_missing_sprite 检查
    for atlas in sprite_atlas_plan["atlases"]:
        checks.append(atlas_missing_check(atlas))
    
    # 6. 为 serialized_field_manifest 生成字段赋值检查
    for field in program_asset_binding_contract["serialized_field_manifest"]:
        checks.append(serialized_field_check(field))
    
    return { "art_checks": checks }
```

## Step14 扩展执行流程

```
原 Level 1（静态结构）→ + sprite_assigned + atlas_no_missing_sprite + serialized_field_assigned
原 Level 2（EditMode）→ + serialized_field_assigned（Inspector 检查）
原 Level 3（PlayMode）→ + button_triggers_state + data_binding_updates + ui_visible_on_start
原 Level 4（像素）   → 不变
```

`art_acceptance_contract.json` 中 `blocking=true` 的 check 失败 → Step14 `failed`
`blocking=false` 的 check 失败 → 记录为 `warning`，不影响整体结果

## 完成标准

1. Step14 生成 `art_acceptance_contract.json`（即使 Unity 不可用，Level 1 checks 仍可静态执行）。
2. 所有 blocking=true 的 Level 1 checks（sprite_assigned、atlas_no_missing_sprite）在 Level 1 阶段执行。
3. button_triggers_state 和 data_binding_updates 在 Level 3 可用时执行，不可用时记录 skipped。
4. 最终验收报告包含 art checks 摘要（passed/failed/skipped/warning 计数，与原有 playmode checks 合并）。
5. 单元测试：`test_art_acceptance_builder.py` 覆盖 sprite_assigned 和 atlas_missing 两类。

## 不做事项

- 不做像素级截图比对（Level 4 范围，已在 deal/14 中定义）。
- 不验证美术风格是否符合 art_direction_decision（主观判断，不可自动化）。
- 不阻断 Unity 不可用时的整体流程（返回 environment_blocked，不返回 failed）。
