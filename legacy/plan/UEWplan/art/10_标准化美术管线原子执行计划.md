# 标准化美术管线原子执行计划

## 执行原则

本计划按开发顺序拆分。每个原子任务都必须产出可运行代码、schema、artifact 注册和测试。不能只写文档、只写合同、只写 TODO。

执行前先记录测试基线：

```powershell
python -m pytest core/tests/ --tb=no -q > plan/UEWplan/art/test_baseline_before_art_pipeline.md 2>&1
```

## Plan Art-00：Schema 和 Registry 基线

### 目标

建立美术管线的 schema 命名空间、registry 条目和 dependency graph 边。

### 修改范围

```text
knowledge/schemas/ai_design/art_pipeline/
pipeline/artifact_layer/registry.json
pipeline/artifact_layer/dependency_graph.json
core/tests/unit/test_artifact_registry_playable_chain.py
```

### 输出

- registry 中引用的 schema 文件全部存在。
- dependency graph 能表达 Step13 对 `art_handoff_manifest.json` 的依赖。

### 修改范围

## Plan Art-05：图像归档和 Sprite 切片元数据

### 目标

让 Step12 生成 Unity 可消费的资产拷贝/命名结果和 Sprite 切片元数据。Python 不做实际像素切割，实际 Sprite 切割由 Step13 的 Unity Editor Script 通过 `TextureImporter` 和 reimport 执行。

### 修改范围

```text
core/art_pipeline/services/asset_normalizer.py
core/art_pipeline/services/sprite_slicer.py
core/tests/unit/test_art_pipeline_sprite_slicer.py
```

### 输出

- `processed_asset_manifest.json`
- `sprite_slice_result_manifest.json`

### 验收

- `sprite_slicer.py` 不包含实际像素切割、resize、crop、trim 或重新编码逻辑。
- `sprite_slice_result_manifest.json` 包含 `sprite_id`、`rect`、`border`、`pivot`、`pixels_per_unit`、`fallback_sprite_id` 和 `source_refs`。
- `nine_slice` 有 border 并被写入结果。
- `button_state_set` 至少有 normal、pressed、disabled；缺 highlighted 时必须有 fallback。
- 切片结果生成稳定 `sprite_id`。
- 切片失败的 P0/P1 资产阻断。

## 完成后用户操作

开发完成并通过测试后，用户只需要：

1. 创建或选择新的项目存档。
2. 从设计阶段重新运行到 Step14，或至少从 Step04 重新运行到 Step14。
3. 打开生成的 Unity 项目。
4. 点击 Play，首屏应有 UI、可交互控件和状态推进。

如果 Step12 或 Step13 进入 `completed_with_review` / `blocked`，不要直接跳 Step13 或打开 Unity 期待有画面，应先处理 `art_rework_queue.json` 或对应 blocking report。
