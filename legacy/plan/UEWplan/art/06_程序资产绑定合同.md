# 程序资产绑定合同（Step13-Art-A）

## 目标

建立 UIController / InputRouter / GameState 与 UGUI Prefab 资产之间的绑定合同，让 Step13 装配完场景后，所有程序组件都知道自己要挂到哪个 UI 对象，绑定哪个事件，驱动哪个状态字段。

## 问题根因

`program_requirements_contract.json`（Step03 输出）定义了需要哪些程序系统（UIController、InputRouter、ObjectiveTracker 等）。`ugui_prefab_spec_contract.json`（Step12 输出）定义了 UI 层级和节点结构。但两者之间缺乏显式的绑定映射：

- UIController 应该持有哪些 UI 对象引用？
- InputRouter 的哪个 action 对应哪个 Button？
- GameState 的哪个字段驱动哪个 Text 节点？

没有这个绑定合同，Unity 程序员需要手动在 Inspector 中连线，或者靠运行时 `Find()` 查找对象，两者都是不可维护的。

## 绑定类型详解

### `ui_reference`（UI 对象引用）

UIController 需要持有对 UI 节点的引用，以便显示/隐藏/更新：

```json
{
  "binding_id":       "uic_resource_panel",
  "binding_type":     "ui_reference",
  "component_class":  "UIController",
  "field_name":       "resourcePanel",
  "target_path":      "UIRoot/Screen_GameHUD/ResourcePanel",
  "target_component": "RectTransform"
}
```

### `event_listener`（事件监听）

InputRouter 或 UIController 监听 Button 点击事件：

```json
{
  "binding_id":       "ir_btn_build",
  "binding_type":     "event_listener",
  "component_class":  "InputRouter",
  "field_name":       "onBuildButtonPressed",
  "target_path":      "UIRoot/Screen_GameHUD/Btn_Build",
  "target_component": "Button",
  "action_id":        "open_build_menu"
}
```

### `data_binding`（数据绑定）

UIController 将 GameState 数据字段同步到 Text/Slider：

```json
{
  "binding_id":    "db_iron_count",
  "binding_type":  "data_binding",
  "component_class": "UIController",
  "field_name":    "ironOreCountLabel",
  "target_path":   "UIRoot/Screen_GameHUD/ResourcePanel/IronOreLabel",
  "target_component": "TMP_Text",
  "data_key":      "resource_count.ironOreCount",
  "update_mode":   "on_change"
}
```

### `state_observer`（状态观察）

ObjectiveTracker 监听 GameState 完成条件：

```json
{
  "binding_id":    "so_objective_progress",
  "binding_type":  "state_observer",
  "component_class": "ObjectiveTracker",
  "field_name":    "progressBar",
  "target_path":   "UIRoot/Screen_GameHUD/ObjectivePanel/ProgressBar",
  "target_component": "Slider",
  "state_field":   "demo_state.progress",
  "update_mode":   "on_change"
}
```

## 从已有合同生成绑定的规则

```python
def build_program_asset_binding_contract(
    program_req_contract,    # Step03 输出
    ugui_prefab_spec,        # Step12-Art-C 输出
    ui_flow_contract,        # Stage02 frozen
) -> dict:
    bindings = []
    
    # 1. 为所有 screen 的 root_object 生成 ui_reference 绑定
    for screen in ugui_prefab_spec["screens"]:
        for node in walk_nodes(screen["root_object"]):
            if node["component_type"] in ("Panel", "Image"):
                bindings.append(ui_reference_binding(node, screen))
            
            # 2. 为所有 Button 生成 event_listener 绑定
            if node["component_type"] == "Button":
                bindings.append(event_listener_binding(node, ui_flow_contract))
            
            # 3. 为所有有 data_binding_key 的节点生成 data_binding
            if node.get("data_binding_key"):
                bindings.append(data_binding_entry(node, ui_flow_contract))
    
    # 4. 为 ObjectiveTracker 生成 state_observer
    for req in program_req_contract["tasks"]:
        if "ObjectiveTracker" in req["module"]:
            bindings.append(state_observer_binding(req, ugui_prefab_spec))
    
    # 5. 生成 serialized_field_manifest（C# Inspector 连线清单）
    manifest = [
        { "class_name": b["component_class"], "field_name": b["field_name"], 
          "field_type": b["target_component"], "target_path": b["target_path"] }
        for b in bindings if b["binding_type"] in ("ui_reference", "data_binding", "state_observer")
    ]
    
    return { "bindings": bindings, "serialized_field_manifest": manifest }
```

## `serialized_field_manifest` 的用途

`serialized_field_manifest` 是 Step13 生成 C# 代码时的依据：
- Step13 读取此清单，在对应 C# 类中生成 `[SerializeField]` 字段声明
- 或生成 Unity Editor Script，在 Awake() 中通过路径自动找到对象并赋值

示例生成代码（Step13 输出）：
```csharp
// Auto-generated by Step13 from program_asset_binding_contract.json
public class UIController : MonoBehaviour {
    [SerializeField] private RectTransform resourcePanel;     // → UIRoot/Screen_GameHUD/ResourcePanel
    [SerializeField] private TMP_Text ironOreCountLabel;      // → .../IronOreLabel
    [SerializeField] private Slider progressBar;              // → .../ProgressBar
    // ... (more from serialized_field_manifest)
}
```

## 完成标准

1. Step13 输出 `program_asset_binding_contract.json`。
2. 每个 `action_id` 在 `ui_flow_contract.input_entry_points` 中有对应记录。
3. 每个 `data_key` 在 `ui_flow_contract.data_bindings` 中有对应记录。
4. `serialized_field_manifest` 包含 UIController、InputRouter、ObjectiveTracker 的所有字段。
5. 无 `target_path` 为空的 binding 条目。
6. 单元测试：1个带 Button + 1个带 Text 的 screen → 正确生成 event_listener + data_binding。

## 不做事项

- 不生成 `UnityEngine.Events.UnityEvent` 的序列化数据（只记录绑定规范）。
- 不处理动画事件绑定。
- 不处理多 Canvas 或嵌套 Canvas 场景。
