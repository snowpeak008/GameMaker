# Step14可玩集成验证原子计划

## 目标

让 Step14 验证 Unity 项目是否真的可运行、可见、可交互、可推进。

该计划完成后，Unity Play 后如果没有 UI、没有场景、没有输入反馈或没有目标进度，Step14 必须失败或明确标记为环境不可执行，不能假 success。

## 依赖

- `13_Step13Unity场景装配原子计划.md`

## 涉及范围

重点修改：

```text
pipeline/step_14_integration_validation/plugin.py
core/engines/generation.py
```

可能涉及 Unity batchmode、EditMode/PlayMode 测试模板、测试报告解析。

建议新增测试：

```text
core/tests/unit/test_step14_playable_acceptance_contract.py
core/tests/unit/test_step14_detects_missing_ui.py
core/tests/unit/test_step14_validation_levels.py
```

## 输入

Step14 必须读取：

- `playable_acceptance_contract`
- Step13 scene assembly report。
- Unity 测试结果。

## 分层验证策略

### Level 1：静态结构验证

无需启动 Unity Play。

验证：

- Entry Scene 文件存在。
- 场景装配报告包含 Camera。
- 场景装配报告包含 Canvas/UIRoot。
- 场景装配报告包含 EventSystem。
- 场景装配报告包含 InputRouter。
- 场景装配报告包含 ObjectiveTracker。
- 音频占位 marker 或声明路径存在。

Level 1 缺失 P0 项必须 failed。

### Level 2：Unity batchmode 编译/EditMode 验证

调用 Unity batchmode 或现有项目封装执行：

- 脚本编译。
- EditMode 组件存在性检查。
- scene build settings 检查。

Unity 路径不可用时不能假 success，必须输出 `environment_blocked`，并说明缺少 Unity 可执行路径。

### Level 3：PlayMode 行为验证

在环境允许时执行：

- Entry Scene 可加载。
- RuntimeBootstrap 初始化。
- UI Root 可见。
- 输入动作可触发状态变化。
- Objective 进度可变化。

如果无显示环境，允许跳过像素级检查，但不能跳过状态和对象存在性检查。

### Level 4：可视化或像素验证

仅在支持 GameView、RenderTexture 或截图输出时执行。

验证：

- 摄像机渲染非空画面。
- 初始 UI 可见。

该级别不可用时标记为 skipped_with_reason，不应掩盖 Level 1-3 的失败。

## 输出

```text
integration_validation_report.json
playmode_test_results.json
playable_acceptance_report.md
```

## 执行步骤

1. 加载 `playable_acceptance_contract`。
2. 加载 Step13 装配报告。
3. 执行 Level 1 静态结构验证。
4. 检测 Unity 可执行路径。
5. 可用时执行 Level 2。
6. 可用时执行 Level 3。
7. 支持时执行 Level 4。
8. 合并验证结果。
9. 输出验证报告。

## 失败条件

以下情况 Step14 必须 failed：

- 无 Entry Scene。
- 无 active camera 声明。
- 无 Canvas/UIRoot。
- 无初始 UI。
- 无输入入口。
- 无目标追踪。
- 输入无状态变化且环境支持 PlayMode。
- 目标进度无变化且环境支持 PlayMode。
- 出现 blocking exception。

以下情况可以 environment_blocked：

- Unity 可执行路径缺失。
- Unity license 或 batchmode 环境不可用。
- 测试 runner 无法启动。

## 完成标准

1. 缺 UI 的项目 Step14 failed。
2. 缺 Camera 的项目 Step14 failed。
3. 缺输入入口的项目 Step14 failed。
4. 缺目标追踪的项目 Step14 failed。
5. Unity 不可用时输出 environment_blocked，不输出 success。
6. 成功项目有完整验收报告。

## 不做事项

- 不做人工截图目测代替测试。
- 不把 Step14 移到独立审查阶段。
- 不允许仅凭文件存在判断 playable。
