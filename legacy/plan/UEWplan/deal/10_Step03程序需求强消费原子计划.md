# Step03程序需求强消费原子计划

## 目标

让 Step03 从 Stage02 frozen playable contracts 生成程序需求，而不是从自然语言设计文本中推断。

该计划完成后，Step03 必须明确输出支持 UI、场景、输入、目标和运行状态所需的程序系统。

## 依赖

- `09_Step02设计冻结强消费原子计划.md`

## 涉及范围

重点修改：

```text
pipeline/step_03_program_requirements/plugin.py
core/engines/generation.py
```

建议新增测试：

```text
core/tests/unit/test_step03_program_requirements_from_contracts.py
```

## 输入合同

Step03 必须读取：

- `runtime_data_contract`
- `ui_flow_contract`
- `scene_bootstrap_contract`
- `playable_acceptance_contract`
- `core_playable_contract`
- `demo_flow_contract`

## 输出要求

Step03 应输出：

```text
program_requirements_contract.json
program_requirement_trace_report.json
program_structure_spec.json
```

其中 `program_requirements_contract.json` 应包含：

- RuntimeBootstrap 需求。
- GameState 需求。
- InputRouter 需求。
- UIController 需求。
- ObjectiveTracker 需求。
- SceneBootstrap 需求。
- CameraRig 需求。
- DataModel 需求。
- TestHook 需求。

`program_requirement_trace_report.json` 是现有 registry 已登记 artifact，必须保留，用于记录每条程序需求与 playable contract/source_refs 的追溯关系。

`program_structure_spec.json` 是结构说明文档或结构化辅助文件，不替代 trace report。

## artifact registry 条目

需要在 `pipeline/artifact_layer/registry.json` 的 `stage_03.program_requirements_bundle.schema_refs` 中新增或确认以下条目：

| path | schema | consumed_by |
|---|---|---|
| `outputs/artifacts/stage_03/program_requirements_contract.json` | `knowledge/schemas/program_requirements_contract.schema.json` | Step05, Step08 |
| `outputs/artifacts/stage_03/program_requirement_trace_report.json` | `knowledge/schemas/ai_design/program_requirement_trace_report.schema.json` | Step05, Step08 |
| `outputs/artifacts/stage_03/program_structure_spec.json` | `knowledge/schemas/ai_design/program_structure_spec.schema.json` | Step08, Step11 |

如果现有 registry 已有其中某项，实施时应确认 schema、路径和 consumed_by 关系与本计划一致，不重复新增。

## 新增 schema 最低结构

`program_requirements_contract.schema.json` 和 `program_requirement_trace_report.schema.json` 已有定义时，实施时只确认路径和 required 字段兼容，不新建重复 schema。

## 执行步骤

1. 加载 Stage02 frozen playable contracts。
2. 从 `runtime_data_contract` 生成数据模型需求。
3. 从 `ui_flow_contract` 生成 UI 控制器需求。
4. 从 `core_playable_contract.action_verbs` 生成输入路由需求。
5. 从 `scene_bootstrap_contract` 生成场景启动与摄像机需求。
6. 从 `demo_flow_contract` 生成目标流程需求。
7. 从 `playable_acceptance_contract` 生成测试 hook 需求。
8. 输出 `program_requirements_contract.json`、`program_requirement_trace_report.json`、`program_structure_spec.json`。

## 完成标准

1. Step03 输出 `program_requirements_contract.json`。
2. Step03 输出 `program_requirement_trace_report.json`，且 traceability 不为空。
3. Step03 输出包含 UIController。
4. Step03 输出包含 SceneBootstrap。
5. Step03 输出包含 InputRouter。
6. Step03 输出包含 ObjectiveTracker。
7. Step03 输出包含 TestHook。
8. 缺 frozen contract 时 Step03 blocked。

## 不做事项

- 不生成美术资源。
- 不进行 Unity 场景装配。
- 不写工厂建造专用系统到核心需求。
