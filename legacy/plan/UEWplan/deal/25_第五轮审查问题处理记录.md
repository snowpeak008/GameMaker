# 第五轮审查问题处理记录

本文件记录第五轮审查提出的残留问题处理结果。

第五轮问题聚焦 Plan10/11 已声明新增 artifact，但部分 schema 文件不存在且计划中没有最低 required 字段结构。该问题不是新增玩法需求，而是对已声明产物的消费契约补全。

## 处理结果总览

| 编号 | 原级别 | 问题 | 处理状态 | 落点 |
|---|---|---|---|---|
| 1 | P1 | Plan10 缺少 `program_structure_spec.schema.json` 最低结构 | 已处理 | `10`、`15` |
| 2 | P1 | Plan11 缺少资源链路新增 schema 最低结构 | 已处理 | `11`、`15` |
| 3 | P1 | Plan11 `art_requirements_contract` schema 路径与现有文件不一致 | 已处理 | `11`、`15` |

## 关键修复说明

### 1. Plan10 schema 补全

计划 `10` 已新增 `program_structure_spec.schema.json` 最低结构。

该 schema 至少约束：

- `allowed_roots`
- `system_path_map`
- `path_binding_contract`
- `output_file_rules`

这些字段对应 Step08/11 需要读取的程序路径、允许写入根目录和任务绑定要求，避免后续实现继续猜测 `program_structure_spec.json` 的结构。

### 2. Plan11 schema 补全

计划 `11` 已新增以下 schema 最低结构：

- `asset_registry.schema.json`
- `asset_requirements_resolved.schema.json`
- `unity_asset_mount_plan.schema.json`
- `audio_placeholder_plan.schema.json`

其中 `asset_registry.json` 保留生成阶段使用的 `target_path`，`asset_spec_contract.json` 与 `unity_asset_mount_plan.json` 使用 runtime 挂载字段 `unity_target_path`。实施时必须显式完成字段映射，不能让 Step13 同时猜多个路径字段。

### 3. art_requirements_contract 路径修正

计划 `11` 已将 `art_requirements_contract.json` 的 schema 路径修正为：

```text
knowledge/schemas/art_requirements_contract.schema.json
```

不能新增重复的：

```text
knowledge/schemas/ai_design/art_requirements_contract.schema.json
```

## 测试计划同步

计划 `15` 已补充回归要求：

- Step03 `program_structure_spec.schema.json` 必须包含计划定义的最低 required 字段。
- Step04 四个新增 schema 必须包含计划定义的最低 required 字段。
- Step04 `art_requirements_contract.json` 必须指向现有 schema 路径，不能创建重复 schema。

## 当前结论

第五轮审查提出的残留问题已经全部落到执行计划中。

本轮修改后，Plan10/11 与 Plan12/20 的处理标准一致：只要计划声明新增 artifact，就必须同步声明 registry、schema 路径和最低 required 字段。
