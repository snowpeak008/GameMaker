# Step02设计冻结强消费原子计划

## 目标

让 Step02 从 D4 structured handoff 冻结 playable contracts，作为后续开发阶段的可信输入。

该计划完成后，Step02 的正式输出必须进入 StageContext/artifact_layer 标准路径，而不是孤立的 `frozen_design_contracts/`。

## 依赖

- `08_StructuredDesignContext统一加载原子计划.md`
- `18_Step00到Step01结构化输入原子计划.md`

## 涉及范围

重点修改：

```text
pipeline/step_02_design_review_freeze/plugin.py
core/engines/generation.py
core/design/playable_contracts.py
pipeline/artifact_layer/registry.json
```

建议新增测试：

```text
core/tests/unit/test_step02_freezes_playable_contracts.py
```

## 输入合同

Step02 必须读取 D4 candidates：

- `core_playable_contract`
- `demo_flow_contract`
- `runtime_data_contract`
- `ui_flow_contract`
- `scene_bootstrap_contract`
- `asset_mount_contract`
- `audio_requirements_contract`
- `playable_acceptance_contract`

## 正式输出路径

Step02 必须输出到：

```text
outputs/artifacts/stage_02/playable_contracts/
  core_playable_contract.json
  demo_flow_contract.json
  runtime_data_contract.json
  ui_flow_contract.json
  scene_bootstrap_contract.json
  asset_mount_contract.json
  audio_requirements_contract.json
  playable_acceptance_contract.json
```

该路径与现有 `pipeline/artifact_layer/registry.json` 对齐。

## 执行步骤

1. Step02 加载 `StructuredDesignContext`。
2. 读取 D4 handoff candidates。
3. require 所有通用必需 playable contracts。
4. 校验合同版本和 schema。
5. 冻结合同到 `outputs/artifacts/stage_02/playable_contracts/`。
6. 写入设计 AI 审查报告。
7. 后续步骤引用 Stage02 frozen contracts，不直接引用可变 D4 输出。

## 完成标准

1. Step02 缺 `ui_flow_contract` 时 blocked。
2. Step02 缺 `scene_bootstrap_contract` 时 blocked。
3. Step02 输出路径与 artifact registry 一致。
4. frozen contracts 包含 traceability/source_refs。
5. Step02 不从 `design.md` 解析 P0 字段。

## 不做事项

- 不生成程序需求。
- 不生成资源。
- 不生成 Unity 场景。
