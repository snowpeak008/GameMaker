# D3设计合同门禁原子计划

## 目标

把 D3 改造成真实设计合同门禁，防止设计不完整的项目进入 D4 和开发流水线。

该计划完成后，缺 UI、缺场景、缺输入、缺目标、缺可玩验收合同的项目必须被 D3 阻断。

## 门禁规则

D3 必须检查：

- profile 是否明确。
- 当前 archetype 是否可识别。
- 通用 P0 节点是否完成。
- 类型 P0 节点是否完成。
- not_applicable 是否有 reason。
- `ai_inferred` 是否被误算完成。
- `migration_inferred` 是否被误算完成。
- `core_playable_contract` 是否可形成。
- `demo_flow_contract` 是否可形成。
- `runtime_data_contract` 是否可形成。
- `ui_flow_contract` 是否可形成。
- `scene_bootstrap_contract` 是否可形成。
- `asset_mount_contract` 是否可形成。
- `audio_requirements_contract` 是否可形成。
- `playable_acceptance_contract` 是否可形成。
- `data_test_design_decision` 是否为 `playable_acceptance_contract` 提供人工确认来源；如果只能生成基础 fallback，必须进入 review 或 blocked，不能假完整。

## 执行步骤

1. D3 读取 D2 报告和当前项目设计状态。
2. 根据 profile 和 archetype 计算 required contract set。
3. 检查 P0 节点完成状态。
4. 检查 contract target 可形成性。
5. 检查 not_applicable reason。
6. 检查 `ai_inferred` 和 `migration_inferred` 是否被误算完成。
7. 使用现有 `GateResult` 输出 gate report。
8. 有 blocking issue 时返回 blocked。

## contract target 可形成性算法

一个 contract target 被视为“可形成”，当且仅当该合同的所有 P0 贡献节点满足以下条件之一：

1. 节点 `decision_state` 属于 `selected` 或 `completed`，并且至少有一个与该合同相关的 `checklistOptions` 选项满足：
   - `optionProvenance.source` 属于 `user_selected` 或 `user_confirmed_ai`。
   - 选项仍在当前知识库允许集合中。
   - 选项没有 unresolved blocking conflict。
2. 节点被标记为 `not_applicable`，并且存在非空 reason，且 archetype 规则允许该节点不适用。

以下情况必须视为不可形成：

- 贡献节点只有 `designNote`，没有结构化选项。
- 所有选项来源都是 `ai_inferred`。
- 所有选项来源都是 `migration_inferred`。
- 选项存在 unresolved blocking conflict。
- 节点 required，但被标记 not_applicable 且无 reason。

D3 可以调用 `build_playable_contract_bundle_from_decisions()` 做候选合同预生成，但不能仅凭 fallback candidate 通过门禁。fallback 比例或 fallback 字段必须进入 blocking issue 或 review item。

## 完成标准

1. 0 个真实决策时 D3 blocked。
2. 缺 `ui_flow_contract` 时 D3 blocked。
3. 缺 `scene_bootstrap_contract` 时 D3 blocked。
4. 缺输入动作时 D3 blocked。
5. 缺目标推进时 D3 blocked。
6. 只有备注没有结构化选项时 D3 blocked。
7. 阻断报告能指出回到哪些节点补全。

## 不做事项

- 不导出 D4 handoff。
- 不生成 Step02 artifacts。
- 不修改 Unity 项目。
