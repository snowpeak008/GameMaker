# 第四轮审查问题处理记录

本文件记录第四轮审查提出的 3 个问题的处理结果。

第四轮审查问题来自对 `10`、`11`、`12`、`20` 等计划之间的 artifact registry、dependency graph 和 schema 最低结构一致性检查。当前执行计划仍以 `00_原子计划索引.md` 为准。

## 处理结果总览

| 编号 | 原级别 | 问题 | 处理状态 | 落点 |
|---|---|---|---|---|
| 1 | P1 | Plan10/11 缺少 artifact registry 更新条款 | 已处理 | `10`、`11`、`15` |
| 2 | P1 | Plan12 Step08 缺少 `depends_on` 和 dependency graph 边更新 | 已处理 | `12`、`15` |
| 3 | P2 | Plan12/20 引用的新 schema 缺少最低字段结构 | 已处理 | `12`、`20`、`15` |

## 关键修复说明

### 1. Step03/Step04 registry 关系

计划 `10` 已明确 Step03 的输出文件和 registry 关系：

- `program_requirements_contract.json`
- `program_requirement_trace_report.json`
- `program_structure_spec.json`

其中 `program_requirement_trace_report.json` 是现有 registry artifact，必须保留并作为 Step03 trace/report 输出；新增的 `program_requirements_contract.json` 和 `program_structure_spec.json` 作为程序需求与结构规格补充，不替代现有 trace report。

计划 `11` 已明确 Step04 的输出文件和 registry 关系：

- `asset_spec_contract.json`
- `art_requirements_contract.json`
- `asset_registry.json`
- `asset_requirements_resolved.json`
- `unity_asset_mount_plan.json`
- `audio_placeholder_plan.json`

其中 `asset_spec_contract.json` 是现有 registry artifact，必须保留为资源合同主输出；`unity_asset_mount_plan.json` 是 Unity 挂载补充计划，不替代 `asset_spec_contract.json`。

### 2. Step08 registry depends_on 与 graph 边

计划 `12` 已明确 `stage_08.program_plan_bundle.depends_on` 必须包含：

- `stage_02.design_freeze_bundle`
- `stage_03.program_requirements_bundle`
- `stage_05.program_review_bundle`

计划 `12` 也已要求 `pipeline/artifact_layer/dependency_graph.json` 存在以下边：

- Stage02 -> Stage08
- Stage03 -> Stage08
- Stage05 -> Stage08

这样 Step08 的实际依赖和它声明读取的 Stage02 playable contracts、Step03 program requirements、Step05 program review 保持一致。

### 3. 新增 schema 最低结构

计划 `12` 已补齐以下 schema 最低 required 字段结构：

- `program_plan_contract.schema.json`
- `scene_assembly_task_requirements.schema.json`
- `ui_runtime_task_requirements.schema.json`
- `input_runtime_task_requirements.schema.json`
- `objective_runtime_task_requirements.schema.json`

计划 `20` 已补齐以下 schema 最低 required 字段结构：

- `asset_alignment_report.schema.json`
- `mount_readiness_summary.schema.json`
- `dev_execution_report.schema.json`
- `art_production_report.schema.json`

这些结构不是完整业务字段上限，而是最低消费契约。实现时可以增加字段，但不能删掉这些 required 字段，否则 Step10/11/13 会再次依赖猜测格式。

## 测试计划同步

计划 `15` 已补充回归要求：

- Step03/Step04 新增或保留 artifacts 必须可从 registry 查到。
- Step08 `depends_on` 必须包含 Stage02、Stage03、Stage05。
- dependency graph 必须存在 Stage02 -> Stage08、Stage03 -> Stage08、Stage05 -> Stage08。
- Step08 和 Step10-12 新增 schema 必须包含计划定义的最低 required 字段。

## 当前结论

第四轮审查提出的 3 个问题已经全部落到执行计划中。

本轮修改后，计划中不再把 Step03/04 registry 关系、Step08 依赖图、Step08/10/11/12 输出 schema 最低结构留给实现阶段临时决定。
