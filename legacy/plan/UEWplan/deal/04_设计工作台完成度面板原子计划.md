# 设计工作台完成度面板原子计划

## 目标

将设计工作台从“可以填写设计”升级为“引导用户完成可开发 playable contracts”。

该计划完成后，用户应该能在设计阶段清楚看到：

- 哪些 P0 合同未完成。
- 哪些节点阻止进入 D4。
- 哪些 AI 建议尚未人工确认。
- 哪些字段缺失会导致 Unity 没有 UI、场景、输入或目标。

## 依赖

- `02_合同Schema注册表与校验器原子计划.md`
- `03_设计知识库节点元数据原子计划.md`

## 涉及范围

建议检查和修改：

```text
core/ui/app_window.py
core/ui/ai_interview_window.py
core/ui/embedded_interview.py
core/design/engine.py
```

建议新增测试：

```text
core/tests/unit/test_design_completion_summary.py
```

## 必须展示的合同

完成度面板至少展示：

- `core_playable_contract`
- `demo_flow_contract`
- `runtime_data_contract`
- `ui_flow_contract`
- `scene_bootstrap_contract`
- `asset_mount_contract`
- `audio_requirements_contract`
- `playable_acceptance_contract`

## 执行步骤

1. 在 engine 层新增设计完成度汇总 API。
2. 汇总 P0/P1/P2 节点完成状态。
3. 汇总 playable contract target 覆盖状态。
4. 区分 `user_selected`、`ai_inferred`、`user_confirmed_ai`、`migration_inferred`。
5. UI 增加完成度面板。
6. UI 增加 P0/P1/P2 过滤。
7. UI 增加“检查设计完成度”入口。
8. UI 显示阻断原因和应返回补全的节点。

## 关键规则

### AI 建议不能直接算完成

AI 推断内容只能作为建议。只有 `user_confirmed_ai` 或 `user_selected` 才能计入 D3 门禁。

### 备注不能替代结构化选择

关键 P0 节点不能只靠 `designNote` 完成，必须有结构化选项、参数或字段。

### not_applicable 必须写原因

如果某节点被标记为不适用，必须记录 reason，并且 D3 可以校验。

## 完成标准

1. UI 能展示当前设计是否满足进入 D4 的最低要求。
2. UI 能展示 P0 阻断项。
3. `ai_inferred` 不会显示为 completed。
4. `migration_inferred` 不会显示为 completed。
5. not_applicable 无 reason 时显示为问题。
6. 完成度面板数据来自 engine，不硬编码在 UI。

## 不做事项

- 不修改 D2/D3/D4 的执行逻辑。
- 不生成 Unity 场景。
- 不做视觉美化优先的 UI 重构。
