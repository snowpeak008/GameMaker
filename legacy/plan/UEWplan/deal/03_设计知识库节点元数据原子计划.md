# 设计知识库节点元数据原子计划

## 目标

让设计知识库和 autosave 状态具备机器可理解的完成要求、来源记录和游戏类型适配能力。

该计划完成后，D2/D3 才能判断当前项目是否真的完成了必需 playable contracts，而不是只判断知识库结构是否完整。

每个关键节点应支持：

{
  "priority": "P0",

  "contract_targets": ["ui_flow_contract", "scene_bootstrap_contract"],
  "required_for_archetypes": ["all"],
  "optional_for_archetypes": [],
  "not_applicable_allowed": true,
  "not_applicable_requires_reason": true,
  "consumed_by_steps": ["Step13", "Step14"]

## optionProvenance 状态模型

当前 `checklistOptions` 只有 `selected` 和 `primary`，无法判断选项来自用户还是 AI。必须新增并持久化 `optionProvenance`。

建议结构：

```json
{
  "optionProvenance": {
    "item_id": {
      "group_id": {
        "option_id": {
          "source": "user_selected",
          "confirmed": true,
          "updated_at": "ISO-8601",
          "actor": "user",
          "ai_inference_id": ""
        }
      }
    }
  }
}
```

允许的 `source`：

- `user_selected`
- `ai_inferred`
- `user_confirmed_ai`
- `migration_inferred`

D3 只允许 `user_selected` 和 `user_confirmed_ai` 计入 P0 完成。`ai_inferred` 和 `migration_inferred` 必须显示为待确认。

## Archetype 映射

必须定义通用 archetype 枚举与必需合同映射。

第一批建议：

- `action`
- `puzzle`
- `strategy`
- `simulation`
- `rpg`
- `narrative`
- `management`
- `generic_playable`

映射来源：

- 优先读取 `project_state.profile` 中的显式字段。
- 其次读取用户已确认的 gameplay/system 选项。
- 最后才允许 fallback 到 `generic_playable`，并产生 warning。

每个 archetype 必须映射：

- 通用必需合同。
- 类型扩展合同。
- 类型 P0 节点。
- 不适用节点规则。

## archetype_requirements.json 格式

D4 导出的 `archetype_requirements.json` 必须使用稳定结构，供 D3、Step00/01 和 Step02 使用。

建议结构：

```json
{
  "schema_version": "1.0",
  "detected_archetype": "strategy",
  "detection_confidence": "high",
  "detection_source": [
    "profile.targetScale",
    "gameplay_system_decision.primary_loop"
  ],
  "required_contracts": [
    "core_playable_contract",
    "demo_flow_contract",
    "runtime_data_contract",
    "ui_flow_contract",
    "scene_bootstrap_contract",
    "asset_mount_contract",
    "playable_acceptance_contract"
  ],
  "optional_contracts": [
    "audio_requirements_contract"
  ],
  "archetype_p0_nodes": [
    "input_control_decision",
    "objective_system_decision",
    "data_test_design_decision"
  ],
  "archetype_p1_nodes": [
    "progression_system_decision"
  ],
  "not_applicable_rules": []
}
```

`detected_archetype` 如果 fallback 到 `generic_playable`，必须产生 warning，不能静默通过。

## Camera 来源

第一阶段不新增独立 `camera_view_spec` 合同。摄像机要求来自：

- `scene_bootstrap_contract.camera`
- 设计节点中的 scene/runtime/presentation 相关选项。
- 如果知识库缺专门节点，需要新增或扩展 `scene_startup_decision` 类型节点，但导出目标仍是 `scene_bootstrap_contract.camera`。

禁止使用 `designNote` 中的自由文本标记作为唯一来源。

## playable_acceptance_contract 来源

`playable_acceptance_contract` 必须有设计节点来源，不能只依赖默认 fallback。

第一阶段绑定：

```json
{
  "node_id": "data_test_design_decision",
  "domain": "data_validation_design",
  "priority": "P0",
  "requirement_level": "required",
  "contract_targets": ["playable_acceptance_contract"],
  "consumed_by_steps": ["Step14"]
}
```

提取规则：

- 从 `data_test_design_decision` 的体验测试、验收信号、操作步骤、预期反馈选项中生成 `playmode_checks`。
- 如果设计节点未提供完整 PlayMode 步骤，允许 Step03 基于 `core_playable_contract.action_verbs` 和 `demo_flow_contract.steps` 生成基础验收。
- 自动生成的基础验收必须标记 `source: generated_from_core_loop`，并在 D3/D4 报告中提示需要人工复核。
- 只有 `data_test_design_decision` 或等价节点确认后，才能视为完整验收合同。

## 执行步骤

1. 梳理当前 103 个节点的数据来源。
2. 给通用 P0 节点增加 `priority`、`requirement_level`、`contract_targets`。
3. 给类型节点增加 `required_for_archetypes`。
4. 在 `engine.set_option_group_option()` 写入 `optionProvenance`。
5. 在 `engine.set_option_group_primary()` 保持 provenance 不丢失。
6. 在 AI 建议接受流程中，把 AI 候选从 `ai_inferred` 转为 `user_confirmed_ai`。
7. 在旧项目迁移时，把无法确认来源的选项标记为 `migration_inferred`。
8. 实现 archetype 映射表和读取 API。
9. 为 `scene_bootstrap_contract.camera` 确定知识库来源。
10. 为 `data_test_design_decision` 绑定 `playable_acceptance_contract`。

## 完成标准

1. 知识库节点能返回 priority、requirement_level、contract_targets。
2. 用户手动选项会记录 `user_selected` provenance。
3. AI 建议不会自动算 completed。
4. 旧数据迁移不会伪装成人工确认。
5. `scene_bootstrap_contract.camera` 有明确节点来源。
6. archetype 可以决定当前项目额外必需合同。
7. `archetype_requirements.json` 结构明确。
8. `playable_acceptance_contract` 有明确设计节点来源。

## 不做事项

- 不实现 D3 门禁。
- 不导出 D4 handoff。
- 不生成 Unity 内容。
