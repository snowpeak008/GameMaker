# 测试迁移与回归验收原子计划

## 目标

建立覆盖设计合同、D2/D3/D4、Step00-14 和旧项目迁移的测试体系，确保不会再次出现“设计完成但 Unity 不可玩”的问题。

## 前置要求：测试基线

开始实现任何代码前，必须先运行当前相关测试并记录基线。

至少记录：

- 当前通过测试数量。
- 当前失败测试数量。
- 当前跳过测试数量。
- 与 playable contracts、AI design contracts、pipeline plugins 相关的失败原因。

基线文件建议：

```text
plan/UEWplan/deal/test_baseline_before_contract_refactor.md
```

## 测试分层

### 合同测试

必须覆盖：

- 现有 playable contract schema 成功校验。
- 缺字段失败。
- artifact registry schema_refs 与实际 schema 文件一致。
- Step03 新增或保留的 `program_requirements_contract.json`、`program_requirement_trace_report.json`、`program_structure_spec.json` 均可从 registry 查到。
- Step04 新增或保留的 `asset_spec_contract.json`、`asset_registry.json`、`asset_requirements_resolved.json`、`unity_asset_mount_plan.json`、`audio_placeholder_plan.json` 均可从 registry 查到。
- Step03 `program_structure_spec.schema.json` 必须包含计划定义的最低 required 字段。
- Step04 `asset_registry.schema.json`、`asset_requirements_resolved.schema.json`、`unity_asset_mount_plan.schema.json`、`audio_placeholder_plan.schema.json` 必须包含计划定义的最低 required 字段。
- Step04 `art_requirements_contract.json` 的 schema 路径必须指向现有 `knowledge/schemas/art_requirements_contract.schema.json`，不能新增重复的 `ai_design` 路径 schema。
- Step08、Step10、Step11、Step12 新增 artifacts 均可从 registry/dependency graph 查到。
- `stage_08.program_plan_bundle.depends_on` 必须包含 `stage_02.design_freeze_bundle`、`stage_03.program_requirements_bundle`、`stage_05.program_review_bundle`。
- dependency graph 必须存在 Stage02 -> Stage08、Stage03 -> Stage08、Stage05 -> Stage08 的边。
- Step08 新增 schema 必须包含计划定义的最低 required 字段。
- Step10-12 新增 schema 必须包含计划定义的最低 required 字段。
- contract version 不兼容失败。
- `runtime_data_contract` 的 tables/entities/relations/state_models 校验。

### 设计阶段测试

必须覆盖：

- 空设计项目 D2 报告未完成。
- 空设计项目 D3 blocked。
- 只有备注没有结构化选择时 D3 blocked。
- `ai_inferred` 未确认不算 completed。
- `migration_inferred` 未确认不算 completed。
- not_applicable 无 reason 时 blocked。

### D4 测试

必须覆盖：

- D4 导出 `handoff_manifest.json`。
- `handoff_manifest.json` 引用现有 `package_manifest.json`。
- `traceability.json` 与合同内部 `source_refs` 不矛盾。
- D4 导出 `decisions.json`。
- selected options 被导出。
- primary options 被导出。
- optionProvenance 被导出。
- traceability 被导出。
- playable contract candidates 使用现有合同名。
- 缺核心合同时 D4 blocked。

### Step 消费测试

必须覆盖：

- Step00/01 可以读取结构化 profile/archetype。
- Step02 缺 `ui_flow_contract` blocked。
- Step03 输出 UIController/InputRouter/ObjectiveTracker。
- Step04 输出 Unity asset mount plan。
- Step05-09 不回退解析 P0 Markdown。
- Step07 正式流程保留 style confirmation approved 门禁。
- Step08 输出 scene assembly task requirements。
- Step08 新 artifacts 已注册到 artifact registry。
- Step10-12 读取 Step08 输出，不回退解析 P0 Markdown。
- Step10-12 新 artifacts 已注册到 artifact registry。
- Step13 缺 UI blocked。
- Step14 缺 UI failed。
- Step14 缺输入响应 failed 或 environment_blocked。

### 端到端测试

必须覆盖：

1. 空项目不能进入开发。
2. 只有文本设计不能进入开发。
3. 完整结构化设计可以进入 Step13。
4. Step13 生成 Entry Scene、Camera、Canvas、EventSystem。
5. Step14 验证可见 UI、输入反馈、目标推进。

## 旧项目迁移

旧项目处理规则：

- 旧 Markdown 可以保留作为参考。
- 旧 `designNote` 可以转换为候选结构化字段。
- inferred 字段必须标记为 `migration_inferred`。
- 未确认字段不能通过 D3。
- 旧 Step 输出不能作为新合同可信来源。

建议新增工具：

```text
tools/migrate_legacy_design_notes_to_contract_candidates.py
```

## 完成标准

1. 开发前有测试基线记录。
2. 所有新增单元测试通过。
3. 所有原有相关测试通过，或有明确迁移说明。
4. 至少一个通用非工厂示例项目通过端到端流程。
5. 空项目、文本项目、缺 UI 项目、缺场景项目都会被阻断或失败。
6. 验收报告能清楚说明失败原因。

## 不做事项

- 不清理历史存档。
- 不把旧项目强行改成通过。
- 不用人工目测替代自动验收。
