# Step04资源需求强消费原子计划

## 目标

让 Step04 从结构化资源合同生成可消费资源需求，避免继续产出“看起来像图，但不能被 Unity 使用”的图片。

## 依赖

- `09_Step02设计冻结强消费原子计划.md`
- `10_Step03程序需求强消费原子计划.md`

## 涉及范围

重点修改：

```text
pipeline/step_04_art_requirements/plugin.py
core/engines/generation.py
```

建议新增测试：

```text
core/tests/unit/test_step04_asset_requirements_from_contracts.py
```

## 输入合同

Step04 必须读取：

- `asset_mount_contract`
- `ui_flow_contract`
- `scene_bootstrap_contract`
- `audio_requirements_contract`

## 输出要求

Step04 应输出：

```text
asset_spec_contract.json
art_requirements_contract.json
asset_registry.json
asset_requirements_resolved.json
unity_asset_mount_plan.json
audio_placeholder_plan.json
```

关系说明：

- `asset_spec_contract.json` 是现有 registry 已登记的正式 artifact，必须保留，是 Step05/06/10/13 的主要机器消费入口。
- `art_requirements_contract.json` 记录美术需求与可消费资源要求。
- `asset_registry.json` 记录资源清单和 source trace。
- `asset_requirements_resolved.json` 是对 `asset_mount_contract` 和 `asset_spec_contract` 的解析结果。
- `unity_asset_mount_plan.json` 是面向 Unity 挂载的补充计划，不替代 `asset_spec_contract.json`。
- `audio_placeholder_plan.json` 是音频占位计划，不替代 `audio_requirements_contract`。

每个 asset 必须包含：

- asset_id。
- asset_type。
- usage_context。
- target_path / unity_target_path 映射关系。
- required_format。
- required_size。
- transparency。
- viewpoint。
- import_settings。
- fallback_policy。
- linked_contract_field。

字段命名规则：

- `asset_registry.json` 保留生成阶段路径字段 `target_path`，用于 Step05/06/10 早期审查。

## 音频占位规则

当前不生成真实音频。Step04 只注册占位路径，后续 Step14 验证文件或 marker 存在即可。

第一阶段沿用现有路径：

```text
Assets/Audio/.audio_placeholder
```

## 执行步骤

1. 加载 Stage02 frozen playable contracts。
2. 从 `asset_mount_contract` 生成资源清单。
3. 从 `ui_flow_contract` 生成 UI sprite、icon、font、prefab 需求。
4. 从 `scene_bootstrap_contract` 生成场景可见对象资源需求。
5. 从 `audio_requirements_contract` 生成占位音频需求。
6. 输出 `asset_spec_contract.json`、`art_requirements_contract.json`、`asset_registry.json` 和 Unity 挂载计划。
7. 缺失但允许占位的资源必须明确 fallback。
8. 不允许无用途资源进入最终清单。

## 完成标准

1. `asset_spec_contract.json` 保留并作为正式消费入口。
2. 所有资源都有 Unity 目标路径。
3. 所有资源都能追溯到合同字段。
4. UI 资源有挂载目标。
5. 场景资源有使用位置。
6. 音频资源即使未生成，也有占位需求。
7. 抽象概念图不能被标记为可消费 runtime asset。

## 不做事项

- 不调用真实图片生成。
- 不生成 Unity 场景。
- 不把某类游戏的资源类型写死为通用必需。
