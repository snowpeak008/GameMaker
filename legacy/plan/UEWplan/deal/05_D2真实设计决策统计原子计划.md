# D2真实设计决策统计原子计划

## 目标

把 D2 从“静态知识库结构检查”改造成“当前项目真实设计决策统计”。

该计划完成后，D2 应该能识别：

- 当前项目是否真的做了设计选择。
- P0/P1/P2 完成情况。
- 哪些 playable contract target 缺失。
- 哪些 AI 建议未确认。
- 哪些节点只是写了备注但缺结构化决策。

## 依赖

- `02_合同Schema注册表与校验器原子计划.md`
- `03_设计知识库节点元数据原子计划.md`

## 涉及范围

重点修改：

```text
pipeline/step_d2_design_decisions/plugin.py
core/design/engine.py
core/design/export_adapter.py
```

建议新增测试：

```text
core/tests/unit/test_d2_real_decision_report.py
```

## 输出文件

D2 应输出：

```text
design_decision_report.json
design_decision_report.md
```

## 报告字段

建议 JSON 结构：

```json
{
  "status": "reported",
  "project_id": "string",
  "summary": {
    "p0_total": 0,
    "p0_completed": 0,
    "p0_blocking": 0,
    "ai_inferred_unconfirmed": 0,
    "migration_inferred_unconfirmed": 0
  },
  "contract_targets": [
    {
      "contract_id": "ui_flow_contract",
      "required": true,
      "source_nodes": [],
      "status": "missing"
    }
  ],
  "issues": []
}
```

## 执行步骤

1. D2 加载当前项目真实设计状态，而不是只加载静态 design data。
2. 统计节点 decision_state。
3. 统计 checklistOptions 的 selected 和 primary。
4. 统计 optionProvenance 的 source 与 confirmed 状态。
5. 统计 P0/P1/P2 完成情况。
6. 统计 contract_targets 覆盖情况。
7. 输出 JSON 与 Markdown 报告。
8. 保持 D2 不阻断，只报告。

## 完成标准

1. 空项目 D2 报告 P0 未完成。
2. 知识库完整但项目没有决策时，D2 不显示 completed。
3. 只有 `designNote` 的 P0 节点会被报告为结构化决策不足。
4. `ai_inferred` 未确认时不会算 completed。
5. D2 报告能被 D3 复用。

## 不做事项

- D2 不负责最终阻断。
- D2 不导出 handoff。
- D2 不生成 Unity 内容。
