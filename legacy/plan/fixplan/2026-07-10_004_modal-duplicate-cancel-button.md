# 模态界面重复取消按钮修复计划

## 记录状态

- 已完成（2026-07-11）：六个主模态框移除 header 重复退出按钮，保留底部退出入口，并补齐 Escape、焦点陷阱和键盘可访问性验证。
- 以下内容保留为原始问题、原因、方案和验收标准。
- 用户建议：删除所有模态界面右上角的取消/关闭按钮，保留底部的取消/关闭按钮。

## 1. 问题记录

当前打开项目模板、另存为模板、存档管理、项目配置、智能助手配置和风格提示词编辑等界面时，模态框标题栏右侧存在一个自定义的“关闭”或“取消”按钮；底部操作栏又存在一个关闭/取消按钮。

因此同一个模态界面出现两个作用相同的退出入口，尤其智能助手配置界面的右上角和底部都显示“取消”，容易让用户误以为存在不同语义。

## 2. 原因分析

- 这些界面不是独立的 Windows 子窗口，而是同一个 Tauri WebView 中的 HTML 模态框。
- `NEWrust/web/src/index.html` 为每个模态框同时定义了：
  - `.modal-header` 内的自定义关闭按钮；
  - `.modal-footer` 内的取消/关闭按钮。
- 前端 JavaScript 又同时为两组按钮绑定相同的隐藏模态框行为，所以形成重复入口。
- 主程序窗口的 Windows 原生标题栏仍然独立存在，主窗口右上角的最小化、最大化和关闭按钮不属于本问题范围。

## 3. 目标行为

- 每个模态界面只保留底部的取消/关闭按钮。
- 删除模态框标题栏右侧的自定义按钮，不新增另一个自定义 Windows 风格关闭按钮。
- 主窗口继续使用 Windows 原生标题栏关闭按钮。
- 底部取消/关闭按钮仍然可以正常关闭界面；确认、保存、删除等业务按钮行为不受影响。
- 读操作界面可以继续使用“关闭”，编辑或取消操作界面可以继续使用“取消”，根据语义保留现有底部文案。

- [ ] 从另存为模板模态框标题栏移除 `close-save-template`。
- [ ] 从存档管理模态框标题栏移除 `close-save-manager`。
- [ ] 从项目配置模态框标题栏移除 `close-project-config`。
- [ ] 从智能助手配置模态框标题栏移除 `close-ai-config`。
- [ ] 从风格提示词编辑模态框标题栏移除 `close-style-prompt-editor`。

### P0：同步清理事件绑定

- [ ] `design.js` 只保留模板浏览器和模板保存底部按钮的关闭绑定。
- [ ] `utility-panels.js` 只保留存档管理底部取消按钮的绑定。
- [ ] `settings-style.js` 只保留项目配置和风格提示词编辑底部取消按钮的绑定。
- [ ] `ai-config.js` 只保留智能助手配置底部取消按钮的绑定。
- [ ] 删除无引用的 `close-*` DOM action 选择器，避免留下失效契约。

### P1：增加回归保护

- [ ] UI gate 检查所有 `.modal-backdrop .modal-header` 不再包含退出操作按钮。
- [ ] 保持模态框标题、底部状态栏和底部操作按钮的响应式布局检查。
- [ ] 检查中文和英文模式下底部按钮文案仍正确。

## 6. 验收标准

- [ ] 所有模态界面不再出现右上角自定义取消/关闭按钮。
- [ ] 每个模态界面仍有一个明确可用的底部取消/关闭入口。
- [ ] 不影响确认、保存、应用、删除、加载和退出保存流程。
- [ ] 中文/英文界面、桌面/窄窗口 UI gate 均通过。
- [ ] 实现前后没有修改主窗口原生标题栏配置。

## 来源

- 用户反馈：所有打开界面右上角存在取消按钮，界面同时存在两个取消按钮。
- 用户决定：删除右上角的取消按钮。
