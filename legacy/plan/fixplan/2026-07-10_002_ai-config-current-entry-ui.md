# 智能助手配置当前项交互改进记录

状态：已完成（2026-07-11）；按钮位于卡片右上角，当前项高亮且草稿状态即时刷新，三类配置互不串线。

日期：2026-07-10

## 1. 问题现象

智能助手配置的“设为当前配置项”目前通过右侧配置详情中的勾选项表达，控件较小，用户不容易发现。

当前配置项在左侧列表中使用对号或状态标记确认。实际操作中，用户选择一个非当前配置并将其设为当前后，左侧列表不会立即刷新，往往要再点击其他按钮后才显示新的当前项。

## 2. 目标交互

- 将“设为当前配置项”放到左侧每个配置项卡片的右上角。
- 使用清晰的文字按钮，不再使用勾选框或对号作为主要确认方式。
- 非当前项显示“设为当前配置项”按钮。
- 当前项使用高亮按钮或高亮状态表达当前关系；不再依赖对号确认。
- 点击后立即刷新左侧列表、当前项状态和相关状态提示，不需要再点击其他控件。
- 保留配置编辑、验证和保存的既有职责，不把本次视觉调整扩大为 AI 配置模型重构。

## 2.1 补充视觉问题：文本补全接口的当前标签脱离卡片

在“文本补全接口”类别中，代表当前配置的“当前”标签目前没有被当前配置项卡片的边框和背景完整包围，视觉上像是脱离配置项的浮动标签。

后续调整时应将当前状态统一收敛到配置项卡片右上角的高亮按钮或卡片高亮状态中，移除脱离卡片的独立“当前”页签表现。

## 3. 交互状态规则

每个 AI 配置类别独立维护一个当前项：

- 左侧列表项仍可点击，用于查看和编辑配置详情。
- 右上角操作按钮只负责设为当前，不应误触发列表选择以外的行为。
- 点击当前项按钮后，模型中的 activeEntryId 应立即更新。
- 重新渲染后，旧当前项取消高亮，新当前项立即高亮。
- 切换开发接口、图像接口、文本补全接口时，各类别的当前项状态互不覆盖。
- 用户尚未点击“保存”时，是否写入磁盘沿用现有保存语义；本记录要求的是界面状态立即同步。

## 4. 需要处理的现有逻辑

- 当前项状态由配置类别的 activeEntryId 表示。
- 开发接口类别还会同步 activeProfileId。
- 当前 UI 的 entry-active 勾选框会在表单同步时调用模型更新逻辑。
- 新的左侧按钮需要在更新模型后主动调用统一 rerender，不能等待下一次按钮或字段事件。
- 若当前详情表单存在未保存编辑，设置当前项前需要保留现有字段同步和校验行为。

## 5. 验收条件

- [ ] 左侧每个配置项的右上角都有明确的当前项操作区域。
- [ ] 非当前项可以直接点击“设为当前配置项”。
- [ ] 当前项使用高亮按钮或高亮容器显示，不依赖对号。
- [ ] 文本补全接口中的当前状态指示完整位于当前配置项卡片内部，不出现脱离边框的“当前”标签。
- [ ] 点击后左侧列表立即反映新的当前项。
- [ ] 点击后不需要切换类别、编辑字段或点击保存才能看到视觉刷新。
- [ ] 三个 AI 配置类别的 activeEntryId 互不串线。
- [ ] 保存后重新打开配置窗口，当前项仍然正确。
- [ ] 删除当前项时，候选项切换和高亮状态立即正确。
- [ ] 窄屏 UI 不出现按钮溢出或遮挡。
- [ ] Web 单元测试、e2e、UI gate 和双语截图基线同步更新。

先调整左侧配置项的按钮结构和样式，再让设为当前动作统一更新模型并立即 rerender，随后补充保存、删除、分类切换和窄屏测试，最后刷新双语文案与 UI 基线。
