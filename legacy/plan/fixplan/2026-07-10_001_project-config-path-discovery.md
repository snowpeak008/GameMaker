# 项目配置路径体验改进记录

状态：核心范围已完成（2026-07-11）；Unity 原生选择、识别、编辑器发现、机器绑定与重连已实现。Godot/Unreal 属于总计划 Phase 8，待产品确认后另行开发。

日期：2026-07-10

## 1. 问题记录

当前项目配置中的“项目路径”和“编辑器路径”主要是文本输入框，要求用户手动复制完整路径。

现有实现能够保存路径并执行基础预检，但不会主动帮助用户发现项目目录、编辑器安装位置或版本匹配关系。这个交互容易产生路径填错、选错可执行文件、换机器后失效等问题。

“引擎名称”不属于本计划的核心改造对象。它仍然只是自定义引擎的文本标识；真正决定预检和路径规则的是“游戏引擎”类型。

## 2. 改进目标

- 用户优先通过原生选择器选择项目目录，而不是手动复制路径。
- 编辑器路径优先自动检测和匹配，手动选择作为兜底。
- 选择项目后自动识别项目类型、项目版本和可用编辑器。
- 路径移动、换电脑或编辑器版本变化后，可以重新扫描并修复配置。
- 预检结果要给出直接可执行的修复入口。
- 保留手动输入能力，以支持非标准目录和自定义引擎。

## 3. 目标交互

    项目目录   [选择文件夹] [重新扫描]
    编辑器版本 [自动检测 ▼] [选择程序]
    状态       Unity 2022.3.x，项目与编辑器匹配

项目目录选择后，界面应显示：

- 目录是否像目标引擎项目；
- 检测到的引擎类型；
- 检测到的项目版本；
- 当前编辑器是否匹配；
- 可用的“重新扫描”“选择路径”“打开目录”等操作。

## 4. 分阶段开发清单

以下条目后续逐项开发，本文件当前不代表任何条目已经实现。

### P0：原生路径选择

- [ ] 项目路径增加原生文件夹选择器。
- [ ] 编辑器路径增加原生文件选择器。
- [ ] 支持取消选择，不破坏原有有效配置。
- [ ] 选择结果经过路径规范化和项目根目录校验。
- [ ] 保留手动输入作为兼容和兜底方式。

### P0：项目目录识别

- [ ] Unity：检查 Assets、ProjectSettings、Packages/manifest.json。
- [ ] Godot：检查 project.godot。
- [ ] Unreal：检查 .uproject 及相关项目结构。
- [ ] 识别失败时给出明确原因和修复建议。

### P1：编辑器自动发现

- [ ] Unity：读取项目 ProjectSettings/ProjectVersion.txt。
- [ ] Unity：扫描 Unity Hub 或已安装编辑器目录。
- [ ] 按项目所需版本筛选候选编辑器。
- [ ] 多个候选时让用户选择，并显示版本与路径。
- [ ] 找不到候选时回退到手动选择。

### P1：配置模型调整

- [ ] 项目配置保存引擎类型、项目目录和所需版本。
- [ ] 编辑器实际路径作为本机解析结果保存或缓存。
- [ ] 区分项目级信息与机器级安装信息。
- [ ] 路径失效时允许重新解析，而不是要求用户重新填写全部配置。

### P1：预检和修复

- [ ] 预检报告显示项目标志、版本匹配、编辑器可执行文件状态。
- [ ] 每个 blocker 或 warning 提供对应修复动作。
- [ ] 支持“重新扫描全部编辑器”和“重新选择当前路径”。
- [ ] 预检不能把 Unity Hub 本身误判成 Unity Editor。

### P2：跨引擎一致性

- [ ] Godot、Unreal 使用各自的项目标志和版本发现规则。
- [ ] 自定义引擎允许用户指定名称、项目目录和可选工具路径。
- [ ] 自定义引擎不因缺少标准目录而被错误阻断。
- [ ] 将引擎发现器设计成可扩展的独立模块。

### P2：路径迁移与可移植性

- [ ] 项目目录移动后提供重新定位流程。
- [ ] 换电脑或编辑器安装位置变化后提供重新扫描流程。
- [ ] 检查存档恢复时的路径是否仍然有效。
- [ ] 对绝对路径失效提供可读的迁移提示。

## 5. 明确不在本轮开发范围

- 本轮只建立需求记录，不修改运行代码。
- 不在本轮新增 Tauri、Rust 或前端依赖。
- 不在本轮实现自动安装或下载游戏引擎。
- 不把“引擎名称”扩展成执行命令或脚本入口。
- 不绕过现有路径安全检查和项目预检。

## 6. 相关现状文件

## 7. 开发顺序建议

先完成 P0 原生选择器和项目目录识别，再完成 P1 Unity 版本/编辑器自动发现；随后补齐预检修复入口和配置模型分层，最后扩展 Godot、Unreal、自定义引擎及路径迁移。
