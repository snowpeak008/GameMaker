# 14 并行隔离与端到端回归验收

## 目标

验证设计语义闭环在两个或更多项目并行运行时不会串档，并且 Step00-10 不再生成“看似成功但内容空洞”的通用计划。

---

## 修改范围

新增或扩展测试：

```text
core/tests/integration/test_design_semantic_pipeline.py
core/tests/integration/test_parallel_project_semantic_isolation.py
core/tests/unit/test_design_semantic_quality.py
```

按需新增测试 fixture：

```text
core/tests/fixtures/design_semantics/
  tower_defense_reference/
  narrative_puzzle_reference/
```

---

## 回归场景

至少覆盖两个项目：

1. 植物大战僵尸类 tower_defense reference。
2. 请出示证件类 narrative_puzzle reference。

端到端范围：

```text
D4 structured handoff -> Step00 -> Step10
```

---

## 必测断言

1. 两项目 `project_signature` 不同。
2. 两项目 `project_dna_contract.json` 不同。
3. 两项目 Step03 程序能力不同。
4. 两项目 Step04 资产分类不同。
5. 两项目 Step08 程序任务不同。
6. 两项目 Step09 美术任务不同。
7. 两项目 Step10 语义对齐矩阵不同。
8. 没有跨 draft 或 project_signature 不一致的 source refs。
9. 模板泄漏文本不进入任务标题、资产 ID、输出文件名。
10. 质量分低于阈值时不能静默 success。

---

## 最低语义验收

Tower defense reference 必须覆盖：

1. 车道/格子系统。
2. 阳光资源。
3. 植物放置动作。
4. 敌人波次。
5. 植物/敌人/阳光/HUD 资产。
6. 波次胜负验收。

Narrative puzzle reference 必须覆盖：

1. 证件数据模型。
2. 规则手册。
3. 审查/批准/拒绝动作。
4. 扣分/罚款/日结。
5. 检查台/证件/印章/规则书/UI 资产。
6. 审查配额和错误惩罚验收。

---

## 验收标准

1. `python -m pytest core/tests/unit/test_design_requirements_archetype_detector.py core/tests/unit/test_design_requirements_archetype_subtypes.py -q` 通过。
2. `python -m pytest core/tests/unit/test_project_dna_builder.py core/tests/unit/test_program_capability_builder.py core/tests/unit/test_art_taxonomy_builder.py -q` 通过。
3. `python -m pytest core/tests/integration/test_design_semantic_pipeline.py core/tests/integration/test_parallel_project_semantic_isolation.py -q` 通过。
4. `python -m compileall core pipeline tools/validators` 通过。
5. 手动抽查两个项目的 Step08/09 产物，不能再只有通用 Runtime + placeholder。
