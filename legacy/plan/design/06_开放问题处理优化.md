# 开放问题处理优化（Step00）

## 问题描述

当前两个项目的 OQ-001 至 OQ-012 内容完全相同，都是通用问题模板，没有游戏专属问题，且没有任何机制强制用户填写。

## 优化二：OQ 阻断机制

`blocking: true` 的 OQ 未填写时，D3 不允许通过：

```python
def check_blocking_open_questions(open_questions):
    unresolved = [
        q for q in open_questions
        if q.get("blocking") and not q.get("answer")
    ]
    if unresolved:
        return [{
            "code": "BLOCKING_OQ_UNRESOLVED",
            "severity": "error",
            "message": f"{len(unresolved)} 个阻断级开放问题未填写",
            "questions": [q["id"] for q in unresolved],
            "return_to": "设计工作台 → 开放问题面板"
        }]
    return []
```

## 设计工作台 UI 变化

- OQ 面板按 Archetype 分组展示，不再是混合通用列表
- `blocking: true` 的问题标记为红色必填
- 已填写的答案在对应节点 designNote 中实时预览
- 点击问题可跳转到对应的设计节点

## 验收标准

- 两个项目的 OQ 列表内容有差异（专属问题不同）
- `blocking: true` 的 OQ 未答时，D3 返回 blocked
- OQ 答案自动写入对应 designNote
- 通用 OQ 模板不再出现在项目文件中
