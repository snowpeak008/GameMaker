# 决策专属内容生成优化（Step02/03）

## 问题描述

当前 Step02 冻结的 `core_playable_contract` 和 Step03 生成的程序需求，在两个完全不同的游戏中输出几乎相同的内容：

- `player_model.first_minute_goal` = "长期有追求"（通用占位）
- `action_verbs` = action_01、action_02（无语义名称）
- `program_requirements` = REQ-001至REQ-009（两项目完全相同）

## 优化一：合同字段从决策提取

### `core_playable_contract` 专属字段生成规则

```python
def build_core_playable_from_decisions(decisions, archetype, profile):

    # 1. player_model 从 core_loop_decision 和 objective_system_decision 提取
    first_minute_goal = extract_from_node(
        decisions, "objective_system_decision",
        fallback="完成首个核心目标"
    )
    # 植物大战僵尸示例 → "在第一关成功阻挡第一波僵尸"
    # 请出示证件示例 → "核验第一批旅客的证件并避免扣分"

    # 2. action_verbs 从 input_control_decision 的 primary 选项提取
    action_verbs = extract_action_verbs(
        decisions, "input_control_decision", archetype
    )
    # PvZ → [{"action_id": "place_plant", "display_name": "放置植物", ...}]
    # Papers → [{"action_id": "approve_document", "display_name": "批准证件", ...}]

    # 3. core_loop 从 core_loop_decision 的 primary 提取
    core_loop_description = extract_from_node(
        decisions, "core_loop_decision",
        archetype_template=ARCHETYPE_LOOP_TEMPLATES[archetype]
    )
    return build_contract(first_minute_goal, action_verbs, core_loop_description)
```

## 优化二：程序需求专属化

### 当前问题

```
REQ-001: Implement RuntimeBootstrap  ← 两个项目完全相同
REQ-002: Implement GameState model   ← 两个项目完全相同
```

### 优化后结构

每个 REQ 增加 `game_specific_requirements` 字段，从 archetype + 决策生成：

```json
{
```

## 验收标准

- `core_playable_contract.player_model.first_minute_goal` 包含游戏具体描述
- `action_verbs[0].display_name` 使用游戏语义名称（如"放置植物"而非"action_01"）
- `program_requirements` 中每个 REQ 的 `game_specific_requirements` 非空
- 输出文件路径包含游戏专属类名（如 `TowerDefenseGameState.cs`）
