# 资产专属内容填充优化（Step04）

## 问题描述

当前两个项目 Step04 输出的资产列表完全相同：7个通用占位资产（`asset_ui_placeholder`、`asset_fallback_visual`等），没有任何游戏专属内容。

## 优化方案：三层资产结构

### 第一层：通用基础资产（保留，两项目均需要）

```
asset_ui_placeholder         ← 保留，用于 UI 占位测试
asset_fallback_visual        ← 保留，视觉 fallback
asset_audio_placeholder      ← 保留，音频占位
```

### 第三层：设计决策专属资产（从用户确认的 L5 实体和选项提取）

从 `decisions.json` 中提取用户明确选择的内容节点生成资产：

```python
def extract_decision_driven_assets(decisions, archetype):
    assets = []
    for node_id, node_state in decisions["nodes"].items():
        entities = node_state.get("designEntities", [])
        for entity in entities:
            if entity.get("kind") in ("ui", "building", "character", "icon"):
                asset = build_asset_from_entity(entity, archetype)
                assets.append(asset)
    return assets
```

## 资产 ID 命名规则

使用 `{game_prefix}_{archetype_role}` 格式，不使用通用名：

| 通用（当前）| 植物大战僵尸 | 请出示证件 |
|------------|------------|----------|
| `asset_ui_placeholder` | `pvz_hud_placeholder` | `papers_hud_placeholder` |
| `ui_prefab_game_hud` | `pvz_game_hud` | `papers_inspection_hud` |
| `asset_fallback_visual` | `pvz_lane_fallback` | `papers_desk_fallback` |


## 验收标准

- Step04 输出资产总数：基础资产（3个）+ Archetype专属（5-10个）+ 决策驱动资产（N个）
- 所有资产 `asset_id` 包含游戏前缀或 archetype 语义
- `consumer_system` 字段使用游戏专属系统名（如 `GridManager`，非 `game_hud`）
- 两个项目的 asset_spec_contract 内容差异度 > 80%
