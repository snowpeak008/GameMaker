# Rust 重建开发注意事项

---

## 一、最高优先级红线

1. 不允许 Rust 产品依赖 Python 运行时。
2. 不允许 GUI 直接写正式存档。
3. 不允许 pipeline 直接写正式存档。
4. 不允许同一个正式存档被两个会话同时编辑。
5. 不允许 AI 输出绕过验证直接进入 accepted state。
6. 不允许业务代码硬编码用户机器路径。
7. 不允许旧 Python schema 作为 Rust 权威契约。
8. 不允许为了快速展示 UI 而跳过框架边界。
9. 不允许用“测试里能跑”替代事务保存。
10. 不允许把 API key 写进项目存档或导出包。

---

## 二、命名注意事项

必须使用统一术语：

- 正式存档：`FormalArchive`
- 临时工作区：`DraftWorkspace`
- 存档锁：`ArchiveLock`
- 项目导出包：`ProjectExportPackage`
- AI 介入：`AiIntervention`
- 游戏设计与开发工作台：`GameDesignAndDevelopmentWorkbench`

避免：

- `save` 泛指一切
- `project` 同时指目录、存档、工作区、Unity 项目
- `workspace` 同时指 Git workspace 和业务工作台
- `lock` 不说明锁对象

建议 Rust 命名：

- `ArchiveId`
- `DraftId`
- `SessionId`
- `RunId`
- `StageId`
- `TaskId`
- `ArtifactId`

---

## 三、路径与文件系统注意事项

### 路径来源

所有路径必须来自：

- app data root
- test temp root
- user selected external project path
- imported package path

不得来自：

- 当前工作目录猜测
- 硬编码盘符
- 旧 Python `core.paths`
- 环境变量隐式覆盖，除非测试专用

### 安全规则

- 删除目录前必须确认目标在允许 root 内。
- 移动目录前必须确认源和目标。
- 正式存档保存必须通过事务。
- 临时文件必须使用唯一名称。
- Windows 下避免依赖 Unix-only 文件锁语义。

### 内容指纹

正式保存前后应计算内容指纹。

用途：

- 判断保存事务是否完整。
- 判断导出包是否完整。
- 判断崩溃恢复是否需要提示。

不要把内容指纹当成唯一业务版本号。

---

## 四、并行与并发注意事项

### 多项目并行

允许：

- 多个进程
- 多个 Session
- 多个 Draft
- 多个不同 Archive

必须隔离：

- 日志
- runtime state
- AI task record
- pipeline run state
- cache
- temp files

### 同项目并发

第一版禁止：

- 同一项目多个 pipeline run 并发写入。
- 同一正式存档多会话编辑。
- 同一 Unity/外部项目路径并发写入。

后续若要加并发，必须先有：

- 依赖图调度
- artifact 写入范围声明
- 冲突检测
- merge/rollback 策略
- UI 可见冲突报告

---

## 五、正式存档注意事项

正式存档是用户可恢复状态，不是运行垃圾桶。

正式存档应包含：

- 项目元信息
- 设计状态
- 已接受的阶段结果
- 用户配置引用
- SDK 选择
- 打包资料
- 附件
- 保存历史摘要

正式存档不应包含：

- API key
- 临时日志全文
- 未接受 AI 输出
- 临时下载缓存
- 运行中任务状态
- GUI 窗口位置，除非是用户偏好

---

## 六、AI 注意事项

### AI 介入不是后台常驻

AI 只在以下情况下触发：

- 内容不足
- 评分不足
- 阶段需要生成
- 阶段需要审查
- 用户主动请求
- SDK 需要解释
- 代码/资产任务需要生成

### AI 输出处理

AI 输出状态必须有：

- raw
- parsed
- validated
- accepted
- rejected
- superseded

不能只有字符串结果。

### Provider 抽象

业务代码只能依赖能力：

- TextGeneration
- StructuredGeneration
- Review
- CodeGeneration
- ImageGeneration
- SdkAssist
- LongTask

不能依赖：

- OpenAI 字段名
- Claude CLI 输出格式
- Codex CLI 工作目录行为
- 某个供应商的错误字符串

---

## 七、GUI 注意事项

GUI 只负责：

- 展示状态
- 收集用户输入
- 发出命令
- 展示错误
- 展示进度

GUI 不负责：

- 计算设计评分
- 执行保存事务
- 判断 archive lock
- 调用 AI Provider
- 运行 pipeline
- 修改正式存档

GUI 所有操作应变成 application command：

- `CreateDraft`
- `OpenArchive`
- `SaveArchive`
- `StartPipeline`
- `RequestAiIntervention`
- `ExportPackage`
- `ImportPackage`

---

## 八、测试注意事项

Rust 测试必须覆盖：

1. ID 生成和序列化。
2. 路径安全。
3. 原子写。
4. draft 创建。
5. archive 创建。
6. archive lock。
7. 同 archive 双开拒绝。
8. 不同 archive 并行。
9. 保存事务失败回滚。
10. export/import package。
11. task runner。
12. stop request。
13. structured log。
14. AI mock provider。
15. AI 输出验证。
16. pipeline mock stage。
17. GUI view model。
18. SDK resource load。
19. package report。
20. 跨 crate contract。

测试禁止：

- 写真实用户目录。
- 依赖网络。
- 依赖真实 AI。
- 依赖旧 Python runtime。
- 依赖固定时间。
- 依赖固定 PID。

---

## 九、错误处理注意事项

错误必须可解释。

每个错误至少包含：

- error code
- human message
- source module
- context
- recoverability
- suggested action

例：

```text
ADM_ARCHIVE_LOCKED
该正式存档已被另一个会话打开。
建议：切换到已打开窗口，或关闭该窗口后重试。
```

不要只返回：

```text
failed
unknown error
io error
```

---

## 十、配置注意事项

配置分类：

- app config
- user config
- provider config
- project config
- GUI preference

敏感信息：

- API key
- token
- local credential path

敏感信息不得：

- 写进正式存档
- 写进导出包
- 写进日志明文
- 出现在错误弹窗全文

---

## 十一、SDK 注意事项

SDK 是核心功能，不是文档目录。

SDK 条目必须能回答：

- SDK 是什么
- 适用平台
- 集成前置条件
- 必要配置
- 常见错误
- 验证方法
- 和游戏项目的关系
- AI 可解释摘要

Rust 版 SDK 不应只是文件浏览器。

---

## 十二、流水线注意事项

Stage 必须声明：

- stage id
- display name
- input contracts
- output contracts
- dependencies
- gates
- AI intervention points
- validation rules
- resume policy

Stage 不应：

- 自己决定保存正式存档。
- 自己写全局状态。
- 自己读 provider config。
- 自己绕过 runtime task runner。

---

## 十三、资源迁移注意事项

迁移资源前必须问：

1. 这是内容，还是旧运行格式？
2. 是否仍符合新产品范围？
3. 是否有 Rust schema？
4. 是否有 Rust loader 测试？
5. 是否有中文编码测试？
6. 是否有 ID 唯一性测试？

未通过这些问题的资源不能进入 Rust 产品。

---

## 十四、开发顺序注意事项

正确顺序：

1. 类型
2. 文件系统安全
3. 配置
4. 存档
5. runtime
6. 日志
7. AI 抽象
8. validation
9. pipeline 抽象
10. design 抽象
11. GUI shell
12. 资源迁移
13. 业务链条

错误顺序：

1. 先画完整 GUI。
2. 先复制旧模板。
3. 先接真实 AI。
4. 先写 Step 业务。
5. 最后再补存档和日志。
