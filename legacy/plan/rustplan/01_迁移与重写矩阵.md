# Rust 重建迁移与重写矩阵

> 结论先行：当前 Python 项目只作为参考项目。Rust 版不做兼容移植，不承诺读取旧存档，不复用 Python 运行时代码。

---

## 一、分类规则

### A 类：可直接保留为决策参考

这类内容不进入 Rust 运行时，但作为产品和架构约束存在。

### B 类：可内容迁移

这类内容可以经过审查后复制或改写进 `RUST/resources/`，但要接受 Rust 新 schema。

### C 类：可逻辑参考，必须 Rust 重写

这类内容说明“业务上发生了什么”，但实现必须重写。

### D 类：必须废弃并重写

这类内容与 Python/Tkinter/旧格式强绑定，不能迁移。

---

## 三、可直接保留为参考的内容

### 1. 领域术语

来源：

- `CONTEXT.md`

可保留：

- 游戏设计与开发工作台
- AI 介入
- 正式存档
- 临时工作区 / 草稿
- 存档锁
- 内容指纹
- 项目导出包

处理方式：

- 作为 Rust docs 和类型命名参考。
- 不把旧路径说明当成实现要求。
- 术语变化必须先更新 `CONTEXT.md`。

### 2. 架构决策

来源：

- `knowledge/decisions/ADR-*.md`

可保留：

- Rust full rebuild
- Rust desktop shell
- Rust data model reset
- Rust product scope
- Rust framework first
- Rust cargo workspace
- Rust draft/archive model
- Rust archive storage format
- Rust pipeline model
- Rust pipeline serial first
- Rust AI intervention model
- Rust pluggable AI providers

处理方式：

- 作为 Rust 计划约束。
- 冲突时以最新 Rust ADR 为准。

## 四、可内容迁移的内容

### 1. 游戏设计领域数据

来源：

- `knowledge/design_data/domains/*.json`
- `knowledge/design_data/domain_order.json`
- `knowledge/design_data/gameplay_system_options.json`
- `knowledge/design_data/option_mapping.json`
- `knowledge/design_data/archetypes/*.json`

迁移方式：

1. 定义 Rust 新 design resource schema。
2. 编写一次性资源转换脚本或手工转换。
3. 用 Rust 测试验证所有资源可加载。
4. 校验中文字段、节点 ID、选项 ID、权重字段。

不能直接假设：

- 旧字段名合理。
- 旧节点层级完全适合 Rust UI。
- 旧质量指标可直接使用。

### 2. 项目模板内容

来源：

- `knowledge/design_data/project_templates/*.json`

迁移方式：

- 作为内容样本迁移，不作为兼容格式迁移。
- Rust 版重新定义 template manifest。
- 每个模板必须通过 Rust schema 校验。
- 模板应按目标品类、2D/3D、规模、核心玩法分类重建索引。

第一批建议只迁移当前活跃 25 个模板，不迁移历史 archive。

### 3. SDK 知识内容

来源：

- `knowledge/sdks/`

迁移方式：

- 迁入 `RUST/resources/sdk/`。
- 重建 SDK index。
- 每个 SDK 条目至少包含：SDK 名称、用途、平台、集成风险、配置项、验证方法、AI 可解释摘要。

### 4. 提示词思想

来源：

- `pipeline/step_*/prompts/*.txt`
- `knowledge/design_data/prompt_framework/`

迁移方式：

- 不能原样塞入 Rust。
- 需要按 AI Intervention 模型重写为 task prompt。
- 每个 prompt 必须绑定输入 schema、输出 schema、失败策略、验证策略。

## 五、可逻辑参考但必须 Rust 重写的内容

### 1. 存档系统

参考：

- `core/save/manager.py`
- `core/runtime/run_context.py`
- `core/runtime/locks.py`
- `core/tests/unit/test_draft_archive_paths.py`
- `core/tests/unit/test_parallel_runtime_isolation.py`

必须重写：

- 正式存档格式
- 临时工作区格式
- 存档锁实现
- 保存事务
- 导出包格式
- 崩溃恢复
- 多进程隔离

必须保留的行为语义：

- 每个进程独立 Session ID。
- 每个进程独立 Draft Workspace。
- 不同正式存档可并行。
- 同一个正式存档不能同时编辑。
- GUI/pipeline 不直接写正式存档。
- 保存必须是事务边界。

### 2. 流水线系统

参考：

- `core/main.py`
- `core/plugin_manager.py`
- `core/stage_plugin.py`
- `pipeline/_registry.json`
- `pipeline/artifact_layer/dependency_graph.json`
- `pipeline/artifact_layer/registry.json`

必须重写：

- stage trait
- stage registry
- dependency graph
- serial runner
- stage state
- gate
- artifact contract
- run logs
- resume logic

保留的语义：

- 阶段有输入、输出、状态、验证。
- 阶段之间有依赖。
- 阶段输出必须可审查。
- 阶段失败必须可解释。
- AI 介入必须记录。

### 3. AI 适配器

参考：

- `core/adapters/base.py`
- `core/adapters/openai_adapter.py`
- `core/adapters/codex_adapter.py`
- `core/adapters/claude_code_adapter.py`

- Provider trait
- Provider config
- task request/result
- streaming
- retry
- structured output validation
- provider diagnostics
- cost/time/token metadata

保留的经验：

- 不要让步骤代码知道供应商细节。
- 文本、代码、图像、审查是不同能力。

### 4. 设计引擎

保留的逻辑方向：

- 设计内容必须评分。

- 设计冻结必须有质量门。

### 5. 打包系统

必须重写：

- packaging model
- package manifest
- package preflight

保留语义：

- 打包是顶层阶段，不属于开发流水线内部 Step。

### 6. SDK 系统

参考：

- `core/sdk/`

- `knowledge/sdks/`

- SDK resource schema

保留语义：

- SDK 是核心功能。

## 六、必须废弃并重写的内容

### 1. 全部 Python 运行时代码

包括但不限于：

- `core/**/*.py`
- `pipeline/**/*.py`
- `tools/**/*.py`
- `gui_app.py`
- Python UI
- Python save manager
- Python adapters
- Python validators
- Python tests

它们只能作为参考，不能作为 Rust 产品运行依赖。

### 2. Tkinter GUI

必须废弃：

- `core/ui/main_window.py`
- `core/ui/app_window.py`
- `core/ui/pipeline_panel.py`
- `core/ui/save_manager_dialog.py`
- 所有 Tkinter dialog/panel/card

Rust GUI 必须重建：

- Slint component
- Rust view model
- application service commands
- UI state binding

### 3. 旧存档和旧草稿

必须废弃兼容承诺：

- `saves/*`
- `drafts/*`
- 旧 `manifest.json`
- 旧 `draft_meta.json`
- 旧 `execution_objects.json`
- 旧 `run_state.json`

可选后续：

- 设计旧项目导入器。
- 但导入器不是第一版框架目标。

### 4. 旧 JSON Schema 作为运行时契约

不能直接沿用：

- 旧 schema 命名
- 旧字段布局
- 旧 artifact id
- 旧 Step 绑定

可以参考：

- 旧 schema 表达了哪些业务对象。
- 旧 schema 暴露了哪些质量门。

Rust 新 schema 必须按新领域模型重建。

### 5. 旧测试体系

必须重建：

- Rust unit tests
- Rust integration tests
- fixture builder
- mock AI provider
- archive isolation tests
- pipeline runner tests
- GUI model tests

Python pytest 不能作为 Rust 通过标准。

## 七、直接迁移清单

严格意义上，“直接迁移”只允许以下几类：

1. `CONTEXT.md` 的术语定义，作为文档参考。
2. Rust 相关 ADR，作为架构决策。
3. 经过重新校验的知识文本。
4. 经过新 schema 转换后的模板内容。
5. 经过新 schema 转换后的 SDK 内容。
6. 经过重写的 prompt 内容。

不允许直接迁移：

- `.py` 代码
- 旧 save/draft
- 旧 GUI
- 旧 settings
- 旧 pipeline registry
- 旧 artifact registry
- 旧 tests
- 旧 exe

---

## 八、迁移验收标准

某项内容被判定为“已迁移”必须同时满足：

1. 进入 `RUST/resources/` 或 Rust 文档位置。
2. 有 Rust schema 或 Rust type 支撑。
3. 有 Rust 测试覆盖加载。
4. 不依赖 Python 文件路径。
5. 不依赖旧 runtime 目录。
6. 不要求旧 Python 模块解释。
