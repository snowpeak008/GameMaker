> 落点 crate：`adm4-decision`（模型/DAG/完成度）+ `adm4-space`（清单加载与校验）
> 依据：redesign_v3 文档 02/03 + 第二版 L4/L5 结构经验

---

## 1. L 层梯度（全局唯一语义）

| 层 | 名称 | 回答的问题 | 示例（通道塔防） |
|----|------|-----------|-----------------|
| L0 | 项目档案 | 平台/商业模式/规模/合规（非玩法） | PC 单机 premium，medium 规模 |
| L1 | 体验方向 | 核心情感与幻想 | 「以小博大守护脆弱生态」 |
| L2 | 品类结构 | 什么品类、什么模式结构 | 通道塔防 + 波次关卡制 |
| L3 | 系统组成 | 有哪些系统、系统间接口 | 部署/资源/波次/克制系统 |
| L4 | 机制规则 | 每系统的规则与状态机（公式符号级） | 克制伤害 = 基础×克制系数 |
| L5 | 实体与参数结构 | 实体类型、属性表结构、关系表结构 | 守卫 5 种 × {成本,攻速,射程,克制标签}；克制矩阵 5×4 |
| L6 | 数值表 | 具体数字、曲线、关卡数据 | 每守卫具体数值；10 关波次表 |

**深度档（DepthProfile）**：项目创建时选定目标层（最低 L4，可选 L5/L6），全局统一。冻结门按深度档检查完整性。L4 档项目的 Phase 1 文档显式标注「数值层留待开发期填充」，不可进 Phase 2。

第二版的 9 项项目画像字段（商业模式/运营模式/社交结构/平台范围/主平台/发行区域/项目规模/内容分级/单次时长）**全部转为 L0 通用层决策点**，不再是独立的 profile 结构。

第二版的 MDA 五层标签（aesthetics/dynamics/mechanics/constraints/evidence）保留为决策点的可选展示标签 `mda_layer`，用于 UI 分组与访谈话术，不参与门禁。

## 2. 核心类型（adm4-decision）

### 2.1 DecisionPoint（决策点定义，来自设计空间清单，只读）

```rust
pub struct DecisionPoint {
    pub id: DecisionId,                 // 如 "ld.counter_matrix"
    pub domain: DomainId,               // 组织维度（继承 16 域划分思想，域集由清单定义）
    pub level: DesignLevel,             // L0..=L6
    pub genre_scope: GenreScope,        // Universal | Pack(GenrePackId)
    pub question: String,               // 一句话问题
    pub mda_layer: Option<MdaLayer>,    // 可选 MDA 标签（展示用）
    pub requirement: PointRequirement,  // Unlocked（默认，激活驱动）| Baseline（基线，可显式 N/A）
    pub options: Vec<DecisionOption>,
    pub skin_fields: Vec<ParamPath>,    // 属于「皮」的参数路径（命名/主题/文案），换皮门只查这些
    pub evidence_slots: bool,           // 模板逆向时此点是否需要来源标注
}

pub struct DecisionOption {
    pub id: OptionId,
    pub label: String,
    pub summary: String,
    pub implications: Vec<String>,      // 选它意味着什么
    pub requires: Vec<OptionSelector>,  // 前置约束
    pub conflicts: Vec<OptionSelector>, // 冲突约束（硬拦截）
    pub unlocks: Vec<DecisionId>,       // 选中后激活哪些深层决策点（适用性判定的驱动）
    pub parameter_schema: ParameterSchema,
    pub is_custom: bool,                // 显式 custom 选项；冻结门要求结构化描述并计数
}

pub struct OptionSelector { pub decision: DecisionId, pub option: OptionId }
```

### 2.2 参数与表结构（L5/L6 的核心）

```rust
pub enum ParameterSchema {
    None,
    Scalar(Vec<ScalarField>),   // L0-L4 标量/枚举参数
    Table(TableSchema),         // L5 定义列结构，L6 填行
    Matrix(MatrixSchema),       // L5 矩阵（如克制矩阵）
}

pub struct ScalarField {
    pub key: String,
    pub kind: ValueKind,                  // Int | Float | Bool | Text | Enum(variants)
    pub constraint: Option<ValueConstraint>, // Range{min,max} | OneOf | Pattern
    pub required: bool,
    pub is_skin: bool,                    // 该字段是否属于「皮」（换皮比对粒度）
}

pub struct TableSchema {
    pub columns: Vec<ScalarField>,
    pub row_key: String,                  // 行标识列
    pub cardinality_key: String,          // 对应品类包 cardinality_expectations 的键
}

pub struct MatrixSchema {
    pub row_axis: AxisRef,                // 引用某决策的选项集或某表的行集
    pub col_axis: AxisRef,
    pub cell: ScalarField,
}

pub enum AxisRef {
    DecisionOptions(DecisionId),          // 轴 = 该决策点的选项集
    TableRows(DecisionId),                // 轴 = 该决策 Table 参数的行集
}
```

`ValueKind`/`ValueConstraint` 与 `adm4-spec` 的 `PropertySpec` 共用同一套类型（定义在 `adm4-contracts`），保证 C0 编译时参数值可直接落入 GameSpec，无两套类型体系。

### 2.3 Selection（一次选择的记录，属于项目状态）

```rust
pub struct Selection {
    pub decision_id: DecisionId,
    pub option_id: OptionId,
    pub parameters: ParameterValues,
    pub rationale: String,                // 为什么选（用户写或 AI 访谈生成）
    pub provenance: Provenance,           // UserManual | AiInterviewConfirmed | Template(id)
    pub confirmed_by_user: bool,          // AI 访谈/模板预填必须 true 才计入完成度
    pub template_original: Option<ParameterValues>, // 模板预填时记录原值，供换皮门逐字段比对
}

pub enum ParameterValues {
    None,
    Scalars(BTreeMap<String, TypedValue>),
    Rows(Vec<BTreeMap<String, TypedValue>>),      // Table 行数据
    Cells(Vec<MatrixCell>),                        // Matrix 格数据 {row,col,value}
}
```

### 2.4 适用性判定（简单玩法不卡门）

```rust
pub enum PointApplicability {
    Active,                          // 被激活：必须 confirmed 才算完成
    Inactive,                        // 未被任何已选选项 unlock：不进分母
    NotApplicable(NaJustification),  // baseline 点，本项目合理不需要：显式跳过
}

pub struct NaJustification { pub reason_code: String, pub note: String } // 结构化理由码，非散文
```

规则：
1. **激活式跳过**：L0-L2 通用根点恒 Active；深层点只有父选项 `unlocks` 才激活。
2. **显式 N/A**：`requirement=Baseline` 的点无论激活与否都建议回答；不需要时给结构化 `reason_code`，进冻结报告计数。
3. **深度档兜底**：`level > depth_profile.target` 的点一律不进分母。

### 2.5 DAG 校验器（新写，Kahn 内核）

最小规则集：
1. 无环（拓扑可排序）；
2. 每个 `requires`/`conflicts`/`unlocks` 的目标存在；
3. `conflicts` 双向对称，且**真拦截**（选择时报错，不只标注）；
4. `unlocks` 真实驱动激活；
5. 每决策点 ≥1 选项；`custom` 选项必须提供结构化 `parameter_schema`；
6. `AxisRef` 指向的决策点存在且轴可枚举。

### 2.6 完成度计算

```
分母 = level ≤ depth_profile.target 且 genre_scope 适用
       且 applicability ∈ {Active, Baseline 未 N/A} 的决策点
完成 = 分母内每点：有 Selection 且 confirmed_by_user=true
       且参数按 schema 填齐（L6：表行数达基数下限、矩阵无空格）
```

输出 `CompletenessReport { done, total, blocking: Vec<MissingItem> }`；`MissingItem` 精确到「哪个决策点/哪张表/哪一格」，直接喂冻结门与 UI。确认单元分层：结构层（L0-L4）按点计；表层（L5-L6）以整表为单元，缺格进待填清单而非默认值（R2）。

## 3. 设计空间清单（adm4-space）

清单是**决策点与选项的定义源**（非项目选择）。一份清单 = 通用层或一个品类包。用户按格式填内容（E4 输入门），工程只建 schema、加载与校验。

### 3.1 文件布局

```
knowledge/design_space/
├── design_space.schema.json      清单 JSON Schema（正式）
├── _template/pack.blank.json     空白模板 + README 填写指南
├── _example/mini.json            最小样例（1 域 2 决策点）
├── universal/                    通用层（L0-L2 全部 + 跨品类决策点）
│   └── *.json
└── <pack_id>/                    品类包
    ├── pack.json                 L3-L6 品类专属决策点 + 基数期望 + ≥3 参考游戏名
    ├── references/*.json         逆向答卷（逆向工具链产出）
    └── cross_validation.md       交叉验证报告
```

### 3.2 pack.json 结构

```jsonc
{
  "pack_id": "lane_defense",
  "pack_version": "0.1.0",
  "display_name": "通道塔防",
  "reference_games": ["<A>", "<B>", "<C>"],          // ≥3，硬要求
  "cardinality_expectations": {                       // 基数期望表，接 C3 基数门（R6）
    "guard_types": { "min": 4, "max": 8 },
    "wave_count":  { "min": 8, "max": 20 }
  },
  "consistency_rules": [                              // 冻结门第 2 道的跨决策校验规则
    { "id": "matrix_rows_match_guards",
      "kind": "matrix_axis_matches_table_rows",
      "matrix_decision": "ld.counter_matrix",
      "table_decision": "ld.guard_roster" }
  ],
  "decision_points": [ /* DecisionPoint 的 JSON 序列化 */ ]
}
```

### 3.3 校验规则（加载即校验，违例→blocked）

1. schema 合法（serde 严格字段 + 路径级错误定位）；
2. DAG 合法（复用 adm4-decision 校验器）；
3. `reference_games.len() >= 3`，否则 blocked；
4. 矩阵轴引用合法；
5. 每个 Table/Matrix 参数的 `cardinality_key` 在 `cardinality_expectations` 有对应区间；
6. 品类包决策点 `level ∈ L3..=L6`；通用层含 L0-L2 全部（允许含跨品类 L3+）。

### 3.4 交叉验证报告

对每决策点列出 ≥3 参考答卷各自的选择；仅 1 款覆盖的选项标「弱证据」，提示品类包维护者复核。基数区间取参考实测值域并集±合理外扩。参考游戏是**校准来源非复刻目标**；`reference_games` 名单同时登记进换皮词表。
