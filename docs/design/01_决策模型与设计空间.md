## 0. 新模型一句话

**玩法 = 从系统库实例化若干"系统模块"，每个实例声明一个重度档（档位定义自带五维标定与 P 维承诺），实例间以名词端口连成系统实例图；组合合法性由三条机器规则判定——重核连通性 R-C1′、重度预算 R-C2（声明档单轨）、重度传导 R-C3；决策点降级为系统模块内由 `tier_gate` 激活的机制选择器，经扩展后的 EffectSpec（7→16 分层封闭枚举）与 Graph/Curve 参数确定性编译到 C0-C6。**

与 2026-08 版的关系：L0-L6 分层、红线 R1-R7、冻结门纪律、DecisionPoint/Selection/参数表结构**全部保留**（见 §8 衔接节）；被取代的是"品类包 = 决策点所有权仓库"的旧组织方式——决策点归属改为系统模块，品类包转为"引用哪些模块、各开哪个档、名词怎么绑"的组合模板壳。

## 1. 系统模块模型

### 1.1 系统的定义与边界三测试

**一个系统 = 一组机制规则 + 这组规则独占写权限的状态（数据表/状态机）+ 对外的名词端口。** 系统是"状态所有权 + 规则闭包"的单位，不是功能页签，也不是体验层主题词。

边界三测试（两个评定者应同判）：

- **T1 状态所有权**：存在至少一张只有该候选系统能写的数据表或状态集。无独占状态者不是系统。
- **T2 可摘除**：整体摘除候选系统（只删接口边、不改其他系统内部规则），游戏其余部分规则仍自洽。若摘除 X 必然迫使 Y 内部规则改写，则 X、Y 是同一个系统。
- **T3 名词转换**：至少消费一个名词并产出/修饰至少一个名词。只存数据不转换名词的是数据资产，不是系统。

判例：装备/宠物/背包是三个系统；"成长"是 Dynamics 层聚类标签，**禁止用 D 层词汇给系统命名**；"手感系统"不是系统（T1 不过）；"新手引导"是系统（引导进度表独占）。

### 1.2 四类名词 × 三类端口

| 名词类 | 定义 | 判定 | 例 |
|---|---|---|---|
| 资源 resource | 可计数、可增减、可转移的量 | 有余额语义 | 金币、体力、行动点 |
| 实体 entity | 有属性表的对象实例 | 有行标识 + 属性列 | 一件装备、一张卡、一个敌人 |
| 事件 event | 时点信号，带载荷 | 有发生时刻，无余额 | 击杀、升级、波次结束 |
| 修饰器 modifier | 作用于其他系统属性或规则的持续效果 | 有作用目标 + 生效期 + 叠加序 | 套装加成、遗物、buff |

端口三类：**provides / consumes / modifies**。一条接口边 =（源系统, 端口, 名词, 目标系统）；系统实例图 = 系统为节点、接口边为边的有向图，是组合校验器（§3）的唯一输入。

类型落点：名词落为 `NounDecl`，`NounKind` 五分（Resource / EntityClass / Property{of} / Signal / RuleSlot——RuleSlot 是允许他系统 `ModifyRule` 作用的规则挂点）；端口落为 `SystemInterface { provides, consumes, modifies }`。

**接口完整性判定**：系统全部 L4 机制的 `effects_template` 凡引用非本系统所有的实体/资源/属性必须有对应接口边；`consumes ∪ modifies` 中每个名词必须在绑定表有映射且映射目标被某实例 provides 或属 pack 核心名词（`core_nouns`），悬空 → 加载失败（V6，fail-closed）。

### 1.3 MDA 三层映射

每个系统模块强制填三层：

- **M（Mechanics）**：本系统的 L4 决策点列表——既有 pack 窄链原样保留。
- **D（Dynamics）**：预期运行时动态，用"谓词 + 可观测信号"书写、禁止形容词。**D 层是文档纪律**（写作规范 + 红队人工审），不进机器校验——谓词可观测性不可静态判定，假装机检会制造覆盖假象。
- **A（Aesthetics）**：MDA 八分类限选 ≤2 主项。机检保留：所有 core 系统 A 主项并集 = 玩法美感承诺；某 core 系统 A 主项与承诺完全不相交 → 警告（不 block）。

### 1.4 系统库：40 系统设计清单，库内实装 15 模块

设计清单 = 定稿 §2.4 的 39 系统（战斗 8 / 成长 6 / 经济 9 / 内容 8 / 社交 3 / 元游戏 3 + 红队核准新增 #38 三消棋盘、#39 牌型组合）+ #40 职业流派（定稿 §9.2a，两档形态：轻档涌现式安装约束+派生标签 / 重档预设式职业表+门控+转职）。**清单开放扩充**，库外走 custom 入口（§6）。

库内实装（2026-09-06 实况，`knowledge/systems/`，共 15）：

| 批次 | 模块 |
|---|---|
| 波 3 首批 4 | sys.equipment（E0-E6 七档）/ sys.inventory / sys.loot / sys.economy |
| 波 4 P0+ 7 | sys.build_placement（G1）/ sys.match_format（G2）/ sys.tactical_board（G5，含 grid 迁移承接档 MG0/MG1）/ sys.squad_command（G8）/ sys.scoring_combo（G11）/ sys.class_archetype（#40）/ sys.onboarding |

### 1.5 复用机制：引用 + 绑定

pack 不复制系统决策点，改为 `GenrePack.system_refs: Vec<SystemRef>`（实例 id / 模块 id / semver 版本要求 / 允许档位范围 / 名词绑定表 / κ 声明）。加载语义：模块决策点按实例命名空间重写 id（纯字符串前缀替换，逐字节确定）并入决策图；模块一致性规则与基数期望同样重写后并入既有 gate2 机器；绑定悬空 → 加载失败；模块文件哈希进 `FrozenDesign.content_hash`（条件键 `module_versions`，无模块项目哈希逐字节零漂移）。同一模块可多实例；实例 id 包内唯一（每包最多一个模块实例能以"实例 id = 旧前缀"保 id 迁移——波 4b 发现 A）。

## 2. 重度模型

### 2.1 重度三件套

重度 = **声明档 × 五维标定 × 测得向量**：

1. **声明档（tier）**——设计师的意图输入，模块局部有序阶梯（`HeavinessLadder`，档数与命名由模块作者定：装备 7 档、判定窗 2 档均合法）。它决定激活哪些决策点（§4）。每档定义必须标注五维分与全局档带；跨模块比较走全局档带（跨模块 rank 不可比），重核判定一律用全局档带 W≥9。
2. **五维标定**——档位定义的内容标准，是"该档该放什么"的设计学承诺。
3. **测得向量**——编译期从冻结集确定性计算，**仅作审计证据**：声明档与测得档漂移 ≥1 档 → gate2 警告（不 block），不参与任何预算校验（测得分在创作早期恒 ≈0，预算要在组合期指导设计，时序上只有声明档成立）。

### 2.2 五维量表与全局档带

W(S) = M + D + C + P + O，五维各 0-3，总分 0-15。**全局档带：轻 0-4 / 中 5-8 / 重 9-12 / 极重 13-15**；**重核 = W≥9**。

| 维 | 名称 | 数什么 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|
| M | 机制深度 | 系统内 L4 级独立机制规则数 | ≤1 | 2-3 | 4-6 | ≥7 |
| D | 数据深度 | 系统独占数据结构数（表/矩阵/曲线/图各算 1） | ≤1 张简单表 | 2-3 | 4-6 或含矩阵 | ≥7 或含图/嵌套 |
| C | 耦合宽度 | 以本系统为端点的接口边数（三端口全口径） | ≤1 | 2-3 | 4-6 | ≥7 |
| P | 决策形态 | 玩家决策结构四选一 | 无决策 | 偶发一次性选择 | 会话级重复决策 | 构筑级组合决策 |
| O | 内容供给 | 系统所有表行数合计量级 | ≤10 | 11-100 | 101-1000 | >1000 或持续运营供给 |

两条口径修订（定稿指令 5）：**C 维在谱系标定中写"接口边下限"**（C 是组合相对量，实例图上实测，声明与实测漂移 ≥1 档警告不 block）；**每档定义必须写死 P 维下限**（声明 E2 档即承诺 P=3——把心智负担从测量问题转为档位定义问题）。P 是唯一含判断的维度，争议时唯一裁决问句："选择空间是否相乘"；**P 维永久人工评定**（用户裁决：以真实玩家/用户体验反馈为最终裁决来源），测得向量无 P 代理，漂移警告不含 P 维。

**五维等权与档带 4/8/12 已经 11 款标定回归检验并签字定稿（2026-09-06）**：散点零排序倒挂、W9 重核门槛零误伤零漏放；两处已知张力（O 维"内容填充 vs 设计决策"语义、C 维组合相对性）按用户口径转"后台标记记录制"，积累实例后再议，不因单例改公式。

### 2.3 谱系标定样例

装备全谱系（sys.equipment 已按此入库）：E0 纯属性加成（W3 轻）→ E1 +品质词条（W7 中）→ E2 +技能 BD（W11 重，P 由 2 跳 3 的相变拐点）→ E3 +宝石（W12 重）→ E4 +合成冶炼（W15 极重）→ E5/E6 饱和续记。宠物谱系（P0 外观 W2 → P4 繁殖融合 W15）形状同构，证维度可迁移。W≥13 后总分饱和，强制附"机制累计数 + 内容量级"续记字段：组合校验用 W，人的沟通用续记。

已知局限（如实保留）：高段饱和靠续记补偿；P 维永久人工（已裁决接受）。

## 3. 组合三规则

### 3.1 core_loop 与关联强度 κ

**L2 新增必填决策点 `core_loop`**：最小可玩闭环的动词序列，每个动词绑定到一个系统实例。创作顺序纪律：core_loop 动词绑定允许引用"待实例化系统占位"，L3 实例化后回填校验。

**κ(S) ∈ {core, strong, weak, meta}**，纯结构判据按序取首个命中，机器可判、无自由裁量：

| κ | 判定 | 预算权重 |
|---|---|---|
| core | 系统机制出现在 core_loop 动词序列内 | 1.0 |
| strong | provides 核心循环消费的名词，或 modifies core 系统属性 | 0.75 |
| weak | 可绕开或影响间接（摘除后核心循环仍完整转动） | 0.5 |
| meta | 只在局外生效 | 0.25 |

**融合双环写法（附录《极端组合形态测试》修正案 7，写作规范）**：融合玩法（X+Y）的 core_loop 用**拉平写法**——内环（X 的循环）+ 衔接动词 + 外环（Y 的循环）+ 回流动词，拉平为单一动词闭环；"双环"作为报告层标签与文档注释（内环动词区间 / 外环动词区间）记录供人读，κ 判定只消费动词序列成员资格，不受影响。回流动词必须存在——没有回流就不是双环是单向流水线（也合法，但 κ 会如实把上游判 strong 非 core）。**跨核映射表必须显式落为接口边 + TableSpec，禁止藏在机制参数里**（藏参数里会绕过 V6 与 C 维计数）。

### 3.2 R-C1′ 重核连通性

形态枚举 F0-F3 作为校验依据已删除（F 名保留为报告层描述标签）。设 **H = {W≥9 且 κ∈{core, strong} 的系统实例}**，三查：

- **(a) 连通**：H 的诱导子图必须连通——**硬 block，不可豁免**；
- **(b) 强耦合**：H 中每个节点与 H 内其他节点的接口边合计 ≥2——**硬 block，不可豁免**（(a)(b) 防的是"两个游戏钉在一起"的结构缺陷，与玩法大小无关）；
- **(c) 数量参考线**（用户裁决 2026-09-03 改制：**提示义务，非设计义务**）：|H| 对照 L0 档位参考线（超休闲 0 / 休闲 1 / 中核 2 / 重核 3 / MMO 4）。超线**不 block**：提示 + 一次性署名形态确认（R3 留痕，h_set 变化确认失效重签，AI 永不代签）；确认后 AI 的设计义务转向**逐重核系统的轻重需求访谈**（逐系统确认档位与理由），总体形态由用户自行设计。档位枚举会无穷倒退，故不为任何超大玩法新增档位。

双连通（无割点）守卫为**提示级**（检出货币桥式钉接嫌疑时提醒，不拦；ARPG 单主核轮毂拓扑是常态，措辞分流列为观察项）。

样板实证的三条判定路径：spire_like |H|=3 超线 → 确认流（5a）；autochess_thin |H|=1 压线免确认（5b）；towerdef_thin |H|=0 空集（5d）。

### 3.3 R-C2 重度预算（声明档单轨）

**B(G) = Σ W(S) × weight(κ)**，W 一律取声明档映射的全局五维分；测得分不参与预算校验，仅出漂移警告。

**五档预算值已标定定稿（用户签字 2026-09-06，报告 `docs/memory/w7_wave5/5-0_标定报告.md`）**：

| 档 | hyper_casual | casual | mid_core | hard_core | mmo |
|---|---|---|---|---|---|
| B(G) 上限（参考线） | **12** | **28** | **42** | **55** | **68** |

数据文件 `knowledge/calibration/budget.json`（`CompositionBudget` 同形，删除即回滚静默态）。预算刻度语义 = **设计复杂度**（非团队规模/品质成本——用户裁决；星露谷一人开发判重核档是正确结论，CS2 的"重核竞技"直觉混入了射程外的品质成本）。报告按 weight×W 降序列出"最贵的系统"，指向减重度档而非删系统。

**超预算永久制度（用户裁决 2026-09-06）**：超预算**不 block、不新增档位**——一律提示 + 一次性署名形态确认（与 |H| 超线同一制度）。五档是**参考线上界**而非硬墙：B(G) > 68 的组合（EU4 型 84、大战略+MMO 混合型等）照常提示并走署名确认；附录修正案 1/3 的"大战略档 95-105"方案**正式作废**（新增档位会随玩法规模无穷倒退）。五维权重与档带的调整走"后台标记、积累实例后再议"的记录制。

### 3.4 R-C3 重度传导

传导走接口边。载体：`HeavinessTier.inductions: Vec<Induction>`——本模块处于本档（含以上）时对其他系统的最低档位要求，附 reason 进 finding 文案。**传导目标支持名词析取**：`Induction.target: ModuleId | NounProvided(NounId)`（"装备 E3 需要宝石有源"由掉落**或**商店任一 provides 即满足，不点名模块防误报）。维度级要求写进目标模块的档位定义内容。传导闭包 = 有限格上的单调不动点，worklist 迭代必终止。双向性：正向（重系统要求承接系统跟上最低档）机检；反向超配只警告不 block。

### 3.5 违例清单与冻结门合流

校验器为纯函数（`adm4-decision/src/composition.rs`），违例两类——block 与 advice：

| 违例 | 内容 | 处置（现行实装口径） |
|---|---|---|
| V1 传导缺口 | Induction 目标（模块或名词）在组合中不存在 | block |
| V2 传导不满足 | 目标实例声明档低于传导要求（附完整传导链） | block |
| V3a/V3b 连通/强耦合 | R-C1′(a)(b) | block，不可豁免 |
| V3c 数量参考线 | \|H\| 超参考线 | **advice + 署名形态确认**（改制后口径） |
| V4 重而弱关联 | W≥9 且 κ∈{weak, meta} 的实例 | block（重系统游离在核心循环外） |
| V5 预算 | B(G) 超档位参考线 | **advice**，附逐系统降序分值表 |
| V6 悬空消费 | consumes 名词无人 provides 且非 pack 核心名词 | 加载失败 |

落点：全部并入 **gate2_consistency**（不新增第 5 道冻结门）；同一纯函数同时挂 authoring 期即时反馈（`compose report`），不用等冻结。冻结门仍为五道：完备度 → 一致性（含组合校验）→ 换皮 → AI 红队 → 哈希冻结。

## 4. tier 激活：合成决策点复用 unlocks

不新造激活机制。加载器为每个系统实例合成一个 L3 单选点 `<instance_id>.tier`，每个允许档位一个选项，选项 unlocks = 该模块中所有 `tier_gate.rank ≤ 本档 rank` 的点 id。档位选择走现有 select → unlocks 激活 → 完成度分母 → gate1 整条链路；换挡等价于既有"改选致下游失活"语义。`DecisionPoint.tier_gate: Option<TierId>`（serde default None，旧清单零影响）：项目对该模块选定档位低于此档时，点不激活、不进完成度分母。`allowed_tiers` 收窄会把不可达档位的点连带剔除（含关联一致性规则）。tier 合成点须 ≥2 选项（结构约束，单档模块需迁移承接档等手法，见 sys.tactical_board 的 MG0/MG1 先例）。

三条工程不变量全程有效：**I1 确定性守恒**（新分支全是纯函数投影）、**I2 serde 旧档守恒**（新字段 `#[serde(default)]`、新枚举新 tag）、**I3 校验前置**（新非法状态在冻结门或 C0 拦截）。

## 5. EffectSpec 16 变体与 Graph/Curve 参数

### 5.1 EffectSpec：7 → 16 分层封闭枚举，**16 变体全部真渲染（1c 后全交付，无未交付臂）**

序列化保持单层 tag 枚举（旧 7 个 tag 与字段一个不动，旧 JSON 逐字节兼容），语义分三层确定性等级：

| 层 | 变体 | C4 投影承诺 | 交付状态 |
|---|---|---|---|
| 第 1 层 封闭核心（7） | ModifyProperty / SpawnEntity / DespawnEntity / ChangeState / GrantResource / ConsumeResource / EmitSignal | 全语义投影 | ✅ 一直交付 |
| 第 2 层 受控扩展（8） | Displace / AreaApply / Attach / Detach / Schedule（Delayed/OverTime/Periodic × Seconds/Turns/Ticks）/ ModifyRule（封闭 RulePatch：ScaleCoefficient/ReplaceFormula/Disable/Enable/AddPrecondition）/ DrawFromPool / RollCheck（on_success/on_failure 两分支） | 模式投影：每变体一个固定渲染函数，字段全部来自作者填写 + `substitute_placeholders`；穷尽匹配无 `_` 臂 | ✅ **1c（2026-09-06）后八臂全部真渲染**：波 1 交付 Displace/Schedule/ModifyRule/DrawFromPool，1c 交付 AreaApply/Attach/Detach/RollCheck |
| 第 3 层 逃生舱口（1） | Custom（verb + 类型化 operands + 必填 GWT 三段模板） | 转录投影：只誊写设计者自己写的验收模板，模板缺失 → C0 按 R2 阻塞 | ✅ 交付 |

**叠加序**：`ModifyRule` 与 `Attach` 带 `priority: i32`；同目标多修饰器按 priority 结算，同序冲突按机制 id 字典序确定性 tie-break；C4 将叠加序渲染进 GWT（尖塔样板"力量类先加、乘算类后乘"字面验收，5a §2 伤疤 2）。`ModifyRule` 的 target 必须是 spec 内真实 mechanic id 或系统声明的 RuleSlot 名词，悬空 → 校验错误不可能流到 C4。1c 另补 `check_effect_references` 悬空复检（Attach/Detach target 判据同 effect_dangling_entity、Detach 的 modifier 须被某 Attach 声明过）。

**effects_template 的 entity 引用纪律**：一律 `{param:xxx_table_id}` 占位符 + 必填 scalar 参数，禁止裸语义名（C1 `effect_dangling_entity` 拦截）——波 5 三样板与 1c 已把选用路径上的模块数据全部占位符化；已知基建缺口：Rows/Matrix 参数不走 `substitute_placeholders`（表结构选项的裸 entity 无占位符修复路线），登记量产波。

**未来扩展变体的纪律**：第 2 层的扩法可重复（这是射程拓宽通道之一，见 §7.2）；扩展期间的未交付渲染臂必须是结构化 `Err("效果变体 X 的需求渲染未交付")` + 锁定测试，禁 `todo!()`/`unimplemented!()`/`_` 臂——1c 前四臂的中间态即按此纪律运行，纪律永久保留给未来扩展。

### 5.2 Graph / Curve 参数

`ParameterSchema`/`ParameterValues` 各加 Graph、Curve 两个 tag 分支（旧 tag 不动）。GraphSchema：节点/边负载（复用 ScalarField，含 is_skin）、directed、acyclic、entry 约束、节点基数键；校验：边端点必须是已声明节点、acyclic 声明则拓扑检查（假 acyclic 被 `graph_cycle_in_acyclic` 拦截）、节点数进基数期望。GameSpec 有 `graphs: Vec<GraphSpec>`（serde default），`contains_ref`/`all_ref_paths` 含 graphs 分支（R4 锚定闭合）。**对话/图类模块默认 `acyclic=false`**（对话大量回环 hub），仅天赋树/肉鸽地图类显式声明 true（尖塔地图 acyclic=true 已样板实证）。

Curve 不加新 section，C0 编译成两列 (x,y) Table + 插值注记，复用既有表通路（音游 accuracy_curve 已样板实证）。**已知宽度缺陷（如实保留）**：CurveSpec 是单值 y=f(x)，二维偏移序列（CS2 后坐力）装不下，退化为多列 Table——表达位仍有，语义降级如实声明；"音游谱面=Curve"逐案核结论是否定（谱面是多列实体行，走 entity_table；SV 变速段退化四列 Table 已如实申报）。二维序列类型是已标注的升级路径（§7.2 通道 3）。

### 5.3 design_notes：rationale 进编译链

`DesignNote { source_decision, source_option, role: Rationale|Statement, text }`，五类 spec 元素各带 `design_notes`（serde default）。C0 装入选择的 rationale 与 statement；C2 `source_text` 追加注记；C4 契约渲染进"设计意图"小节。**纪律：注记只被携带与展示，永不被编译成结构**——GWT 仍只从结构化字段派生（I1）。

## 6. custom 入口（原创机制一等公民）

- **机制级**：`add_custom_mechanic(CustomMechanicDraft)` 引擎 API（走既有 confirm 纪律，AI 永不代确认）。草案强制与内建 L4 选项同等信息密度：归属系统必填、rule_text 必填、effects 走 EffectSpec 全集当场反序列化 + 悬空校验、Custom 变体必带 GWT 三段、rationale 必填。落地为 `is_custom: true` 的项目私有单选点走全部既有链路，冻结落 `frozen/v{N}/custom_points.json`、流水线跑增广空间，C0 零特殊分支。"每点 custom 选项"由引擎统一注入而非 pack 作者逐点手写。审计 B 两个失败机制（可编程索敌/波次自适应变异）现全链到 C4 契约 + C6 任务——回归钉子锁定。
- **换皮纪律**：R5 扫描显式覆盖 custom（custom 恰是整段抄袭的最大通道，无豁免）；gate4 每个 custom 必须显式处置（accept/revise + 署名，缺失即 block）。custom 占比 >40% 警告——**阈值试用制**（用户裁决：跨多项目试用，每个真实项目结束时收集体感反馈，多项目后定终值）。
- **私有/入库分层**：项目私有 custom 不走 pack 认证（零参考游戏即可冻结），天然拆掉"原创混合玩法找不到 3 个参考"的死锁；沉淀入模块库时才认证（加严红队通道：评审加倍 + 主创署名）。组合模板维持 ≥3 参考硬要求（模板是复用资产）。
- 系统级 custom：项目私有系统模块经 `system_module_add` 入项目（`content/system_modules.json`），波 3a 已落地。

## 7. AI 访谈三段式与射程边界宣言

### 7.1 访谈三段式（主创作路径）

访谈引擎从"逐决策点问答"升级为系统级三段（AI 提案 + 用户确认、AI 永不代确认，schema 见 `docs/design/08`）：

1. **概念访谈**：用户口述想法 → AI 提议系统清单 + 重度档 + core_loop 草案（system prompt 注入已占用实例 id 清单与硬约束——6pre 修复）。内置两个**形态嗅探器**（提示词层，不新增机器规则）：
   - **大战略型嗅探**：预判 |H|>4 时——AI 只提示不设阻（一次性形态确认后不再劝减），设计火力全部转入**逐重核系统的轻重需求理清**（"这个系统你要轻度还是重度？对标哪款游戏的哪个系统？"→ 落为档位声明与 rationale）；总体形态由用户自行设计。
   - **融合型嗅探**："X+Y"句式命中后走六步流程（系统并集 → 识别双核定重 → core_loop 双环拉平 → 跨核资源映射表 → 组合校验预期 → 冻结与沉淀），**必问跨核连接问句**："两个玩法在哪里交换资源？"——答案即映射表草案。
2. **组合访谈**：校验器违例 → AI 人话解释违例并给出闭集修复选项（升档/降档/换系统/署名确认），|H| 引导署名但 AI 不代签。
3. **机制访谈**：进入各系统内部逐激活点提案；**PromptLibrary**（v2 2575 点降级而成的访谈提示词库，现 211 条，不进完成度分母/冻结门）作为追问弹药；custom 草案可由 AI 起草仍走用户确认。

手动逐点操作保留为兜底路径。真 AI 通道已验证可用（DeepSeek 实调用，6 次复验零静默放行、AI 输出结构合规率 6/6）；已知语料层遗留见波 6 上呈清单。

### 7.2 射程边界宣言（用户已裁决：接受收窄 + 必须保留拓宽通道）

模型显式放弃四类：**手感定稿**（参数有位、品质无门：后坐力/毫秒操作/延迟补偿算法）、**物理涌现**（单跳传播可表达，多跳涌现结果不可静态推导）、**netcode**（完全在外）、**叙事内容本体**（容器完整，百万字写作质量不在射程内）。射程外清单是特性不是耻辱——模型必须能说出自己装不下什么，才能防"覆盖很广的假象"。

**四条拓宽通道（裁决附加条件的兑现，任何一类射程外能力将来都有回收路径）**：

1. **系统库开放入库**：40 系统是开放清单不是封闭集，custom 系统经加严红队认证可沉淀为新模块（仅新增 module.json，无痛接入纪律保证零架构改动）；
2. **EffectSpec 受控扩展层可重复扩**：将来支持新机制类别（如物理力效果），在第 2 层加变体 + 一个固定投影函数即可，不动封闭核心；
3. **参数类型可增**：Graph/Curve 之后可继续加类型（如二维序列，即可回收 CS2 后坐力缺陷）；
4. **射程外参数位**：四类放弃项各留参数位（手感参数表/物理系数/校准参数），引擎侧定稿后可回填，设计文档不失完整性。

覆盖性事实与实证等级见 `docs/design/09_覆盖性声明.md`。
