## 1. 项目创作状态（AuthoringState，设计期唯一权威）

```rust
pub struct AuthoringState {
    pub project_name: String,
    pub genre_pack: GenrePackId,
    pub pack_version: String,
    pub depth_profile: DepthProfile,               // 创建时选定，L4/L5/L6
    pub selections: BTreeMap<DecisionId, Selection>,
    pub not_applicable: BTreeMap<DecisionId, NaJustification>,
    pub interview: InterviewState,
    pub template_mode: TemplateMode,               // None | Prefilled(TemplateId) | Compare(TemplateId)
    pub revision: u64,                             // 每次变更 +1
}
```

变更操作（引擎方法，全部经校验）：
- `select_option`：校验选项存在、requires 满足、conflicts **硬拦截**（违例返回错误并列出冲突源）；
- `set_parameters`：按 `ParameterSchema` 逐字段校验类型与约束；表/矩阵按行/格校验；
- `set_rationale` / `confirm_selection` / `mark_not_applicable(reason_code)`；
- `clear_selection`：级联检查——若其它选择 requires 本选项，列出受影响项。

每次变更后重算适用性（unlocks 激活图）与完成度，供 UI 实时显示。

## 2. 两种作业模式

**模式 A · 手动选择**：UI 按领域 × L 层组织决策点；AI 不可用时始终可用。

**模式 B · AI 访谈（分层逐条确认）**：

| 层 | 确认单元 | AI 行为 |
|----|---------|--------|
| 结构层 L0-L4 | 每决策点逐条 | 提案「建议选 X，理由，参数建议」；用户确认/改选/改参/跳过 |
| 参数表层 L5-L6 | **整表** | 提案整表值（每格挂 rationale）；用户确认整表为一个决策，可**例外下钻**改任意行/格 |

```rust
pub enum InterviewTurn {
    StructuralPoint { decision_id: DecisionId, proposal: OptionProposal },
    TableProposal   { decision_id: DecisionId, proposal_rows: ParameterValues,
                      cell_rationales: Vec<CellRationale> },
}
```

硬规则：
- **AI 永不代提交**：只有 `confirmed_by_user=true` 的 Selection 计入完成度；不存在任何「强制输出/批量代确认」入口（吸取三代 `force_ai_output` 教训，V4 不提供该命令）；
- AI 按决策图拓扑序逐点提案；访谈可分多次，进度持久化在 `InterviewState`；
- AI 不可用时模式 B 整体不可用（显式提示），不锁死模式 A；
- 两模式可混用（访谈 80% + 手动补 20%）。

## 3. 冻结门五道（进入流水线的唯一入口）

落 `adm4-authoring::freeze`，按顺序全通过才可冻结：

| # | 门 | 机器判定规则 |
|---|----|------------|
| 1 | **完备度/拆分就绪度** | 适用决策点均 confirmed；L5/L6 表结构/行数据完整（按深度档：L6→每表填满、每矩阵格有值）；缺格→`Blocked`+待填清单，不给默认值（R2）。`custom` 选项必须有结构化描述，比例进报告 |
| 2 | **一致性** | requires/conflicts 图零违例 + 品类包 `consistency_rules` 跨决策校验（如「克制矩阵行数=守卫种类数」） |
| 3 | **换皮门** | 所有 `provenance=Template(*)` 选择的 `skin_fields` 参数与 `template_original` 逐字段比对，未改→block；全部产出文本过参考名扫描（词表见 02 号），命中→block 列位置 |
| 4 | **AI 红队评审** | AI 以对抗姿态找设计矛盾/不可实现点/体验断裂；产出必须携带 `ReviewProof`（R3：条目数核对+哈希互异+零发现证据）；发现项用户逐条处置（修改/接受风险）后方可通过；AI 不可用=blocked（R7） |
| 5 | **冻结** | 决策集+品类包版本+深度档 → 规范化 JSON → sha256 内容哈希 → 只读 |

> 门 1 是枢纽：完备度检查的正是「下游能否不发明就拆分」——L4 达公式符号级、L5 是真表结构，是 C4 能"派生而非发明"的准入前提。

### 3.1 冻结产物

```rust
pub struct FrozenDesign {
    pub version: u32,                    // 冻结版本号，修改=新版本，旧版只读
    pub decisions: Vec<Selection>,       // 规范化排序
    pub not_applicable: Vec<(DecisionId, NaJustification)>,
    pub genre_pack: GenrePackId,
    pub pack_version: String,
    pub depth_profile: DepthProfile,
    pub content_hash: String,            // sha256:hex
    pub frozen_at: String,               // 调用方注入时间戳

}
```

`FrozenDesign` 是唯一内容真相源；C0 以它为唯一输入。UI 冻结面板展示五道门状态与逐门 block 清单，全绿才可点冻结。
