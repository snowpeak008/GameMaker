# V4 设计 · 05 · 七条红线的机器化

> 落点 crate：`adm4-contracts`（类型）+ 各消费点强制
> 依据：redesign_v3 文档 07。三代病灶都是约束缺失，V4 把红线落成类型，使违反在代码层就困难。

---

## R1 指标即测量

任何报告中的分数/计数必须携带证据指针；证据为空而指标非零 → 构造即拒。

```rust
pub struct MeasuredMetric {
    value: f64,
    evidence: Vec<EvidencePointer>,
}
impl MeasuredMetric {
    pub fn new(value: f64, evidence: Vec<EvidencePointer>) -> Adm4Result<Self> {
        if value != 0.0 && evidence.is_empty() { return Err(/* R1 violation */); }
        Ok(Self { value, evidence })
    }
}
pub struct EvidencePointer { pub file: String, pub path: String, pub observed: String }
```

字段私有 + 构造校验 ⇒ 报告结构里无法出现无证据的非零指标。

## R2 未知即停

派生函数返回 `Derive<T>` 而非 `T`：

```rust
pub enum Derive<T> { Resolved(T), Blocked { unknown: Vec<UnclassifiedItem> } }
```

C0 编译、C3 视觉白名单、C4 机制投影等所有派生路径使用；派生路径禁止 `unwrap_or*` 兜底（代码评审约束）。

## R3 评审最低工作量证明

```rust
pub struct ReviewProof {
    pub reviewed_count: usize,     // 必须 == upstream_count（或带显式抽样清单）
    pub upstream_count: usize,
    pub content_hash: String,      // 同批评审哈希全同 → 判橡皮图章 → fail
    pub per_category_evidence: Vec<CategoryEvidence>, // 零发现也要填「查过什么、为何没问题」
}
pub fn verify_review_batch(proofs: &[ReviewProof]) -> Adm4Result<()>; // 数量+哈希互异校验
```

用于 C1 红队、冻结门第 4 道、逆向 S3 交叉核验。

## R4 AI 产出锚定

```rust
pub struct AnchoredNarrative { pub text: String, pub anchors: Vec<SpecRef> }
```

C2/C3/C4 的 AI 叙述产物必须是 `AnchoredNarrative`；`anchors` 为空或路径不存在于 GameSpec → fail。C2 门禁「锚定覆盖率 100%」即对全部声明检查。

## R5 参考名扫描全程在线

```rust
pub struct SkinScanner { wordlist: Vec<String> }   // 模板库 game_name+aliases + 品类包 reference_games
impl SkinScanner { pub fn scan(&self, text: &str) -> Vec<SkinHit>; }
```

挂在 `ArtifactWriter` 落盘钩子：冻结门 + C0-C6 每步产物都扫，命中 → step fail + 列位置。

## R6 基数申报

```rust
pub struct CardinalityDeclaration {
    pub rule: String,                 // 映射规则（人读+机器记）
    pub produced: usize,
    pub expected: CardinalityRange,   // 来自品类包 cardinality_expectations
    pub dropped: Vec<DroppedItem>,    // 丢弃清单，不能静默丢
}
```

C3（实体→资产）、C4（机制→需求）强制返回；`produced` 超界 → 人工确认门（block 到确认，非 fail）。

## R7 fallback 禁令

- AI 调用失败路径**只能**产 `StageStatus::Blocked { reasons }`，不得转模板/默认值后报 success；
- `adm4-ai` 的 Provider 接口不提供任何「降级」参数；
- 不存在「强制输出/AI 代确认」命令；
- 代码评审 + CI 检查：AI 失败分支若接「读模板/取默认」再返回成功状态 → 违规。

## 落地节奏

红线类型在工程第一批交付（与 foundation 同期），后续每步「只能」用带约束的类型：

| 消费点 | 强制红线 |
|--------|---------|
| 逆向工具链 | R3（交叉核验哈希异）、R7、宁缺勿造 |
| 冻结门 | R2（缺格 blocked）、R3（红队证明）、R5（换皮扫描） |
| C0-C2 | R1、R3、R4（C2 锚定）、R5 |
| C3-C6 | R1、R2（视觉白名单）、R4、R5、R6（基数申报） |
