# AutoDesignMaker 第四版（V4）总体设计

> 版本：v4-design-1（2026-08-29）
> 性质：第四版的**架构真相源**。全新工程，与 Python 第一版、`RUST/` 第二版、`NEWrust/` 第三版的代码**零关联**（不 import、不复制、不兼容旧存档格式）。
> 设计依据：
> 1. **设计结构基线** = `RUST/` 第二版的产品设计（六任务区工作台交互契约、分层决策模型、正式存档体系、验收追溯链、AI 层抽象）。
> 2. **最终形态** = `plan/redesign_v3/`（2026-07-25/26，尚未开发的最新设计）：决策驱动 L0-L6、品类包、模板逆向答卷、冻结门五道、C0-C6 文档编译流水线、P0-P5 EXE 生产边界、七条红线机器化。
> 3. 三代病灶（经代码实读逐条坐实）作为反面约束，在类型层杜绝复发。

---

## 1. 产品定位

AutoDesignMaker V4 是一个**决策驱动的游戏设计与生产工作台**：

- 用户在**决策工具**中通过封闭枚举选项 + typed 参数完成游戏设计（手动模式 / AI 访谈模式）；
- 设计经**冻结门五道**固化为唯一内容真相源 `FrozenDesign`；
- **C0-C6 文档编译流水线**把冻结集确定性编译为 GameSpec 并产出双格式文档集（机器契约 + 渲染 Markdown）；
- 选 L6 深度档的项目可进入 **Phase 2（P0-P5）** 生产可玩 EXE（本版只定边界，另行立项）；
- **模板生产线**（逆向工具链）独立于项目流程，把知名成熟游戏逆向为带来源标注的答卷，经人工审核认证入库，作为品类包校准来源与项目预填素材。

核心不变式（继承 redesign_v3 §2）：

> **内容只在决策工具里创作一次；此后每一步都是从 GameSpec 的确定性派生或经门禁的 AI 加工，任何步骤不得引入决策集里不存在的设计内容。**

## 2. 三代病灶 → V4 回应

| 病灶 | 三代表现（代码实读坐实） | V4 回应 |
|------|------------------------|---------|
| 创作环节缺失 | 一代靠模板蒙混；二代 Brief 模板生成；三代绕开手写 fixture | 创作全部发生在决策工具内；冻结门第 1 道（完备度）是流水线准入 |
| 参考与项目混同 | 模板 projectState 整卷进项目无换皮约束 | 数据层 Provenance 区分 + 冻结门换皮门 + 全程参考名扫描（R5） |
| 指标非测量 | score 恒 100/60、coverage 恒 1.0、`unbound=[]` 硬编码 | `MeasuredMetric` 类型：空证据非零即构造失败（R1） |
| fail-open 默认 | 「认不出→art_asset/2048/P0」式默认值 | `Derive<T>` 类型：未知输入→`Blocked`+待分类清单（R2） |
| 评审橡皮图章 | 三份评审同哈希、review 恒 passed、blockers 恒 [] | `ReviewProof`：数量核对+哈希互异+零发现证据（R3） |
| AI 发明设计 | AI 叙述无锚定 | `AnchoredNarrative`：无锚定即 fail（R4） |
| AI 失败静默兜底 | AI 失败→模板兜底→报 success | 全系统无 fallback 路径；AI 失败=blocked+原因（R7） |
| 双轨双语义并存 | 三代 ProjectState/GameSpec 双权威、两套 L 语义 | **单一权威**：设计期=决策项目状态；冻结后=FrozenDesign→GameSpec。L0-L6 唯一语义 |
| 上帝模块 | 1.3 万行 generation.py、11 万行 core_pipeline.rs | 每 crate 单一职责，流水线每步一个 executor 文件 |
| 步骤空心化 | plugin/prompts 与真实逻辑脱节 | 步骤=真实 executor，无占位提示词文件 |

## 3. 分层架构与 crate 划分

```
V4/                              全新 Cargo workspace（edition 2024, rust 1.96）
├── crates/
│   ├── adm4-foundation          错误/ID/sha256 内容哈希/规范化 JSON/原子写/安全路径/时间戳
│   ├── adm4-contracts           跨层 DTO + 七条红线类型（MeasuredMetric/Derive/ReviewProof/
│   │                            AnchoredNarrative/SkinScanner 词表/ CardinalityDeclaration）
│   ├── adm4-decision            决策模型：DesignLevel L0-L6 / DecisionPoint / DecisionOption /
│   │                            ParameterSchema(Scalar|Table|Matrix) / Selection / DepthProfile /
│   │                            适用性判定 / DAG 校验器（Kahn）/ 完成度计算
│   ├── adm4-space               设计空间清单输入门：通用层+品类包加载/校验（≥3 参考、基数期望、
│   │                            矩阵轴引用）/ 交叉验证报告
│   ├── adm4-template            模板体系与逆向工具链：TemplateAnswer/Evidence/Template/认证/
│   │                            覆盖率报告/换皮词表登记/EvidenceSearchChannel trait/AI 映射/交叉核验
│   ├── adm4-spec                GameSpec（全新定义）：intent/entities/actions/state_machines/
│   │                            resources/content/acceptance(GWT)/SpecRef 锚定/规范化+sha256/校验
│   ├── adm4-authoring           创作引擎：项目状态（选择集）/ 手动模式操作 / AI 访谈（结构层逐条 +
│   │                            L5-L6 整表提案+例外下钻）/ 模板预填与对照 / 冻结门五道 / FrozenDesign
│   ├── adm4-pipeline            流水线框架（registry/StageExecutor/状态机/checkpoint/双格式产物）
│   │                            + C0-C6 七个 executor + 换皮扫描落盘钩子 + 一致性双向核对
│   ├── adm4-archive             数据根/正式存档/存档锁/草稿工作区/原子保存/内容指纹/导出导入包
│   ├── adm4-ai                  Provider 抽象/OpenAI 兼容 HTTP/preset/SecretRef/预算/journal/
│   │                            fail-closed（无兜底）
│   └── adm4-app                 应用编排：项目生命周期/创作服务/冻结服务/流水线服务/运行日志/
│   │                            文档集打包/SDK 知识库
├── apps/
│   ├── adm4-cli                 全流程 CLI（空间校验/创作/冻结/编译/逆向/存档/AI 诊断）
│   └── adm4-desktop             Slint 桌面（任务区：设计工作台/冻结门/流水线/模板逆向/打包/日志/SDK）
├── knowledge/
│   ├── design_space/            设计空间清单（schema/空白模板/最小样例/示例品类包）
│   └── schemas/                 JSON Schema
└── docs/design/                 本设计文档集
```

依赖方向（严格单向，低→高）：

```
foundation → contracts → decision → space ──┐
                     │        └── template ─┤
                     └── spec ──────────────┼→ authoring → pipeline → app → cli / desktop
                                 archive ───┤                          ↑
                                 ai ────────┴──────────────────────────┘
```

纪律（继承 rustplan + NEWrust 独立化经验）：

- `unsafe_code = forbid`；GUI/CLI 无业务规则，只调 `adm4-app`；
- 所有路径经 foundation 的安全路径工具，禁止硬编码用户路径；
- API 密钥不进存档、不进日志（Debug 脱敏）；
- 测试不依赖真实 AI/网络/用户目录（AI 用注入的确定性测试 Provider）。

## 4. 两阶段生命周期与任务区

### 4.1 项目生命周期

```
创建项目（选品类包 + 深度档 L4/L5/L6，可选模板预填/对照）
   ↓ 设计阶段（可反复）
决策工具：手动选择 ⇄ AI 访谈（分层逐条确认）
   ↓ 冻结门五道（完备度→一致性→换皮→AI 红队→哈希冻结）
FrozenDesign（只读，唯一内容真相源；修改=新冻结版本）
   ↓ Phase 1：C0-C6 文档编译
双格式文档集（机器契约 + 渲染 MD）+ 两个人工门（C5 风格、C6 签收）
   ↓（仅 L6 深度档；本版只留边界）
Phase 2：P0-P5 EXE 生产（另行立项）
```

### 4.2 桌面任务区（继承第二版六任务区交互契约，按 v3 轻改）

| 任务区 | 内容 | 来源 |
|--------|------|------|
| 设计工作台 | 领域 × L 层组织的决策点列表/表单；选项+implications；L5/L6 表格编辑；实时完成度与冲突高亮；AI 访谈面板 | v2 外壳 + v3 节点重做 |
| 冻结门 | 五道门状态 + 逐门 block 清单（待填清单/冲突/换皮命中/红队处置）+ 冻结按钮（全绿才可点） | v3 新增 |
| 开发流水线 | C0-C6 阶段卡（数据驱动，面板与步骤解耦）；区间执行；C5/C6 人工门；双格式产物查看 | v2 面板规格 + v3 数据 |
| 模板逆向 | 逆向工具链人工审核界面（独立于项目流程的维护工具）：逐领域过卷/证据链接/改/退回/认证 | v3 新增 |
| 打包 | Phase 1 文档集交付打包；（L6 项目显示 Phase 2 入口占位） | v2 |
| 运行日志 | 结构化执行事件，过滤与回看 | v2 |
| SDK 知识库 | SDK 知识收集/审批/呈现 | v2 |

## 5. 单一权威状态（终结双轨）

| 阶段 | 权威状态 | 说明 |
|------|---------|------|
| 设计期 | `AuthoringState`（决策项目状态：每决策点的 Selection + 访谈态 + 画像） | 草稿自动保存；正式存档显式提交 |
| 冻结后 | `FrozenDesign`（规范化 JSON + sha256，只读） | 版本化；旧版永不改 |
| 编译后 | `GameSpec`（由 C0 确定性编译，绑定冻结哈希） | 下游一切派生的唯一输入 |

**不存在**第二套并行的域/节点勾选状态。第二版的「域→节点→检查清单」层级保留为**决策点的组织维度**（domain 字段 + L 层），不再是独立的状态树。
