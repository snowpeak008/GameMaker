## 1. 模板的定义

模板 = **一个知名成熟游戏在当前选项体系下的逆向答卷**，是品类选项空间里的一个**参考点**——用于校准品类包、预填/对照项目，**不是项目要复刻的目标**。

```rust
pub struct Template {
    pub game_name: String,
    pub aliases: Vec<String>,           // 换皮门扫描词表来源
    pub genre_pack: GenrePackId,
    pub pack_version: String,
    pub depth_reached: DesignLevel,     // 逆向到哪层（可低于 L6）
    pub answers: Vec<TemplateAnswer>,
    pub coverage: CoverageReport,       // 各层覆盖率 + 低置信度清单
    pub certification: Certification,   // { reviewed_by, date, status: Draft|Approved|Rejected }
}

pub struct TemplateAnswer {
    pub decision_id: DecisionId,
    pub option_id: OptionId,
    pub parameters: ParameterValues,
    pub evidence: Vec<Evidence>,
    pub notes: String,                  // 逆向者备注
}

pub struct Evidence {
    pub source_url: String,             // 必填（宁缺勿造）
    pub quote: String,
    pub source_type: SourceType,        // Official | Wiki | Datamine | Inference
    pub confidence: Confidence,         // High | Med | Low
}
```

原则：
- 只逆向**官方标准版玩法**，不收模组/玩家自制内容；
- L6 数值允许社区测定数据，但 `source_type`/`confidence` 如实标注；
- 查不到就空着并进 `coverage`——**宁缺勿造**；
- **未经人工审核（`certification.status != Approved`）的模板不能入库、不能预填项目**。

## 2. 产线五步

```
S1 检索(混合D) → S2 AI映射填答 → S3 交叉核验 → S4 人工审核 → S5 认证入库
```

| 步 | 输入 | 处理 | 输出 | 红线 |
|----|------|------|------|------|
| S1 | 品类 + ≥3 参考游戏名 + 决策点清单 | 自动档拉官方/wiki 候选（`EvidenceSearchChannel`）+ 人工供证低置信/L6 | `EvidenceCandidate[]` | 无源即空 |
| S2 | 证据 + 选项空间 | AI 把证据映射到「选哪个选项+填什么参数」，每条挂 evidence | `TemplateAnswer[]` 草稿 | R4：每条挂 source_url |
| S3 | 低置信条目 | **第二个独立 AI 会话**复核，不同来源互相印证 | 核验标记（一致/冲突） | R3：两会话内容哈希必须互异 |
| S4 | 全部答卷 | GUI 逐领域过卷，可改可退回 | 审核通过标记 | 未审核不入库 |
| S5 | 通过的答卷 | 登记 game_name+aliases 进换皮词表；产 coverage_report | `Template`（Approved） | — |

### 2.1 联网证据通道（接口先行）

```rust
pub trait EvidenceSearchChannel {
    fn search(&self, query: &EvidenceQuery) -> Adm4Result<Vec<EvidenceCandidate>>;
}
pub struct EvidenceCandidate {
    pub source_url: String,     // 必填
    pub title: String,
    pub snippet: String,
    pub source_type: SourceType,
    pub fetched_hash: String,   // 内容哈希，可缓存/复核
}
```

两个候选实现（落地时二选一，接口不变）：带联网 CLI 包装 / 专用搜索 API。V4 本轮交付接口 + **人工供证通道**（审核界面「贴来源」入口，人贴 URL+引文）。自动档只做官方/wiki 概览广度；低置信与 L6 数值层强制人工供证。检索面向同品类 ≥3 款游戏横向描边界，不深挖单一游戏。

## 3. 模板进入项目（消费侧，落 adm4-authoring）

- **预填模式**：答卷整卷预填进决策工具，每条 `provenance=Template(id)`、`confirmed_by_user=false`、记录 `template_original` 参数原值；项目创建时明确警示「冻结前必须完成换皮」。
- **对照模式**：模板不进项目，仅在决策点侧栏显示「该游戏此处的选择与理由」。

---

## 4. 换皮扫描词表（接红线 R5）

S5 认证入库时把 `game_name + aliases` 写入全局换皮词表（`knowledge/design_space/skin_wordlist.json`，随品类包 `reference_games` 一并登记）：

- 供冻结门换皮扫描（03 号文档门 3）+ C0-C6 每步产物落盘前扫描（R5）复用；
- 入库即登记，卸载模板即移除对应词条；
- 扫描输出 `SkinHit { location, matched_word }`，命中即 block 并列出位置。
