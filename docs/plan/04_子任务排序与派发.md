## 任务卡验收标准

### T1 通道塔防包 L6 深化
1. 既有 15 个决策点/选项 id 一个不改不删；新增 L5 表结构点与 L6 行数据点，覆盖：守卫属性表、敌人属性表、克制矩阵、波次表、经济数值表。
2. 每个 L6 点带 `cardinality_expectations`；L4 机制点带 `effects_template`。
3. `reference_games` ≥ 3；正文零参考游戏名（R5）。
4. `space validate` 全绿；`cargo test --workspace` 全绿。

### T2 战棋品类包新建
1. 新建 `grid_strategy/pack.json`：L3（系统组成）→ L4（机制公式级）→ L5（表结构）→ L6（行数据期望）完整链，≥ 20 个决策点。
2. 与 lane_defense 零共享决策点 id（反品类污染）。
3. 其余同 T1 第 2-4 条。

### T3 逆向工具链产线
1. `FileCorpusChannel`：目录语料关键词检索实现 `EvidenceSearchChannel`。
2. `MappingService::map_answers(&dyn AiProvider, ...)`：证据 → `TemplateAnswer`，无 `Evidence` 拒收（R1），AI 非法输出直接 Err（R7）。
3. `CrossCheckService`：第二次独立 AI 会话对照，输出逐条一致/冲突报告；冲突降级待人工。
4. `Certification` 状态机：`Draft→Mapped→CrossChecked→HumanReviewed→Certified` 只进不跳；Certified 时自动登记别名进 `SkinWordlist`。
5. 全链单测（ScriptedProvider），含至少一个"跳级被拒""无证据被拒"的负例。

### T4 AI 访谈分层确认
1. `propose_next` 按 L 层升序推进（低层未全确认不进高层），同层按 DAG 拓扑序。
2. L5/L6 整表提案为一个确认单元；`confirm_proposal` 支持 `overrides` 例外下钻并记录进 transcript。
3. AI 发明选项/非 JSON → Err 停止（R7）；确认只能显式调用（AI 永不代提交）。
4. 单测覆盖：分层推进顺序、下钻、拒绝后重提、非法输出即停。

### T5 AppServices 门面扩展
1. 暴露：逆向产线五步命令、访谈回合（propose/confirm/reject）、模板预填/对照。
2. 每条新命令写 RunLog；写盘后刷新存档指纹。
3. e2e 新增场景：脚本化 AI 走逆向五步产出 Certified 模板 → 用其预填新项目 → 访谈补齐 → 冻结 → C0-C6 全绿。

### T6 CLI 子命令补齐
`template`（list/import-corpus/map/cross-check/review/certify）、`interview`（next/confirm/reject）、`prefill`；全部有 `--help` 中文说明；冒烟脚本可全程无人值守走完 T5 的 e2e 场景。
> **实际交付命令名（2026-08-29）**：`template new-draft|search-corpus|map|cross-check|review|certify|compare`；预填并入 `project new --template`；`interview` 多交付 `progress`；另有 `authoring set-rationale` 与 `scripts/cli_smoke.ps1`。`template list` 未做（门面未列，需要时一行可补）。

### T7 桌面 UI 四面板
L5/L6 结构化表格编辑器（行增删/格编辑）、访谈面板（提案展示/确认/拒绝/下钻）、逆向维护面板（五步状态+审核动作）、冻结门明细面板；GUI 无业务规则（D14）。
