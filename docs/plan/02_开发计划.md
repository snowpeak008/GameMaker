# V4 开发计划

> 状态：已定稿（2026-08-29）。定义里程碑、并行波次、角色分工与风险控制。
> 配套文档：`01_设计计划.md`（做什么）、`03_工程规范.md`（怎么做）、`04_子任务排序与派发.md`（谁做、什么顺序）。

---

## 1. 角色与协作模型

- **主开发（orchestrator）**：负责计划、任务派发、跨任务集成、验收与最终门禁。**不承担开发任务。**
- **子 agent（developer）**：每人领取一个任务卡，只在任务卡限定的文件范围内开发；完成后自验收（编译 + clippy + 本 crate 测试）并提交报告。
- **子 agent 模型**（用户指定，2026-08-29 起）：只能用 Claude 旗下模型，统一使用 Claude Opus 5 Thinking（`claude-opus-5-thinking-high`）。
- **验收 agent（reviewer）**：波次结束后并行审查代码质量、红线合规、测试真实性；发现问题回炉给新的修复 agent。

## 2. 并行策略与冲突控制

- 任务按 **crate/目录边界分区**：同一波次内任意两个任务的可写文件集合不相交。
- 共享文件（`V4/Cargo.toml`、`adm4-app/src/services.rs`、各 crate `lib.rs` 的 pub use）只允许该波次指定的一个任务修改；其余任务如需新 API，先在报告中声明，由下一波承接。
- 所有子 agent 共享同一工作区与 `target/`；cargo 自带构建锁，允许并发构建（会排队）。
- 子 agent 禁止 git 提交、禁止修改 `docs/design/` 与 `docs/plan/`、禁止触碰 V4 以外的目录。

## 3. 里程碑与波次

### M1（波次 W1，4 任务并行）：内容深度与核心能力

| 任务 | 范围 | 可写文件 |
|------|------|----------|
| T1 通道塔防包深化 | lane_defense 补齐 L6 | `knowledge/design_space/lane_defense/**` |
| T2 战棋包新建 | grid_strategy L3-L6 全深度 | `knowledge/design_space/grid_strategy/**` |
| T3 逆向产线 | FileCorpusChannel、MappingService、交叉核验、认证状态机、词表登记 | `crates/adm4-template/**` |
| T4 访谈分层确认 | 按层推进、整表确认单元、例外下钻、非法输出即停 | `crates/adm4-authoring/**` |

**M1 出口门**：四任务全部自验收通过 + 主开发全量门禁（fmt/clippy/test/space validate/e2e）绿。

### M2（波次 W2，1 任务）：服务门面集成

| 任务 | 范围 |
|------|------|
| T5 AppServices 扩展 | 把 T3/T4 新能力接入 `adm4-app`（模板产线命令、访谈回合命令、逆向审核动作），扩展端到端测试覆盖新链路 |

单任务执行，因为 `services.rs` 是共享瓶颈文件。

### M3（波次 W3，2 任务并行）：交互壳

| 任务 | 范围 | 可写文件 |
|------|------|----------|
| T6 CLI 补齐 | template/reverse/interview 子命令 | `apps/adm4-cli/**` |
| T7 桌面 UI | 表格编辑器、访谈面板、逆向面板、冻结门明细 | `apps/adm4-desktop/**` |

### M4（波次 W4，并行验收）：发布门

- 并行验收 agent：A) 全量门禁 + CLI 冒烟脚本化走查；B) 红线 R1-R7 与工程规范合规审查；C) 文档同步审查（README、docs/design 与实现一致性抽查）。
- 产出交付报告；主开发签署后 M4 关闭。

### M5（缓期，不派发）：Phase 2（P0-P5 EXE 产线）

仅保留架构接缝，待 Phase 1 产品验收后由用户决定立项。

## 4. 依赖关系

```
T1 ──┐
T2 ──┤（数据，互不依赖）
T3 ──┼──→ T5 ──→ T6 ─┐
T4 ──┘               ├──→ W4 验收
                T7 ──┘（T7 依赖 T5，与 T6 并行）
```

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| 并行任务改坏共享契约 | 波次内文件集不相交；lib.rs 导出冲突由主开发在波次间集成时统一处理 |
| 子 agent 降级测试换绿灯 | 工程规范明令禁止；验收 agent 专项检查测试 diff；违规回炉重做 |
| 数据包内容与校验器打架 | T1/T2 以 `cargo run -p adm4-cli -- space validate` 为硬验收；不许改校验器迁就数据 |
| e2e 测试锚定 id 被改坏 | 设计决定 D4：已有 id 只增不改不删 |
| cargo 并发构建锁等待 | 接受排队；任务卡要求子 agent 用 `-p <crate>` 限定范围减少全量构建 |
