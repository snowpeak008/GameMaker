# W7 附录：系统库缺口扫描 · 2026-09-02

> 受托方：外部资深制作人/系统策划评审。对象：`W7_设计方法论重构_定稿.md` §2.4 的 39 系统清单 + §9.2a 的 #40 职业流派。
> 方法：18 个指定品类 + 6 个补充品类逐一穷举"品类成立必需系统"，逐个对照 39+1 库；候选缺口全部过 §2.1 边界三测试（T1 独占状态 / T2 可摘除 / T3 名词转换）。
> 射程纪律：§6.5 四类显式出射程（手感定稿 / 物理涌现 / netcode / 叙事内容本体）**不计为缺口**，涉及处如实标注"射程外"。
> 结论速览：**发现 13 个候选新模块（P0×5 / P1×6 / P2×2）**，18 项特别检查项判定为"非系统"并给出归宿，对既有清单提出 8 条修订建议。

## 0. 扫描前提与两个立即可见的一致性发现

1. **定稿判例 2 与清单不一致**：§2.1 判例 2 白纸黑字认定"新手引导**是**系统（引导进度表独占、消费首次行为事件、产出 UI 修饰器）"，但它不在 39+1 清单内。这不是新发现的缺口，是定稿自身的登记遗漏，应径直入库（见 §2 候选 #G6）。
2. **§6.3 MOBA 分解通过校验但缺视野系统**：MOBA 的 H={技能, 战斗, 目标, 装备} 通过 R-C1′，但眼位/战争迷雾——MOBA 会话级核心决策之一——在分解里没有任何系统承载。这实证了本次扫描的必要性：组合校验器只能校验"已声明的系统"之间的关系，**声明遗漏它是看不见的**（见候选 #G4 视野侦测）。

## ② 候选新模块清单（按依赖品类数降序）

> 每条含：三测试 / 一句话定义 / M→D→A / 重度谱系草案 / 依赖品类 / 优先级。编号 G1-G13 仅本文内引用，入库时续 #41 起。

### G1 建造放置（依赖 9 品类）**P0**
- **三测试**：T1 独占"世界格/槽位归属表"（哪格放了什么，含朝向/层级）✓；T2 摘除后暗黑类/卡牌类完全自洽 ✓；T3 消费建筑/塔实体+材料资源+放置指令事件，产出放置态实体+邻接修饰器+区域功能状态 ✓。**是系统**。
- **定义**：将实体按空间规则放入世界格/槽位并产生持续功能的系统。
- **M→D→A**：放置合法性/邻接规则/支撑规则表 → 空间规划与基地心智 → 表达/挑战。
- **谱系**：轻=预设槽位放置（塔防塔位，仅合法性检查）→ 中=网格自由放置+邻接加成（模拟经营/农场布局）→ 重=多层结构建造+支撑规则表+蓝图复制（Minecraft；物理坍塌出射程，支撑**规则表**在射程内——边界即用户特别检查所划）→ 极重=可破坏地形+建造经济闭环（拆除返还/维护费）。
- **依赖**：塔防（成立必需）、生存建造（成立必需）、模拟经营（成立必需）、工厂自动化（成立必需）、RTS、大战略（建筑位）、MMO 家园、星露谷类、自走棋（轻档）。
- **特别检查裁定**：塔防的放置与 Minecraft 的建造**是同一系统的轻档与重档**——独占状态同构（格归属表）、规则闭包同族（合法性→功能生效），差异全在档位内容，正是重度谱系该表达的。

### G2 对局赛制（依赖 8 品类）**P0**
- **三测试**：T1 独占"赛程表/局分状态/晋级树" ✓；T2 摘除后沙盒/单局游戏自洽 ✓；T3 消费胜负事件/淘汰事件（由 #31 等产出），产出名次实体+晋级状态+奖励事件 ✓。**是系统**。与 #31 边界清晰：#31 管单目标攻防**过程**并产出胜负，G2 消费胜负组织**多局结构**。与 #34 边界：#34 管跨对局的段位与匹配（meta 层），G2 管一次赛事内的结构（局内-局间层）。
- **定义**：把多个单局胜负组织成局分、轮次、淘汰与名次的对局结构系统。
- **M→D→A**：赛制规则/晋级条件/名次结算表 → 局间张力与翻盘叙事 → 挑战/社交。
- **谱系**：轻=单局胜负+名次结算 → 中=局分制 BO-N+回合换边（格斗/CS）→ 重=多人淘汰晋级树（糖豆人/锦标赛/自走棋 8 人循环）→ 极重=联赛赛季+晋降级+赛程日历（体育经理）。
- **依赖**：格斗（成立必需）、派对（成立必需）、体育竞速（成立必需）、自走棋、大逃杀（名次）、卡牌对战、MOBA、FPS 竞技。

### G3 环境气象（依赖 6 品类）**P1**
- **三测试**：T1 独占"天气状态机/区域环境值表"（#28 独占的是时间轴，两者可互摘）✓；T2 摘除后时钟照走、生产照排 ✓；T3 消费时钟事件/区域事件，产出环境修饰器（雨天火伤-50%）+环境事件（风暴来临）✓。**是系统**。
- **定义**：驱动全局或区域环境状态并向其他系统输出修饰器的系统。
- **M→D→A**：天气转移表/环境阈值/季节日程 → 备灾节奏与季节感 → 幻想/挑战。
- **谱系**：轻=昼夜标签（**此档不必开系统，#28 直接产出即可**——特别检查"世界时钟够不够"的答案：昼夜够、天气不够）→ 中=天气状态机+全局修饰器（星露谷雨天免浇水）→ 重=区域环境值+生存压力（饥荒冬季/缺氧气体）→ 极重=环境改造（玩家反向写环境：温室/梯田/缩圈亦此档变体）。
- **依赖**：生存建造（成立必需）、模拟经营、大战略（消耗/减益）、MMO、开放世界、大逃杀（缩圈）。

### G4 视野侦测（依赖 6 品类）**P1**
- **三测试**：T1 独占"可见性网格+警戒状态机"（感知关系表）✓；T2 摘除后 RTS 全图可见仍自洽 ✓；T3 消费单位位置/光照/噪音事件，产出可见性状态（修饰信息披露）+警觉事件（供 #6 索敌消费）✓。**是系统**。
- **定义**：裁定"谁能感知谁"并把感知结果转为信息披露与警觉状态的系统。
- **M→D→A**：视野半径/迷雾双层规则/侦测公式 → 信息博弈与紧张感 → 挑战/感官。
- **谱系**：轻=视野半径+信息披露门 → 中=战争迷雾（已探索/当前可见双层，RTS/大战略）→ 重=警戒状态机（潜行四态：未觉察→怀疑→警戒→搜索，含光照/噪音输入）→ 极重=双向信息战（隐身/真视/侦查单位/假情报反制）。
- **依赖**：RTS（成立必需）、潜行（成立必需）、MOBA（眼位——§6.3 分解遗漏的实证）、SRPG、大战略、FPS。
- **备注**：迷雾（我方看世界）与警戒（NPC 看玩家）方向相反但同为感知规则闭包，本稿合为一系统两分支档；若波次实作发现状态表无法统一，可拆为两系统，T1 各自成立。

| 模块 | 解锁品类 |
|---|---|
| G1 建造放置 | 塔防、生存建造、模拟经营、工厂自动化（4 个品类的成立必需，另 5 品类增强） |
| G2 对局赛制 | 格斗、派对、体育竞速（3 个成立必需，另 5 品类增强） |
| G5 战术棋盘 | SRPG（成立必需）、自走棋、战棋 Roguelike |
| G8 编队指挥 | RTS、SRPG（成立必需）、自走棋、体育、大战略 |
| G11 计分连击 | 音游（成立必需——#29 判定事件无人消费成分数）、三消、动作、街机 |

**P1（应该有：重要品类的核心件或全品类横切件）——6 个**

| 模块 | 关键理由 |
|---|---|
| G4 视野侦测 | RTS/潜行成立必需；MOBA 现有分解的实证遗漏（§0.2） |
| G7 阵营外交声望 | 大战略成立必需（重档）；MMO/开放世界横切件；§9.2a 预言的"阵营"正式判定 |
| G10 领土版图 | 大战略成立必需；与 G7 同波入库可直接解锁大战略品类 |
| G3 环境气象 | 生存建造成立必需；昼夜留在 #28、天气起开系统的边界已划清 |
| G9 载具坐骑 | 体育竞速品类核心实体；与 #11 边界已论证 |
| G6 新手引导 | 判例 2 勘误件，实现简单（谱系轻），商业上线必需 |
| （附带）R1-R8 修订 | 随 P0 波一并执行，工作量为文档级 |

**P2（可以等：品类窄或非成立必需）——2 个**

| 模块 | 等待理由 |
|---|---|
| G13 物流贸易 | 仅工厂自动化成立必需；大战略可先用轻档路线表凑合（Custom 兜底过渡） |
| G12 难度辅助 | 无品类成立必需；轻档接近参数位，建议等 DDA 需求出现再入库 |

**波次衔接建议**：定稿 §7.1 波 3 首批四模块（装备/背包/掉落/货币）不变；本清单 P0 五件建议编为"量产波 A"（空间与结构族），P1 六件编为"量产波 B"（宏观与横切族）——两波合计 11 模块 + 已登记的 #40，与 37 卡量产合流。**大战略/RTS/SRPG 样板项目开工前，其成立必需件（G1/G4/G5/G7/G8/G10）必须就位**，同 §9.2a 对 #40 的落点纪律。

**射程外事项重申（不进任何波）**：物理堆叠动态、群体涌现模拟（动物园游客/工厂吞吐的涌现层）、操控手感（竞速/格斗帧数据）、netcode、谜题与叙事内容本体——各按 §6.5 留参数位。
