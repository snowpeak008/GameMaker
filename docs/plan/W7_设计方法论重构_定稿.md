## 2. 系统本体模型（采 A §1 全部，B §1 类型落地）

### 2.1 定义与边界三测试

**定义**：一个系统 = 一组机制规则 + 这组规则独占写权限的状态（数据表/状态机）+ 对外的名词端口。系统是"状态所有权 + 规则闭包"的单位，不是功能页签，也不是体验层主题词。

**边界三测试**（两个评定者应同判）：
- **T1 状态所有权**：存在至少一张只有该候选系统能写的数据表或状态集。无独占状态者不是系统。
- **T2 可摘除**：整体摘除候选系统（只删接口边、不改其他系统内部规则），游戏其余部分规则仍自洽。若摘除 X 必然迫使 Y 内部规则改写，则 X、Y 是同一个系统。
- **T3 名词转换**：至少消费一个名词并产出/修饰至少一个名词。只存数据不转换名词的是数据资产，不是系统。

**判例 1（简报 Q1 原题）**：装备/宠物/背包是三个系统。三者各有独占状态（T1）、互相可摘除（T2）、各有独立名词转换（T3）。"成长"是 Dynamics 层聚类标签，无状态所有权，**禁止用 D 层词汇给系统命名**。
**判例 2**："手感系统"不是系统（T1 不过，它是战斗/移动系统 L4 参数的品质属性）；"新手引导"是系统（引导进度表独占、消费首次行为事件、产出 UI 修饰器）。

### 2.2 接口规范：四类名词 × 三类端口

| 名词类 | 定义 | 判定 | 例 |
|---|---|---|---|
| 资源 resource | 可计数、可增减、可转移的量 | 有余额语义 | 金币、体力、能量、行动点 |
| 实体 entity | 有属性表的对象实例 | 有行标识 + 属性列 | 一件装备、一张卡、一个敌人 |
| 事件 event | 时点信号，带载荷 | 有发生时刻，无余额 | 击杀、升级、波次结束 |
| 修饰器 modifier | 作用于其他系统属性或规则的持续效果 | 有作用目标 + 生效期 + 叠加序 | 套装加成、遗物、buff |

端口三类：**provides / consumes / modifies**。一条接口边 = （源系统, 端口, 名词, 目标系统）；系统实例图 = 系统为节点、接口边为边的有向图，是 §4 组合校验器的唯一输入。

**接口完整性判定**（A §1.2 + B 校验器 V6 悬空消费，堵住审计 B"探针列静默放行"）：遍历系统全部 L4 机制的 `effects_template`，凡引用非本系统所有的实体/资源/属性必须存在对应接口边，无边即校验失败；`consumes ∪ modifies` 中每个名词必须在绑定表有映射且映射目标被某实例 provides 或属 pack 核心，悬空 → 加载失败。

**类型落点（B §1.2）**：名词落为 `NounDecl`，`NounKind` 五分（Resource / EntityClass / Property{of} / Signal / RuleSlot——RuleSlot 是允许他系统 `ModifyRule` 作用的规则挂点）；端口落为 `SystemInterface { provides, consumes, modifies: Vec<NounId> }`。

### 2.3 MDA 三层映射（采 A §1.3，按裁决 12 修订）

每个系统模块强制填三层：
- **M（Mechanics）**：本系统的 L4 决策点列表——即现有 pack 窄链，原样保留。
- **D（Dynamics）**：预期运行时动态，用"谓词 + 可观测信号"书写、禁止形容词。**按红队裁决 12，D 层降为文档纪律**（写作规范 + 红队人工审），不进机器校验——谓词的可观测性不可静态判定，假装机检会制造覆盖假象。
- **A（Aesthetics）**：MDA 八分类限选 ≤2 主项。机检保留：所有 core 系统 A 主项并集 = 玩法美感承诺；某 core 系统 A 主项与承诺完全不相交 → 警告（不 block）。

## 3. 重度模型（A 五维与双谱系 + B 局部 ladder，按红队裁决 1/2 与指令 4/5 修订）

### 3.1 重度三件套（红队 §3.1 修正方案）

重度 = **声明档 × 五维标定 × 测得向量**，三者分工：

1. **声明档（tier）**——设计师的意图输入，模块局部有序阶梯（`HeavinessLadder`，档数与命名由模块作者定：装备 4 档、音游判定 2 档均合法）。它决定激活哪些决策点（§5.2）。**每档定义必须标注 A 五维分与全局档带**，跨模块比较走全局档带；**B 的 `heavy_rank_threshold` 废除**（跨模块 rank 不可比，红队已证为坏类型），重核判定一律用全局档带 W≥9。
2. **五维标定**——档位定义的内容标准（下表），是"该档该放什么"的设计学承诺。
3. **测得向量**——编译期从冻结集确定性计算，**仅作审计证据**：声明档与测得档漂移 ≥1 档 → gate2 警告（不 block），不参与任何预算校验。理由（红队裁决 2）：测得分在创作早期恒 ≈0（点还没答），预算要在组合期指导设计，测得分冻结期才有——时序上不成立。

### 3.2 五维量表（采 A §2.1，按指令 5 修订两处）

W(S) = M + D + C + P + O，五维各 0-3，总分 0-15。**全局档带：轻 0-4 / 中 5-8 / 重 9-12 / 极重 13-15**。

| 维 | 名称 | 数什么 | 0 档 | 1 档 | 2 档 | 3 档 |
|---|---|---|---|---|---|---|
| M | 机制深度 | 系统内 L4 级独立机制规则数 | ≤1 | 2-3 | 4-6 | ≥7 |
| D | 数据深度 | 系统独占数据结构数（表/矩阵/曲线/图各算 1） | ≤1 张简单表 | 2-3 | 4-6 或含矩阵 | ≥7 或含图/嵌套 |
| C | 耦合宽度 | 以本系统为端点的接口边数（**三端口全口径**：provides 被消费 + consumes + modifies，裁决 10） | ≤1 | 2-3 | 4-6 | ≥7 |
| P | 决策形态 | 玩家决策结构四选一 | 无决策 | 偶发一次性选择 | 会话级重复决策 | 构筑级组合决策 |
| O | 内容供给 | 系统所有表行数合计量级 | ≤10 | 11-100 | 101-1000 | >1000 或持续运营供给 |

**修订一（指令 5）：C 维在谱系标定中改为"接口边下限"**。C 是组合相对量（同一装备 E2 在幸存者组合 C=2、在 MMO 组合 C=6），谱系档位写 C≥n 下限，实例图上实测；声明与实测漂移 ≥1 档 → gate2 警告不 block。这消解了 A 标定表与量表定义的自相矛盾。
**修订二（指令 5）：每档定义必须写死 P 维下限**。声明 E2 档即承诺 P=3（构筑级决策）——把心智负担从测量问题转为档位定义问题。P 是唯一含判断的维度，消歧问句序（A §2.1）：选择互相组合出新价值？→3；每会话重复面对？→2；选完长期不碰？→1；无选项？→0。争议时唯一裁决问句："选择空间是否相乘"。

M/D/O 为纯计数，两人同分；C 按实例图数边。**五维等权是初标定（无回归数据），10 款标定回归（§7 波 5 前置）后调权。**

### 3.3 测得向量扩维（指令 4，与五维一一对应）

| 五维 | 测得代理（`MeasuredWeight` 扩维后） |

## 4. 组合规则（按指令 1/3/4/6/9/12：删形态枚举，连通性 + 预算单轨 + 传导析取）

### 4.1 核心循环与关联强度 κ（采 A §3.1，按裁决 9 修订）

**L2 新增必填决策点 `core_loop`**：最小可玩闭环的动词序列（如幸存者"移动→自动攻击→拾取经验→三选一升级→移动"），每个动词绑定到一个系统实例。**创作顺序纪律（指令 9）**：core_loop 动词绑定允许引用"待实例化系统占位"，L3 实例化后回填校验——否则 L2 先于 L3 的分层顺序死锁。

**κ(S) ∈ {core, strong, weak, meta}**（采 A 四级，裁决 9；B 的 `CoreLink` 枚举改四值），按序取首个命中：

| κ | 判定（纯结构判据，机器可判） | 预算权重 |
|---|---|---|
| core | 系统机制出现在 core_loop 动词序列内 | 1.0 |
| strong | provides 核心循环消费的名词，或 modifies core 系统属性 | 0.75 |
| weak | 可绕开或影响间接（摘除后核心循环仍完整转动） | 0.5 |
| meta | 只在局外生效 | 0.25 |

**按红队裁决 9，A 原 strong 判据中"且每局必然触达"一句删除**——它需要运行时知识、不可机检；删除后 κ 全部可由接口边机器判定，"纯计数无自由裁量"的声称才成立。

### 4.2 R-C1′ 重核连通性规则（红队 §3.2 替代方案，替代 A 的 F0-F3 形态枚举）

**A §3.2 形态枚举 F0-F3 作为校验依据删除**（A 在自证阶段为它打了三次补丁——§4.3"F3+ 修饰器伴生"、§4.6 改 F1 定义、§4.7 发明 F4——枚举的是结果形状，而用户愿景说的是生成原则）。F0-F3 命名保留为**报告层描述标签**（校验器输出"当前组合呈 F3 双核形态"），不再是校验依据。A §4.3/§4.6/§4.7 三处例外条款随之删除。

**R-C1′**：设 H = {W≥9 且 κ∈{core, strong} 的系统实例}，三查：
- **(a) 连通**：H 的诱导子图必须连通；
- **(b) 强耦合**：H 中每个节点与 H 内其他节点的接口边合计 ≥2（原 F3"强耦合证明"的一般化）；
- **(c) 数量参考线（用户裁决 2026-09-03 改制：提示义务，非设计义务）**：|H| 对照 L0 档位**参考线**（超休闲 0 / 休闲 1 / 中核 2 / 重核 3 / MMO 4）。**超线不 block**——超大玩法（EU4 型、大战略+MMO 混合型…）是稀有但正当的设计，档位枚举会无穷倒退（每种混合都要新档），故一律改为：
  1. 超线 → **提示 + 一次性形态确认**：系统列出全部重核及其分值，用户署名确认"我知道并接受这是 |H|=N 的超大玩法"（R3 留痕，等价于用户自行接管总体形态设计）；
  2. 确认后，**AI 的设计义务转向**：不再劝减总体形态，转为**逐重核系统的轻重需求访谈**——每个重核系统逐一确认档位与理由（"外交你要 EU4 级还是文明级？为什么？"），这是用户裁决原话"将玩家定位的某个系统是轻度还是重度的需求理清，会更重要"的落地（§9.2b 概念访谈相应扩展：识别到 |H|>4 时自动切入此模式）；
  3. R-C2 预算在形态确认后同样降为**提示**（逐系统分值表照出，供用户自查"最贵的系统"）——主开发按裁决意图延伸，超大形态下预算硬线与 |H| 硬线同理不成立；
  4. **(a) 连通、(b) 强耦合保持硬 block 且不可豁免**——它们防的是"两个游戏钉在一起"的结构缺陷，与玩法大小无关；附录《极端组合形态测试》的双连通（无割点）守卫降为**提示级**（检出货币桥式钉接时提醒，不拦）。
  原"大战略档 |H|≤10"方案（附录修正案 1）**作废**——被本制度取代。

**红队验证过的四案例判定**（无例外条款下全部正确）：

| 案例 | H 与判定 |
|---|---|
| 杀戮尖塔 | H={局内构筑, 回合战斗, 遗物}；遗物 modifies 战斗+构筑、构筑↔战斗双边 → 连通 ✓、每节点 H 内边 ≥2 ✓；\|H\|=3 > 中核上限 2 → L0 须声明重核档（≤3）→ **通过且语义正确**（其设计负担确实是重核级） |

### 4.3 R-C2 重度预算（单轨制，裁决 2）

B(G) = Σ W(S) × weight(κ)，**W 一律取声明档映射的全局五维分**（含 κ 四级权重 1.0/0.75/0.5/0.25）。测得分**不参与预算校验**，仅出漂移警告（§3.1）。

**A §3.3 的预算表数值作废**（拍脑袋 + 星露谷误判实证：B(G)=42.5 超中核档 38，一人游戏被判重核）。预算数值按 B §3.2 的 `CompositionBudget` 数据文件形态存放。**标定已定稿（用户签字 2026-09-06，报告 `docs/memory/w7_wave5/5-0_标定报告.md`）**：五档 B(G) 上限 = 超休闲 **12** / 休闲 **28** / 中核 **42** / 重核 **55** / MMO **68**（11 款样本回归，散点零倒挂；五维等权与档带 4/8/12 一并定稿维持）。预算刻度语义 = 设计复杂度（问题 2 裁决复核维持）。报告按 weight×W 降序列出"最贵的系统"，指向减重度档而非删系统（降重操作 = 装备从 E4 调回 E2）。

**超预算处置（用户裁决 2026-09-06，永久制度）**：超预算**不 block、不新增档位**——一律提示 + 一次性署名形态确认（与 §4.2(c) 的 |H| 改制同一制度）。用户原话："很有可能出现更大更复杂的，所以我们没必要限制了，这些超限制的都不做限制。"故五档为**参考线上界**而非硬墙：B(G) > 68 的组合（EU4 型 84、大战略+MMO 混合型等）照常提示并走署名确认，**附录《极端组合形态测试》修正案 1/3 的"大战略档 95-105"方案正式作废**（新增档位会随玩法规模无穷倒退）。五维权重与档带的调整走"后台标记、积累实例后再议"的记录制，不因单例改公式。

### 4.4 R-C3 重度传导（采 B 档位级 Induction 为 v1 实现，裁决 4 + 指令 6）

传导走接口边，不是玄学感应。实现载体：`HeavinessTier.inductions: Vec<Induction>`——本模块处于本档（含以上）时对其他系统的最低档位要求，附 reason 进 finding 文案。**A 的维度级要求（如"背包.D≥1 分类"）转写进目标模块的档位定义内容**（背包 medium 档定义即含分类规则）。

**双方共同缺陷已按裁决 4 修复：传导目标支持名词析取**——`Induction.target: ModuleId | NounProvided(NounId)`。否则"装备 heavy 强制点名 sys.economy"会对无经济系统但有掉落回收的游戏误报 V1。A §3.4 装备传导表按新目标形态转写：

|---|---|---|
| E1 | `ModuleId(sys.loot) ≥ 含品质/词条权重档` | 词条从哪来必须有规则（"掉落表含权重列"写进 sys.loot 该档定义） |

## 5. 类型系统与编译链（采 B 修正版）

### 5.1 SystemModule 与决策点归属

### 5.2 档位激活：tier 合成决策点复用 unlocks（裁决 6）

**B 的一处漏答已按指令 7 修复（A 需求 8 的欠账）**：`ModifyRule` 与 `Attach` 补**叠加序字段** `priority: i32`；同目标多修饰器按 priority 结算，同序冲突用确定性 tie-break（按机制 id 字典序）；C4 将叠加序渲染进 GWT。杀戮尖塔遗物结算顺序敏感（力量类与乘算类先后不同结果不同），波 5 样板以此验收。

### 5.4 Graph / Curve 参数（采 B §4.2，按指令 10 修订默认值）

`ParameterSchema`/`ParameterValues` 各加 Graph、Curve 两个 tag 分支（旧 tag 不动）。GraphSchema：节点/边负载（复用 ScalarField，含 is_skin）、directed、acyclic、entry 约束、节点基数键；校验：边端点必须是已声明节点、acyclic 声明则拓扑检查、节点数进基数期望。GameSpec 新增 `graphs: Vec<GraphSpec>`（serde default），`contains_ref`/`all_ref_paths` 增加 graphs 分支（R4 锚定闭合）；Curve 不加新 section，编译成两列 TableSpec + 插值注记，复用既有表通路。

**指令 10：对话/图类模块默认 `acyclic=false`**（极乐迪斯科对话大量回环 hub，A"对话树"是口误），仅天赋树/肉鸽地图类显式声明 true。

**Curve 已知宽度缺陷（红队 §2.3 记 B 小过，如实保留）**：CurveSchema 是单值 y=f(x)，CS2 后坐力的每发 (dx,dy) 二维偏移序列装不下，需退化为三列 Table（shot_index/dx/dy）——表达位仍有，语义降级如实声明；"音游谱面=Curve"同理需逐案核。

### 5.5 design_notes：rationale 进编译链（采 B §5.1）

`DesignNote { source_decision, source_option, role: Rationale|Statement, text }`，SystemSpec/MechanicSpec/TableSpec/GraphSpec/ContentSpec 各加 `design_notes: Vec<DesignNote>`（serde default）。C0 编译每个 spec 元素时装入该选择的非空 rationale 与 statement 类自由文本；C2 的 `source_text` 追加注记（修复审计 B"变异器设计全在理由里但不进 AI 上下文"）；C4 契约携带并渲染进"设计意图"小节。**纪律：注记只被携带与展示，永不被编译成结构**——GWT 仍只从结构化字段派生，保 I1。

### 5.6 custom 入口与纪律（裁决 7/8/11 + 指令 8，全采 B）
