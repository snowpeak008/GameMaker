## T-G4a-1 · 可玩切片 / 运行时清单 / 引擎指南骨架 / 开发轮次记录

【必读】`docs/plan/03_工程规范.md` 全文；`docs/plan/09` §1-3（生产模型、切片、薄运行时+指南+durable docs）；`docs/plan/10` §1（插件架构）；`crates/adm4-build/src/program/derive.rs`（既有派生风格、`CoverageGap` 用法）；`crates/adm4-build/src/governance/program_line.rs`（`ProgramContract` 字段事实）；`crates/adm4-spec/src/model.rs`（`GameSpec`/`SpecRef`）；`crates/adm4-build/src/registry.rs`（`ArtifactKind::{PlayableSlice, RuntimeManifest, EngineGuide, DevRoundLog}` 已声明）。

【可写】仅 `crates/adm4-build/src/program/slice.rs`、`manifest.rs`、`engine_guide.rs`、`dev_round.rs`（新建）与 `program/mod.rs`（只加 `pub mod` 行）。**不得改** `derive.rs`、`executors.rs`、`runner.rs`、`lib.rs`、`engine/**`。

【任务】
1. `slice.rs`：`PlayableSlice { core_loop, primary_input: Vec, player_feedback: Vec, scene, success_or_fail_state, excluded_scope: Vec, anchors: Vec<SpecRef> }` + `RiskSlicePlan { items: Vec<RiskSliceItem { risk: RiskKind(手感|画面|技术|资产), description, verify_by: VerifyMethod(命令|截图|视频), anchors } > }`。确定性抽取函数 `extract_playable_slice(&GameSpec, &ProgramContract) -> Adm4Result<SliceExtraction { slice, risk_plan, gaps: Vec<CoverageGap> }>`：只映射不发明；不超过 1 主场景 / 1 主操作 / 1 成败反馈（超出即 `Err` 点名多出的候选）；每个风险必须有验证方式；抽不出核心循环/主操作/成败状态 → `Err(Adm4Error::blocked(..))` 说明缺哪条事实。提供 `PlayableSlice::validate()` 复用同一套检查。
2. `manifest.rs`：`RuntimeManifest { goal, durable_files: Vec<String>, engine_guide_ref, proof_requirements: Vec<String>, repair_loop: Vec<String>, slice_ref, anchors }` + `render_runtime_manifest(&PlayableSlice, &RiskSlicePlan) -> RuntimeManifest` 与 `RuntimeManifest::to_markdown()`（极短，一页内；Markdown 不得带契约里没有的事实）。
3. `engine_guide.rs`：**引擎无关骨架**——`EngineGuide { engine_id, sections: Vec<GuideSection { title, pitfalls: Vec, commands: Vec<GuideCommand { purpose, command }> }> }` + `EngineGuideSource` trait（`fn engine_id(&self) -> &str; fn guide(&self) -> Adm4Result<EngineGuide>`）+ `NotProvidedGuide`（如实报"本引擎指南未提供，归后置波次"）。**不得**内置任何具体引擎内容。
4. `dev_round.rs`：`DevRoundLog { rounds: Vec<DevRound { index, started_at, finished_at, commands: Vec, failures: Vec, repair_summary, status: RoundStatus(进行中|成功|失败|中止) }>, durable: DurableDocs { plan_md, structure_md, assets_md, proof_md } }` + `DevRoundLog::append_round`、`load`/`save`（JSON，落到调用方给的目录，用 `adm4_foundation` 的原子写）+ `render_durable_docs(&PlayableSlice, &RuntimeManifest) -> DurableDocs`（四份 `PLAYABLE_*.md` 初稿，只含契约事实）。可停可续：`load` 缺文件 = 空日志，字段缺失按 serde default。

【验收标准】
- a. 切片抽取对同一输入逐字节确定性（两次调用 serde 输出相等）；
- b. 缺核心循环/主操作/成败状态三者任一 → `Err`，消息点名缺哪条；多于 1 主场景 → `Err` 点名候选；
- c. 每个 `RiskSliceItem` 必有 `verify_by`，`validate()` 拦空值；
- d. 清单 Markdown 与契约字段一一对应（测试：Markdown 中每个非空事实都能在契约里找到）；
- e. `EngineGuide` serde 往返 + 旧档兼容（缺键可读）；`NotProvidedGuide` 返回 `Err` 且消息说明归属；
- f. `DevRoundLog` 落盘/加载往返；`append_round` 索引递增；缺文件加载为空；
- g. 全部新增公共类型有中文 doc；库代码无 unwrap/expect/panic；`rg -i unity` 零命中；
- h. 门禁全绿；本 crate 新增测试 ≥ 12。

【自验收】`cd V4; cargo fmt --check; cargo clippy -p adm4-build --all-targets; cargo test -p adm4-build; cargo test --workspace; rg -i unity crates/adm4-build/src/program`（应无输出）。

【报告】四段式（改动清单 / 逐条验收自评 / 测试证据含数字 / 遗留与声明），中文，只陈述事实。特别注明：暴露给 T-G4a-3 的公共 API 签名清单。

## T-G4a-2 · EngineBackend 全接口 + 引擎工程种子 + 通用 MCP stdio 协议层 + Mock 后端

【必读】`docs/plan/03_工程规范.md` 全文；`docs/plan/09` §4（EngineBackend 接口原型）与 §5.1（ProofBundle 结构）；`docs/plan/10` §1（接缝层）与 §4 第 1 条（接缝纪律）；`crates/adm4-build/src/engine/mod.rs`（现有 `EngineBackend`/`EnginePreflight`/`NotConfiguredBackend`，**只增不改既有签名**）；`crates/adm4-ai/src/http.rs` 与 `provider.rs`（既有 I/O 与 trait 风格）；`crates/adm4-foundation/src/error.rs`（`Adm4Error` 构造器）。

【可写】仅 `crates/adm4-build/src/engine/**`（`mod.rs` 可改、新建 `types.rs`、`mock.rs`、`mcp/{mod,jsonrpc,transport,client}.rs`）。**不得改** `program/**`、`executors.rs`、`runner.rs`、`lib.rs`、`Cargo.toml`（不许加依赖；JSON 用 workspace 既有 serde_json）。

【任务】
1. `types.rs` 引擎无关契约：`EngineProjectSeed { engine_id, project_dir_name, seed_kind, required_tools: Vec, notes, anchors }`（这是 P0 契约 `engine_seed` 要落的真种子；`engine_id` 只是字符串标识，不得写死任何引擎名）；`SliceTask { slice_ref, round_index, objective, constraints: Vec }`；`DevContext { project_dir, manifest_path, guide_path, durable_dir }`；`DevRound`（与 T-G4a-1 的轮次记录对齐：`index/commands/failures/repair_summary/status`——**本卡自定义一份，字段名按上述保持一致**，T-G4a-3 负责合流）；`RunResult { launched: bool, duration_ms, log_path, exit_detail }`；`ProofBundle { build_log, run_log, screenshots: Vec, video: Option, captured_at, capture_detail }`。全部 serde default。
2. `mod.rs` 扩展 `EngineBackend`（**保留** `id()`/`preflight()` 原签名）：新增 `open_or_create_project(&self, seed: &EngineProjectSeed, dir: &Path) -> Adm4Result<()>`、`agent_develop(&self, task: &SliceTask, ctx: &DevContext) -> Adm4Result<DevRound>`、`run_playmode(&self, project: &Path) -> Adm4Result<RunResult>`、`capture_proof(&self, project: &Path) -> Adm4Result<ProofBundle>`。`NotConfiguredBackend` 四个新方法全部返回 `Err(Adm4Error::blocked(..))` 带原因（R7）。
3. `mcp/`：**通用 MCP stdio 客户端协议层，零引擎语义**。
   - `jsonrpc.rs`：JSON-RPC 2.0 请求/响应/错误/通知类型 + 编解码；id 递增。
   - `transport.rs`：`McpTransport` trait（`send(&mut self, frame: &str) -> Adm4Result<()>; recv(&mut self) -> Adm4Result<String>`）+ 两个实现：`StdioTransport`（按 MCP stdio 规范一行一帧 `\n` 分隔，包装 `std::process::Child` 的 stdin/stdout，**仅构造不自动 spawn**，提供 `spawn(program, args, cwd)`）与 `ScriptedTransport`（测试用：预置应答序列，记录发出的帧；应答用完再 recv → `Err`）。
   - `client.rs`：`McpClient<T: McpTransport>`：`initialize(client_info) -> InitializeResult`、`list_tools() -> Vec<McpToolInfo { name, description, input_schema }>`、`call_tool(name, arguments: serde_json::Value) -> McpToolResult { content: Vec<Value>, is_error }`。服务端返回 JSON-RPC error 或 `is_error=true` → `Err`，消息带工具名与原始错误（R7 不吞）。协议版本作为常量暴露；未 initialize 就 call → `Err`。
4. `mock.rs`：`MockEngineBackend`——确定性回放：构造时给 `preflight_ready: bool`、`rounds: Vec<DevRound>`、`run: RunResult`、`proof: ProofBundle`，`open_or_create_project` 在给定目录真实创建 `project_dir_name` 子目录并写一份 `seed.json`；记录全部调用（`calls()` 供断言）；`agent_develop` 按 round_index 取回放，越界 → `Err`。

【验收标准】
- a. 既有两测试不改、仍绿；`NotConfiguredBackend` 四新方法均 `Err` 且消息非空；
- b. 全部新类型 serde 往返 + 缺键可读；
- c. `McpClient` 用 `ScriptedTransport` 跑通 initialize → list_tools → call_tool 全链，并断言发出的帧是合法 JSON-RPC 2.0（含递增 id）；
- d. 服务端 error 对象 / `is_error=true` / 未 initialize 三种失败路径均 `Err` 且不被吞；
- e. `StdioTransport` 帧分割正确（用内存 `Cursor` 实现的 Read/Write 测，**不 spawn 真实进程**）；
- f. `MockEngineBackend` 回放确定性、调用记录完整、目录真实创建、越界 `Err`；
- g. `rg -i unity crates/adm4-build/src/engine` 零命中；无 unwrap/expect/panic（测试除外）；无新依赖；
- h. 门禁全绿；本 crate 新增测试 ≥ 15。

【自验收】`cd V4; cargo fmt --check; cargo clippy -p adm4-build --all-targets; cargo test -p adm4-build; cargo test --workspace; rg -i unity crates/adm4-build/src/engine`。

【报告】四段式。特别注明：`EngineBackend` 完整 trait 签名、`EngineProjectSeed` 字段、`MockEngineBackend` 构造方式（T-G4a-3 接线依据）。

【主开发裁决 2026-09-02（e2e 暴露）】`lane_defense` 全链夹具经 P0 派生出 3 个 `Command` 型能力，切片抽取器按"1 主操作"硬规则报 `validation` 错，被 runner 映成 `Failed`。裁决如下，**禁止改 `pack.json`/既有夹具数据凑数**：
1. "候选多于 1"是**设计侧未收敛**的事实，属 R2 "未知即停"范畴，不是程序错误：`slice.rs::exactly_one` 的多候选分支改为 `Adm4Error::blocked`（消息不变，仍点名全部候选），P1 因此落 `Blocked` 而非 `Failed`。此项**破例允许 T-G4a-3 收尾者改 `program/slice.rs` 这一处**（一行错误类别 + 对应单测断言 `kind == Blocked`）。
2. e2e 夹具中的 P1 三条用例（Mock 成功链 / 预检未就绪 / 未配引擎）需要一个**恰好 1 主操作**的 spec：**不改 lane_defense 夹具**，改为在 e2e 内用 `adm4_build::program::slice::test_fixtures` 同口径自建最小 `GameSpec` + C3/C4 产物写入产物仓，或直接以 `P1Executor` + 内存 `ArtifactStore` 做集成测试（放在 `adm4-build` 或 e2e 均可）。"预检未就绪 → Blocked 且 detail 透传、不跑 agent_develop"与"未配引擎 → Blocked 含 NotConfigured"两条**必须**在切片可抽出的前提下验证，否则验证的是切片阻塞而不是后端门控。
3. 既有 e2e `asset_production_line_runs_p0_and_p2_end_to_end` 里 P1 断言改为 `Blocked`（原因是"3 个主操作候选"，属设计收敛问题）并在断言注释里写明；P2 单段照跑不受影响。
4. 冒烟脚本 `build run --from P0 --to P1 --mock-engine` 对 lane_defense 项目**预期 P1 Blocked（候选未收敛）且退出码按既有 `build run` 对 Blocked 的约定**；断言输出含"主操作"与三个候选 id，作为 R2 阻断的冒烟证据；`build p1-status` 对 Blocked 的 P1 也要能给出摘要（含 blocked 提示）。
