# V4 工程规范

> 状态：已定稿（2026-08-29）。对所有开发者（含子 agent）强制生效。违反任何"必须/禁止"条款的产出不予验收。

---

## 1. 工具链与仓库边界

- Rust 1.96.0（`rust-toolchain.toml` 锁定），edition 2024，目标 `x86_64-pc-windows-msvc`。
- 一切开发只发生在 `V4/` 内。**禁止**读取依赖、复制粘贴 `RUST/`、`NEWrust/`、根 Python 代码——它们只是历史参考。
- **禁止** git 提交/推送（由主开发统一处理）；**禁止**修改 `V4/docs/design/**` 与 `V4/docs/plan/**`（发现设计问题写进任务报告）。
- 新增第三方依赖必须先在任务报告说明理由；优先复用 workspace 既有依赖（serde/serde_json/sha2/reqwest/slint）。

## 2. 代码规范

- `cargo fmt` 无 diff；`cargo clippy --workspace --all-targets` 零警告（不得用 `#[allow]` 压警告，除非任务卡明确批准）。
- workspace 级 `unsafe_code = forbid`（`adm4-desktop` 因 Slint 生成码降为 `deny`，手写代码同样禁 unsafe）。
- 库代码**禁止** `unwrap`/`expect`/`panic!`（测试代码除外）；错误一律走 `Adm4Error`/`Adm4Result`，错误消息用中文、带上下文。
- **禁止** `unwrap_or`/`unwrap_or_default` 在派生与编译路径上吞错兜底（R2/R7）；缺数据必须返回错误。
- 公共类型与方法写中文 doc 注释，说明"为什么"而不是复述代码。
- serde：既有结构的字段名/大小写不得更改（存档兼容）；新结构与所在 crate 既有风格一致（snake_case）。
- 命名：crate 一律 `adm4-*`；id 类字符串用 `snake_case`；决策点 id 形如 `<domain>_<name>`。

## 3. 测试规范

- 每个新增公共行为必须有单元测试；跨 crate 链路进 `adm4-app/tests/end_to_end.rs`。
- 测试必须确定性：AI 一律用 `adm4_ai::ScriptedProvider`；**禁止**真实网络、真实 API key、用户目录。
- 临时目录用 `std::env::temp_dir()` + 唯一子目录，测试自清理。
- **禁止**为了变绿修改/删除/`#[ignore]` 既有测试。既有测试失败 = 你的实现有问题；确属测试本身的 bug，须在报告中给出证据，由主开发裁决。
- 已有决策点/选项/阶段 id 只增不改不删（e2e 与存档锚定）。

## 4. 数据规范（design_space）

- 结构以 `adm4-space` 校验器为准；硬验收：`cargo run -p adm4-cli -- space validate` 全绿。
- 每个决策点：`question` 中文、`options` ≥ 2（或 Table/Matrix 结构点 ≥ 1 加自定义位）、L4 机制点必须带 `effects_template` + `compiler_tags`。
- L5 点 `parameter_schema` 定义表/矩阵结构；L6 点承载行数据期望，配 `cardinality_expectations`。
- `reference_games` ≥ 3；参考游戏名只许出现在 `reference_games` 字段与换皮词表，正文出现即违反 R5。

## 5. 红线检查清单（R1-R7，验收时逐条过）

| 红线 | 机器化要求 |
|------|-----------|
| R1 指标必须带证据 | 报告类型只接受 `MeasuredMetric`，禁止裸数字 |
| R2 未知即停 | 派生用 `Derive<T>`，缺输入返回 Err，禁止默认值兜底 |
| R3 评审工作量证明 | 人工/红队门必须落 `ReviewProof` |
| R4 AI 叙述必须锚定 | 叙述类产物用 `AnchoredNarrative`，无锚即 Err |
| R5 换皮扫描 | 落盘钩子过 `SkinScanner`；词表由认证流程自动登记 |
| R6 基数申报 | 内容类产物带 `CardinalityDeclaration` 并与实际对账 |
| R7 禁止 AI 失败兜底 | AI 错误直接上抛，禁止模板兜底/静默重试成功 |

## 6. 自验收命令（任务完成的最低门槛）

```powershell
cd V4
cargo fmt --check
cargo clippy -p <本任务crate> --all-targets   # 零警告
cargo test -p <本任务crate>                    # 全绿
cargo test --workspace                         # 全绿（确认未破坏他人）
# 数据任务追加：
cargo run -p adm4-cli -- space validate
```

## 7. 任务报告格式（子 agent 完成时必交）

1. **改动清单**：新增/修改文件与一句话说明。
2. **设计符合性**：对照任务卡逐条验收标准自评（通过/未通过+原因）。
3. **测试证据**：自验收命令的实际输出摘要（测试数、警告数）。
4. **遗留与声明**：未做的事、对其他 crate 的新 API 需求、发现的既有 bug。
