# V4 工程规范

> 状态：已定稿（2026-08-29）。对所有开发者（含子 agent）强制生效。违反任何"必须/禁止"条款的产出不予验收。

---

## 1. 工具链与仓库边界

- Rust 1.96.0（`rust-toolchain.toml` 锁定），edition 2024，目标 `x86_64-pc-windows-msvc`。
- 一切开发只发生在 `V4/` 内。**禁止**读取依赖、复制粘贴 `RUST/`、`NEWrust/`、根 Python 代码——它们只是历史参考。
- **禁止** git 提交/推送（由主开发统一处理）；**禁止**修改 `V4/docs/design/**` 与 `V4/docs/plan/**`（发现设计问题写进任务报告）。
- 新增第三方依赖必须先在任务报告说明理由；优先复用 workspace 既有依赖（serde/serde_json/sha2/reqwest/slint）。

## 2. 代码规范

- `cargo fmt` 无 diff；`cargo clippy --workspace --all-targets` 零警告（不得用 `#[allow]` 压警告，除非任务卡明确批准）。
- workspace 级 `unsafe_code = forbid`（`adm4-desktop` 因 Slint 生成码降为 `deny`，手写代码同样禁 unsafe）。
- 库代码**禁止** `unwrap`/`expect`/`panic!`（测试代码除外）；错误一律走 `Adm4Error`/`Adm4Result`，错误消息用中文、带上下文。
- **禁止** `unwrap_or`/`unwrap_or_default` 在派生与编译路径上吞错兜底（R2/R7）；缺数据必须返回错误。
- 公共类型与方法写中文 doc 注释，说明"为什么"而不是复述代码。
- serde：既有结构的字段名/大小写不得更改（存档兼容）；新结构与所在 crate 既有风格一致（snake_case）。
- 命名：crate 一律 `adm4-*`；id 类字符串用 `snake_case`；决策点 id 形如 `<domain>_<name>`。

## 3. 测试规范

- 每个新增公共行为必须有单元测试；跨 crate 链路进 `adm4-app/tests/end_to_end.rs`。
- 测试必须确定性：AI 一律用 `adm4_ai::ScriptedProvider`；**禁止**真实网络、真实 API key、用户目录。
- 临时目录用 `std::env::temp_dir()` + 唯一子目录，测试自清理。
- **禁止**为了变绿修改/删除/`#[ignore]` 既有测试。既有测试失败 = 你的实现有问题；确属测试本身的 bug，须在报告中给出证据，由主开发裁决。
- 已有决策点/选项/阶段 id 只增不改不删（e2e 与存档锚定）。

## 4. 数据规范（design_space）

- 结构以 `adm4-space` 校验器为准；硬验收：`cargo run -p adm4-cli -- space validate` 全绿。
- 每个决策点：`question` 中文、`options` ≥ 2（或 Table/Matrix 结构点 ≥ 1 加自定义位）、L4 机制点必须带 `effects_template` + `compiler_tags`。
- L5 点 `parameter_schema` 定义表/矩阵结构；L6 点承载行数据期望，配 `cardinality_expectations`。
- `reference_games` ≥ 3；参考游戏名只许出现在 `reference_games` 字段与换皮词表，正文出现即违反 R5。

## 5. 红线检查清单（R1-R7，验收时逐条过）

| 红线 | 机器化要求 |
|------|-----------|
| R1 指标必须带证据 | 报告类型只接受 `MeasuredMetric`，禁止裸数字 |
| R2 未知即停 | 派生用 `Derive<T>`，缺输入返回 Err，禁止默认值兜底 |
| R3 评审工作量证明 | 人工/红队门必须落 `ReviewProof` |
| R4 AI 叙述必须锚定 | 叙述类产物用 `AnchoredNarrative`，无锚即 Err |
| R5 换皮扫描 | 落盘钩子过 `SkinScanner`；词表由认证流程自动登记 |
| R6 基数申报 | 内容类产物带 `CardinalityDeclaration` 并与实际对账 |
| R7 禁止 AI 失败兜底 | AI 错误直接上抛，禁止模板兜底/静默重试成功 |

## 6. 自验收命令（任务完成的最低门槛）

```powershell
cd V4
cargo fmt --check
cargo clippy -p <本任务crate> --all-targets   # 零警告
cargo test -p <本任务crate>                    # 全绿
cargo test --workspace                         # 全绿（确认未破坏他人）
# 数据任务追加：
cargo run -p adm4-cli -- space validate
```

## 7. 任务报告格式（子 agent 完成时必交）

1. **改动清单**：新增/修改文件与一句话说明。
2. **设计符合性**：对照任务卡逐条验收标准自评（通过/未通过+原因）。
3. **测试证据**：自验收命令的实际输出摘要（测试数、警告数）。
4. **遗留与声明**：未做的事、对其他 crate 的新 API 需求、发现的既有 bug。

## 8. W7 增补节（2026-09-06 波 6 定型，与前七节同等强制力）

> 来源：W7 六波（v1.0.8-v1.0.14 区间）实证的工程事实与纪律，出处见各条括注。适用于所有后续开发者（含子 agent 与主开发）。

### 8.1 断线接力纪律

- 每张任务卡强制含**断点状态申报节**（`docs/memory/<波次>/T-*_断点申报.md`）：开工即建、每完成一个里程碑追加一条，只写已验证事实并如实标注实证等级。断线后接力者**先读申报再跑测试再动手**。
- 平台 resume 通道不可靠（Sand traffic 错误）、断线后最终报告经常收不到——真实进度**以文件系统证据判定**（产物落盘时间戳、`cargo check`、`rg` 关键符号、代码内容核读），不以最后一条申报文字为准（申报可能落后于实际落盘）。
- 断线后起**全新收尾者**时，任务卡必须附"前任已完成清单"（逐产物：路径 + 判定依据），并明示"勿重做"；收尾者对清单逐项做文件系统核实后方可跳过。
- 前任写入可能延迟到达（波 1 实证：1b 收尾者遇 build_tasks 重复定义）——冲突时保留前任更完备版本，不盲目覆盖。

### 8.2 C4 未交付臂纪律（1c 已清零，纪律永久保留给未来变体扩展）

- EffectSpec 渲染 match **穷尽匹配、禁 `_` 臂**；扩展期间的未交付渲染臂必须返回**结构化 `Err("效果变体 X 的需求渲染未交付")` + 锁定测试**（混入假渲染即测试红），禁 `todo!()`/`unimplemented!()`。
- 1c（2026-09-06）后 16 变体全部真渲染、无未交付臂；本纪律的现行意义是**未来第 2 层新增变体时的中间态规范**（定稿 §5.3 扩展通道 2）：新变体从"加 tag + 诚实 Err 臂 + 锁定测试"起步，真渲染交付时翻转锁定测试。
- 样板/数据侧撞未交付臂时走署名 N/A 豁免（理由+说明+署名三非空）并**逐条上报**，交付后解除豁免改选正名选项重跑全链（5b/5d → 1c 的完整先例）。

### 8.3 融合玩法写作纪律（附录《极端组合形态测试》修正案 7）

- **core_loop 双环拉平写法**：融合玩法（X+Y）的 core_loop = 内环（X 的循环）+ 衔接动词 + 外环（Y 的循环）+ **回流动词**，拉平为单一动词闭环；"双环"只作报告层标签与文档注释（内环/外环动词区间）供人读，κ 判定只消费动词序列成员资格。回流动词必须存在——没有回流就不是双环是单向流水线（也合法，但 κ 会如实把上游判 strong 非 core）。
- **跨核映射表必须显式落为接口边 + TableSpec，禁止藏在机制参数里**——藏参数里会绕过 V6 悬空消费校验与 C 维接口边计数。归属给消费侧或独立适配系统的独占状态。
- 融合访谈必问跨核连接问句："两个玩法在哪里交换资源？"——答案即映射表草案（`concept.rs` 融合嗅探已内置）。

### 8.4 金样操作纪律

- **`golden_make.ps1` 无参数、恒写 `tests\golden`——跑它之前必须先备份该目录**（波 5 主开发误覆盖基准事故的直接教训；恢复只能靠 tag worktree）。正确流程：备份 `tests\golden` → 重固化 → JSON 级豁免清单比对（现行豁免 3 条：`$.graphs` 空数组 / `*.design_notes` / `$.custom_review_targets` 空数组）→ 确认干净或如实申报漂移 → 恢复或转正。
- 豁免清单固定不许随手新增；任何会让 `identity.frozen_hash` 漂移的改动（如给金样包加 system_refs）属金样重固化窗口专项，平时禁做（4b 发现 B）。

### 8.5 PowerShell 改文件纪律

- **禁止用 PowerShell 管道（`Set-Content`/`Out-File` 等）修改源文件**——PowerShell 5.1 会把 UTF-8 源文件写成 GBK（波 3 曾损坏 compose.rs，靠全量重写恢复）。改文件一律走编辑工具的全量写/精确替换。
- 附随已证事实：PS 5.1 脚本源文件需 UTF-8 带 BOM（0d）；命令行传 JSON 会吞引号，须转义函数处理（5a 的 ConvertTo-NativeJsonArg 先例）。

### 8.6 商业游戏名纪律（R5 词表）

- **pack 与系统模块的一切正文文案（summary/design_question/implications/机制口径描述）禁止出现具体商业游戏名**——`reference_games` 字段本身是换皮扫描词表源，正文出现即 R5 拦截（5c 首跑 C0 被拦的实证）。商业游戏名只允许出现在 `reference_games` 字段与换皮词表登记位；机制口径改用中性描述（如"时间戳制谱口径"）。

### 8.7 effects_template entity 引用纪律

- 模块与 pack 的 `effects_template` 中 entity 引用**一律 `{param:xxx_table_id}` 占位符 + 必填 scalar 参数，禁止裸语义名**——C1 `effect_dangling_entity` 要求 entity 是真实实体 id 或实体类前缀，裸语义名（`unit_entity`/`world_map` 等）真实项目激活即全链撞墙（5a 接力数据修复起立为硬纪律，5b/5c/5d/1c 沿用）。
- 已知基建缺口如实附注：Rows/Matrix 参数不走 `substitute_placeholders`（表结构选项的裸 entity 无占位符修复路线），登记量产波；在此之前表结构选项的 effects 引用须改走 scalar 表引用数据路线（1c 对 slot_legality 的处置先例）。
