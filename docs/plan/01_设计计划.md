## 3. 剩余设计缺口与设计决定

以下缺口按 `docs/design` 既有规格补齐，**不引入新架构**；每项列出设计决定，开发不得偏离。

### 3.1 设计空间深度（缺口：L6 数值表层薄、仅一个品类包）

- **决定 D1**：`lane_defense` 品类包补齐 L5 表结构 → L6 数值行数据的完整决策链；每个 L6 点的 `parameter_schema` 必须是 Table 或 Matrix，且带 `cardinality_expectations`。
- **决定 D2**：新建第二品类包 `grid_strategy`（战棋），L3-L6 全深度，作为"无品类污染"检验样本：两包除 universal 外零共享决策点。
- **决定 D3**：每包 `reference_games` ≥ 3；参考游戏名只允许出现在 `reference_games` 与换皮词表登记处，决策点/选项正文中出现任何参考游戏名视为违反 R5。
- **决定 D4**：既有决策点/选项的 id 一律不得删除或重命名（下游测试与存档锚定 id），只允许新增。

### 3.2 逆向工具链产线（缺口：仅有人工供证通道与模型骨架）

- **决定 D5**：`EvidenceSearchChannel` 落地为**本地语料通道**（`FileCorpusChannel`：从目录读取抓取快照做关键词检索），联网检索本期不做——保持 trait 可插拔即可。
- **决定 D6**：AI 映射服务（`MappingService`）接收 `&dyn AiProvider`，把证据候选映射为 `TemplateAnswer`，每条答案必须挂 `Evidence`（含 source_url），无证据 → 拒绝（R1）。
- **决定 D7**：交叉核验 = 用**独立第二次 AI 会话**对照第一次映射结果，输出逐条一致/冲突报告；冲突条目降级为"待人工"。
- **决定 D8**：认证状态机固定为 `Draft → Mapped → CrossChecked → HumanReviewed → Certified`，只能前进不能跳级；只有 Certified 模板可用于预填；认证时自动把游戏别名登记进换皮词表。

### 3.3 AI 访谈分层确认（缺口：无逐层推进策略与例外下钻测试）

- **决定 D9**：访谈按 L 层升序推进（L0 全确认才进 L1，以此类推）；同层内按 DAG 拓扑序。
- **决定 D10**：L5/L6 整表提案作为一个确认单元；用户可提交 `overrides` 做例外下钻（改若干行/格后确认）。
- **决定 D11**：AI 永不代提交：`confirm_proposal` 只能由 UI/CLI 的用户动作触发；`provenance` 固定 `AiInterviewConfirmed`；拒绝的提案留在待办。
- **决定 D12**：AI 输出非法（发明选项、非 JSON）→ 直接报错停止，不做静默修复（R7）。

### 3.4 交互壳（缺口：表格/矩阵编辑仍是 JSON 文本、无访谈/逆向面板）

- **决定 D13**：桌面壳补四块——L5/L6 结构化表格编辑器（行增删、格编辑）、访谈面板（提案→确认/拒绝/下钻）、逆向维护面板（产线五步状态 + 人工审核动作）、冻结门明细面板（五道门逐条 finding）。
- **决定 D14**：GUI 无业务规则：所有校验与状态迁移在 `AppServices` 后面，UI 只渲染 + 转发命令。
- **决定 D15**：CLI 与 GUI 能力对等：新服务方法必须先有 CLI 子命令（可脚本验收），再接 GUI。

### 3.5 Phase 2（P0-P5）

- **决定 D16**：本期不立项。`adm4-pipeline` 保留 `StageKind` 与产物存储的扩展接缝即可，禁止提前搭骨架。

## 4. 设计验收标准

1. 两个品类包 + universal 通过 `space validate`，且通过反污染检查（grid_strategy 不含任何 lane_defense 专属决策点，反之亦然）。
2. 逆向产线可用 ScriptedProvider 走完五步并落库一个 Certified 模板，其别名出现在换皮词表中。
3. 访谈可用 ScriptedProvider 从空项目推进到全部激活点确认，其中至少一个 L6 整表提案带例外下钻。
4. 冻结门五道对上述项目全绿并产出 FrozenDesign；C0-C6 全绿并产出双格式产物。
5. R1-R7 在默认产品路径强制生效（见工程规范第 5 节的红线检查清单）。
