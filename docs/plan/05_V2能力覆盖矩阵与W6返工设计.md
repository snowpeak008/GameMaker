# V2 能力覆盖矩阵与 W6 返工设计

> 日期：2026-08-29
> 背景：用户验收 V4 后裁定——内容实现与 V2 完全不同，未理解 V2 的内容设计逻辑与界面交互逻辑。本文档是返工波次 W6 的设计依据与验收基准。
> 用户三原则（不可违背）：
> 1. **UI 布局交互用 V2 的**（三栏工作台 + 顶部视图导航）。
> 2. **语义冲突以新设计为准，但新设计必须覆盖旧设计**——V2 每项能力在 V4 有明确归宿（保留或被吸收），不允许无归宿消失。
> 3. **设计流程不许清理缩水；开发流水线不许打断开发计划**（不能出现 C0-C6 之后断头）。

---

## 1. V2 内容设计逻辑（真相源：`RUST/` + `knowledge/design_data/`）

- **16 个设计领域**（顺序固定）：产品定位 / 核心体验 / 玩法系统 / 内容 / 经济商业化 / UX 界面 / 表现手感 / 平衡 / 社交社区 / 留存生命周期 / LiveOps 版本 / 数据验证 / 合规风险 / 文档协作 / 发行增长 / 上线就绪。
- 领域 → **设计节点**（`roleClass` 角色分类；`requires`/`unlocks` 依赖）→ **三级决策项检查单**（`outputKey`、关联 16 个共享元模板）→ **L4 选项组**（single/multi、required、allowPrimary 主选、MDA 层标注、designQuestion 设计提问、具体选项）→ **L5 实体**（`system_concrete`/`content_concrete` 节点的实体 JSON）。
- 配套：**26+ 内置游戏项目模板**（整套预填勾选，可载入/另存）、项目画像六字段（品类平台/目标用户/商业模式/美术风格/内容规模/上线节奏）、`cross_layer_rules.json` 跨层规则、玩法系统选项库。
- 交互心智模型：**按领域巡视设计完整度**——领域卡片进度 → 进节点 → 勾检查单 → 选 L4（可设主选）→ 填 L5 → 右栏实时看摘要/缺失/风险/校验 → 模板可整套预填 → AI 访谈补缺 → 导出。

## 2. V2 → V4 能力覆盖矩阵（逐项归宿）

### 2.1 设计工作台视图

| V2 能力 | V4 归宿 | 方式 |
|---------|---------|------|
| 16 领域总览卡片 + 进度 | **保留**（左栏） | 内容模型增加"领域"组织维度：决策点挂 domain 标签；领域进度 = 该域决策点完成度聚合。L0-L6 保留为深度维度（领域 × 层级二维组织） |
| 设计节点列表（roleClass/status/依赖） | **保留**（中栏） | V2 节点 → V4 "节点"实体（决策点分组单元），requires/unlocks 沿用 V4 现有 unlocks 机制 |
| 三级决策项检查单勾选 | **吸收** | V2 检查单项 ≈ V4 决策点；"勾选"语义 = 决策点已确认。检查单进度即节点内决策点确认数 |
| L4 选项组（单/多选、必填、**设主选**、MDA 层标注、设计提问） | **吸收 + 补缺** | ≈ V4 决策点选项。缺口需补：主选标记（多选组中标记 primary）、MDA 层标注、设计提问字段迁移 |
| L5 实体 JSON 编辑 | **保留**（已有升级） | V4 L5/L6 表格/JSON 双模式编辑已实现，挂到节点下呈现 |
| 节点文本（设计说明/风险说明/不适用原因） | **保留** | V4 已有 rationale（设计说明）；补：风险说明、不适用原因（不适用 = PointApplicability 人工豁免，需理由，进冻结门审计） |
| 项目画像六字段 | **吸收** | = V4 L0/L1 决策点（商业模式/平台/体验/品类等）的聚合展示卡片，数据不重复存 |
| 26+ 内置游戏模板（载入预填/另存） | **吸收** | = V4 模板体系（Template + 认证 + 预填）。迁移 V2 内置模板为 V4 认证模板（标注来源=v2 内置，走批量导入而非逐个逆向）；"另存模板"= 从当前项目导出模板（新增能力） |
| 右栏四页签：摘要/缺失项/风险/校验 | **保留** | 摘要=完成度聚合；缺失项=未确认决策点清单；风险=风险说明汇总+红队发现；校验=一致性/外键/冻结门预检实时结果 |
| AI 访谈（生成问题/记录回答/调用 AI） | **保留**（已有） | V4 分层访谈已实现，交互位置放回中栏下方 |
| 存档管理/保存/载入、重置 | **保留**（已有） | V4 ArchiveStore 已实现 |
| 导出（markdown 等格式） | **保留** | 工作台快照导出 + 冻结后 C1 产物导出并存 |

### 2.3 明确的"新设计覆盖旧设计"冲突裁决

| 冲突点 | 裁决 |
|--------|------|
| V2 检查单勾选（布尔） vs V4 决策点选项+参数 | 以 V4 为准（更强语义），勾选状态由"已确认"派生——V2 能力被覆盖，不丢 |
| V2 模板直接整套预填 vs V4 模板需认证才可预填 | 以 V4 为准（红线 R5/逆向证据链），迁移的 v2 内置模板走批量认证通道 |
| V2 无冻结概念 vs V4 冻结五门 | 以 V4 为准；冻结门预检结果进右栏"校验"页签，成为设计流程的自然末站而非另一套系统 |
| V2 Step00-14 vs V4 C0-C6+P0-P5 | 以 V4 分段为准，但视图上保持完整流水线版图（含 Phase 2 占位），映射关系在流水线视图内注明 |
