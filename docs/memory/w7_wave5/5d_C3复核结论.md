# T-W7-5d C3 user_prompt 属性值复核结论（审计 B 速修项欠账）

结论：**欠账属实，判定安全，已修**（非挂账）。修复 = 纯提示词增强，
金样实比对零漂移已验证（证据见 §4）。

## 1. 欠账核实（现状原文）

`crates/adm4-pipeline/src/c3_content.rs::describe_asset` 修复前的 user_prompt：

```text
实体：{name}（{id}），属性：{列键名逗号连接}
```

`EntitySpec.properties` 是 `PropertySpec { key, kind, constraint }`——**只有列结构
没有值**。金样 C3 产物里 7 条画面描述请求的属性段全是 `id, cost, attack,
attack_interval` 这类键名清单，画师拿不到「造价 120 的箭塔」和「600 血的首领」
的体量差信息。审计 B 速修项「C3 user_prompt 带属性值」欠账属实。

## 2. 安全性判定（为什么是修不是挂账）

金样红线优先，先查漂移面，三条证据链全部指向零漂移：

1. **金样产物不含 user_prompt 字段**。`tests/golden/lane_defense/C3/contract.json`
   只有 assets / ui_entries / non_visual_entities / cardinality 四段；document.md
   由 contract 渲染。AI 请求（system_prompt/user_prompt）不落任何产物文件。
2. **金样固化与比对链不消费 prompt**。golden_make/golden_diff 走
   `--scripted-file` 的 ScriptedProvider，按 purpose 出固定应答——prompt 内容
   变化不影响应答字节，`description.text` 与修复前逐字节一致。
3. **frozen_hash 载荷不含 C3 请求面**。修复不改 GameSpec、不改冻结集、不改
   任何 contract 结构。

风险面复核：修复引入「实体表行数据回查」（entity.id = `<表id>.<行键值>`，
复用 C0 `compile_entity_table` 的 id 约定），取不到行（非表派生实体/行缺列）
时**如实退回键名**，不发明数据——旧行为是新行为的子集，无 fail 路径变化。

## 3. 修复内容

`c3_content.rs` 新增 `entity_property_text(spec, entity)`：

- 表行实体：按 id 前缀定位所属 TableSpec，按 row_key 定位行，属性渲染
  `key=value`（TypedValue::render，与既有值渲染同口径）；
- 非表实体 / 行缺列：该属性退回键名（与修复前逐字节一致）。

修复后 user_prompt 示例（塔防样板实测）：

```text
实体：arrow_spire（towerdef.tower_roster.arrow_spire），属性：tower_id=arrow_spire, label=箭岭塔, cost=120, attack=18, fire_interval=1.2, range_cells=3
```

  但若该形态成为常态可在实体声明侧补值挂点。
