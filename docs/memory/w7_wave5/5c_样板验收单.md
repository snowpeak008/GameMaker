## 一、「判定事件→分数」供需链实证

供需链的三层机器证据（`crates/adm4-app/tests/rhythm_sample_e2e.rs` 两测试锁定）：

1. **命名咬合（入库门禁级）**：`sys.scoring_combo.interface.consumes` 含 `sys.rhythm_judgement.judgement_signal`（4a2 已入库，禁改）；本卡 `sys.beatmap_timeline` provides 裸名词 `judgement_signal`，与点号后段**逐字节一致**。dotted 门禁（`knowledge_modules.rs::dotted_interface_nouns_resolve_to_real_providers`）只核库内提供方——`sys.rhythm_judgement` 不在库内故该条按 V6 后置，咬合由下一层完成。
2. **装配级（V6）**：`rhythm_micro/pack.json` 把 scoring_main 的 `sys.rhythm_judgement.judgement_signal` 绑定到 `chart_main.judgement_signal`；加载器校验绑定目标必须是「某实例 provides 的名词」——装配成功本身就是供需边存在的证明。**反例锁死**：e2e 装配测试把绑定改指 `chart_main.ghost_signal` 后装配必须失败且错误点名 V6 与 judgement_signal（防「探针列静默放行」）。
3. **组合级 + 产物级**：组合报告零 block（V6 悬空消费未触发 = consumes 有源）；C4 断言判定机制 GWT 含「发出信号 judgement_signal」（供给端）、计分机制 GWT 含 `score_pool` 入账（消费端）——判定事件从谱面机制发出、被计分机制转成分数的全链在验收产物可见。

**历史前缀申报**：scoring_combo 消费名词的 dotted 前缀是 `sys.rhythm_judgement` 而非本模块 id `sys.beatmap_timeline`（4a2 落盘时 #29 未入库、模块名未定）。任务卡禁改既有模块，改我方咬合的路径 = 裸名词对齐 + pack 绑定桥接（V6 绑定按名词键匹配，不要求前缀等于提供方模块 id），零源码改动即闭合。后续若有修订 scoring_combo 的正当窗口，可把前缀更正为 `sys.beatmap_timeline.judgement_signal`（属文案级修订，绑定键同步改即可）。

**多事件源绑定申报**：scoring_combo 是横切束模块，consumes 还有 `sys.combat.hit_signal` / `sys.match3_board.match_clear_signal`。加载器 V6 要求 consumes∪modifies 每名词必有绑定（无「可选消费」表达位——结构性缺口候补，见遗留 1），本 pack 把三者全部绑到 `chart_main.judgement_signal`：音游语境下判定事件是唯一行为事件源，语义为「三个事件端口共享同一源」，不产生虚假语义。

## 三、Curve/Table 裁量（定稿 §5.4 逐案核，「音游谱面=Curve」判例）

| 表达位 | 裁量 | 理由 |
|---|---|---|
| `accuracy_curve` 偏差→精度换算 | **Curve 成立** | 单值 y=f(x)（x=\|偏差 ms\|，y=精度系数），无二维序列语义；e2e 实证 C0 编译为两列 (x,y) Table + linear 插值注记（波 1 Curve 通路的库内首个真实模块过链证据） |
| `speed_change_rule` SV 段落 | **退化 Table 申报** | 段落是 (start_ms, end_ms, factor) 区间闭合语义，单值采样点表达不了区间端点与重叠校验——四列 Table，语义降级在选项 summary 内如实申报，不假装闭合 |
| 谱面音符表本体 | **Table（非 Curve）** | 音符是(时刻,轨道,类型,时长)多列实体行不是单值函数——「音游谱面=Curve」逐案核的结论是否定，谱面走 entity_table 通路（每行产 EntitySpec，sprite2d 白名单） |

## 七、阈值体感

- **模块规模**：7 决策点 × 各 2 选项、3 档谱系——书写与自检约一人日内舒适；决策点 4-8 的任务卡区间体感合理，再多则单卡审读吃力。
- **档位五维**：BT1 定 W=8（中）刻意压在重核线 9 之下——微样板 |H|=0 使组合判定的「零提示零确认」路径也被覆盖到（既有样板全是超线路径）；BT2 W=11 如实进重，未虚标。
- **V6 无「可选消费」的代价体感**：横切束模块（scoring_combo 三事件源）在单品类 pack 里必须逐名词给绑定，同源多绑是当前唯一合法写法。写起来是三行样板代码，读起来有一瞬歧义（「为什么 combat 事件绑到谱面？」）——体感是轻度别扭但可解释，尚不构成上报级结构缺口；若后续横切束模块变多（≥3 个同类场景），建议波 6 评估 consumes 可选标记。
- **Curve 参数位**：CurveSpec JSON 手写体感良好（4 采样点一行写完）；「逐案核」纪律在本卡三处裁量（成立/退化/非 Curve）各有清晰判据，§5.4 的判例描述够用。
