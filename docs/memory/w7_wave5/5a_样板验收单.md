## 2. 四伤疤逐项证据

### 伤疤 1：DrawFromPool（定稿 §6.2 抽/弃/洗表达位）

- e2e 断言（C4 契约 `cap_deck_main.draft_pick_rule` 的 GWT Then）：
  `从池表 deck_main.card_pool 按规则 weighted_by_rarity_no_duplicate 抽取 3 个到 draft_offer`
  ——池表/规则/数量/目的地全部来自作者填写（I1）。冒烟段对 C4 文档做同文字断言。
- 谱系覆盖：db1 起 draw_discard_cycle（`shuffle_uniform_reshuffle_discard_on_empty`）、
  acquisition_channel（`weighted_by_rarity_exclude_owned`）同走 DrawFromPool 通路。

### 伤疤 2：叠加序（定稿指令 7 正式验收）

两个不同 priority 的 ModifyRule 遗物同靶 `combat_main.damage_formula`，C4 GWT 渲染出叠加序文字：

- 加法遗物（`relic_main.additive_modifier_rule`，flat_bonus=6，priority=10）Then 原文断言：
  > 规则 combat_main.damage_formula 的系数按 base + 6 缩放**（按 priority=10 结算，同序按机制 id 字典序）**
- 乘算遗物（`relic_main.multiplicative_modifier_rule`，multiplier=1.5，priority=100）Then 原文断言：
  > 规则 combat_main.damage_formula 的系数按 result * 1.5 缩放**（按 priority=100 结算，同序按机制 id 字典序）**

加法段（10）先于乘算段（100）结算——力量类先加、乘算类后乘，先后互换结果不同，
叠加序自此可声明可校验（指令 7 落点）。e2e 与冒烟段双处断言原文。

### 伤疤 3：Graph（acyclic 地图）

- e2e 断言（C0 契约 GameSpec.graphs）：恰一图 `spire.map_graph`，
  `directed=true / acyclic=true / entry=single / 3 节点`（floor_start→floor_elite→floor_boss，
  节点负载 node_kind 必填枚举）。冒烟段直读 C0 contract.json 做同断言。
- acyclic:true 显式声明使「不可回头」成为编译期可校验结构约束（假 acyclic 会被
  `graph_cycle_in_acyclic` 拦截，spec 级校验既有测试锁定）。

### 伤疤 4：R-C1′ 判定 + C6 跨机制依赖边

- R-C1′ 三查证据见 §1。
- C6 任务图：两件遗物的程序任务 `task_cap_relic_main.additive_modifier_rule` 与

## 4. 意图披露轻缺口注记（定稿 §6.2 如实标注）

`spire.intent_telegraph`（pack 层 L4 机制点，信息披露）声明「预告什么」
（full_disclosure=数值明牌 / category_hint=类别提示），**不声明「何时刷新」**——
披露时序（意图在回合内何时刷新、被状态改变后是否即时更新）是信息披露机制的时序语义，
当前表达位没有它的结构化落点。已如实写进该决策点 design_question 与两选项 implications
（「披露时序轻缺口：……未进结构化表达位，如实标注」），不假装闭合。
未来若时序语义进表达位（新效果变体或机制点扩展），按定稿 §4.4 扩展流程走，本卡不发明。
