# T-W7-4b 分母对账单

口径说明：`space validate` 输出的是装配后决策图点数（通用层 + pack 本体 + 模块实例化产物），
完成度分母是「Active 点数」的项目态子集；本单以点数为对账主口径，激活语义变化单列。

## grid_strategy（迁移包）

### 装配点数对账

| 项 | 迁移前 | 迁移后 | 差异 |
| --- | ---: | ---: | ---: |
| `space validate grid_strategy` 总点数 | 2610 | 2611 | **+1** |
| pack 本体决策点 | 20 | 16 | −4（四点迁出） |
| 模块实例化并入（实例 id=grid，allowed_tiers=MG0/MG1） | 0 | 4 | +4（同名同 id 回来） |
| tier 合成点 `grid.tier`（L3 单选 Unlocked，加载器合成） | 0 | 1 | +1 |

**总账**：迁出 4 回来 4 加 tier 1 = **+1**，与任务卡预测一致。

### 迁移四点逐项（装配后 id 逐字节保持，D4）

| 装配后 id | 层级 | 迁移前所在 | 迁移后所在 | tier_gate |
| --- | --- | --- | --- | --- |
| `grid.battlefield_system` | L3 | pack 本体 | sys.tactical_board（`sys.tactical_board.battlefield_system` 重写还原） | mg0_migration_base |
| `grid.move_rule` | L4 | pack 本体 | 同上 | mg0_migration_base |
| `grid.terrain_effect_rule` | L4 | pack 本体 | 同上 | mg1_terrain_carrier |
| `grid.terrain_table` | L5 | pack 本体 | 同上 | mg1_terrain_carrier |

配套同步迁移：基数期望 `terrain_types {4,12}` 从 pack 移入模块。装配时按
`<instance>.<key>` 规则重写为 `grid.terrain_types`，terrain_table 选项 schema 的
`cardinality_key` 被同一规则重写为同键——键匹配不断，space validate 通过。
涉及这 4 点的 pack 一致性规则：无（7 条既有规则均不引用迁移点，零同步项）。

### 激活语义差异（点数不变，unlock 来源变化，如实申报）

- 迁移前：`grid.battlefield_system` 为 pack 根点恒 Active；`grid.move_rule` /
  `grid.terrain_effect_rule` 由 battlefield_system 选项 unlock；`grid.terrain_table`
  由 move_rule / terrain_effect_rule 选项 unlock。
- 迁移后：`grid.tier` 为合成根点恒 Active 进分母（+1 的那 1）；tier 选项按档位 unlocks
  迁移点（MG1 = 四点全解锁；模块点选项自身的 unlocks 也按前缀重写保留，多一条激活来源不冲突）。
- 空项目初始分母：迁移前含 battlefield_system（根点）；迁移后 battlefield_system 改为
  tier-gated（tier 未选时 Inactive），改含 `grid.tier`——初始分母数值不变（一进一出），
  完整作答路径多一步「选 MG 档位」。C0 产物语义零 diff（unlocks 不进 GameSpec），
  由 `grid_migration_equivalence` 测试 + spec_diff CLI 双通道锁定。
