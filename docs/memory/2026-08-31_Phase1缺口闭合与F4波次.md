## 2. F4a 流水线控制（T13 的 H3 / H4 / M2）

- **强制重跑**：新增 `PipelineRunner::rerun_from` / `reset_from` / `downstream_stages`；`run_range` 原型行为一字未动（内部走永不取消的信号）。重置范围 = registry 顺序 ∪ `depends_on` 传递闭包（取更保守者）。重置范围内已通过的 C5/C6 人工门连带失效，原署名进 `StageResetReport.revoked_confirmations` 并落日志（R3：旧署名不得为新产物背书）。**先落状态、后删产物**——反序一旦中途失败会留下「状态称成功、产物已消失」的谎报。
- **协作式取消**：`CancelSignal`（`Arc<AtomicBool>`）在 `adm4-pipeline`，段边界检查，不打断段内 AI 调用。取消时当前段写 `Pending` 而非 `Failed`（用户主动停止不是失败），已完成段的成功状态与产物原样保留，下次断点续跑。新增 `PipelineRunOutcome{state, cancelled_at}` 让上层能区分「被取消」与「停在人工门」。
- **阶段产物查询**：`pipeline_artifact(archive_id, version, stage_id) -> StageArtifactView`。`document.md` 预览上限 256 KiB 且置 `document_truncated`，但 `bytes`/`sha256` 恒为整份文件真值（不让 UI 拿截断内容去核哈希）；缺文件 `document_text = None` 而非 `Some("")`；非法 UTF-8 直接报错不做 lossy 转换（R2）。
- 主开发抽查：取消写 Pending、重跑作废下游署名、失败安全顺序均已代码级核对。

## 3. F4b 创作侧能力（T13 的 H1 / H2 / M4 / 体检 / 耗时）

- **另存模板**（`template_export_from_project`）：只导出**已确认**的点（未确认的不当定论传播）；新增 `TemplateOrigin{Reverse | ProjectExport | BulkMigration}`（`#[serde(default)]`）；ProjectExport 跳过 S1-S3（无外部语料，跑一遍只会产出编造的证据）直落 `HumanReviewed`，reviewer+note 双必填，再由既有 `template_certify` 认证。**对逆向来源的证据要求同时加严**（必须有 `mapping_hash` + `crosscheck_proof` 且两者匹配），有单测与 e2e 双层钉住。
- **工作台重置**（`project_reset_workbench`）：清空选择/主选/参数/N-A 豁免/节点文本 + `template_mode`（预填选择已清空，留着就是状态里的假话）；保留项目名、已冻结版本、流水线产物、模板库、日志、访谈 transcript。actor+note 双必填，返回清空计数。
- **画像取点**：`GenrePack.profile_points`（可选，`#[serde(default)]`）驱动 `project_profile`，清单为空回退旧 L0/L1 过滤；`space validate` 拦未知/重复 id。两包各 14 个 id 覆盖 V2 画像六字段（美术风格由 L3/L4 点纳入）。**纯展示取点，完备度分母不变**，有 e2e 逐项比对钉住。
- **体检上提**：`project_doctor` / `ai_doctor`（后者无 `Result`，永不 Err——「AI 不可用」是它要报告的结论而非它自己的失败）；CLI 输出与退出码语义逐字未变。
- **阶段耗时**：`StageRecord.started_at` + `duration_seconds()`（缺时刻/倒序/格式不认返回 `None`，不拿 0 秒冒充）；runner 每段执行前落一次 `Running`。取消判定**排在落 Running 之前**——反序则进程崩在两次写盘之间会留下永远「正在跑」的幽灵段。

## 4. F4c 桌面端接线

- **AI Provider 配置面板**（T13 定为实质缺口：桌面用户此前走不通访谈/红队/流水线全链）：查看/编辑/preset 套用/保存并诊断/停用；不可用在面板、状态栏、底栏三处红字如实显示（R7）。
- **流水线视图**：范围运行（段清单来自 `design_compile_registry()`，UI 不硬编码）、停止运行（工作线程 + `CancelSignal`，文案写「将在当前阶段结束后停止」而非「立即中止」）、阶段重跑（两步确认，警示条列出后端算出的下游清单与将作废的署名）、阶段详情（状态/耗时/产物预览 + 路径 + sha256 前 12 位 + 截断提示）、运行中状态（`slint::Timer` 每 2 秒轮询，不轮询则 `Running` 永远不会出现在屏幕上）。
- **另存模板 / 工作台重置 / 存档体检**入口齐备，破坏性操作二次确认 + 必填由后端拒绝、UI 只转发。
- `Rc<AppServices>` → `Arc`；工作线程回 UI 走 `Weak::upgrade_in_event_loop`。主开发抽查确认门控在 Rust 侧按后端状态推出，Slint 只渲染（D14 未被破坏）。
- **Slint 坑（留给后人）**：`.slint` 文件工作区搜索工具搜不到，查 id 冲突须用 `rg -n "^\s*[a-z0-9-]+ :=" ui/main.slint`；`ComboBox.current-value` 是单向绑定，点击时要读控件当前值而非 root 属性；回程闭包必须 `Send`，不能带 `Rc<RefCell<_>>`。

## 5. F4d 红线补漏与配置能力

- **换皮词表按项目排除（R5 漏洞）**：F4b 曾让 ProjectExport 不贡献词条以免源项目被自己名字拦住，但这留下跨项目漏洞（A 导出模板 → B 预填 → B 产物带着 A 的名字过门）。改为**照常登记 + 扫描时豁免自身**：`SkinScanner::with_exemptions` 在构造时把豁免词从生效词表剔除（`scan` 无第二套判定）。豁免作用域刻意收窄：**只豁免当前项目名、只按归一化整词相等**，别名与子串一概不放行。产物落盘钩子用 `frozen.project_name`（产物由冻结版本渲染，改名不应让旧版被自己的旧名拦住），创作态侧用 `state.project_name`。
- **认证证据旁路收口（R1/R3 漏洞）**：25 份内置模板此前由迁移工具直接写死 `Certified`，不经 `certify`，而取用只看状态位——手工塞一份 JSON 即可获得预填资格。现 `approved_for_prefill` 除状态位外一并要求证据；批量迁移作为显式第三来源 `BulkMigration{batch_id, tool_version, source_ref, answers_digest, migrated_at}`，其中 `answers_digest` 由 Python 与 Rust 两侧共同实现、取用时现算比对。**已知局限**：digest 只覆盖答卷结构，不覆盖 `parameters`/`evidence`（其 canonical 形态依赖 serde 枚举表示，要求跨语言逐字节复现会变成隐式契约），故字段名为 digest 而非 content_hash。
- **配置热更新**：`AppServices.config` 改私有 `RwLock` + `reload_config()`；不选「每次现读」是因为那会让「当前生效配置」失去单一真相。`design_space_root` 排除在热更新外并显式要求重启（它是决策图与模板库缓存的锚）。F4c 的「每次 AI 动作重开门面」绕过已删除。
- **密钥写入**：`ai_save_secret` 写 `config/secrets.json`，值不进回执（只回名字+字符数）、不进日志、不进存档；桌面端密码框可直填。
- **AI 实调用检查**：`ai invoke-check`（CLI + 桌面），发一次最小真实请求，失败原样上抛不美化（R7）；与 `ai doctor`（零网络查配置）的语义区分写进 help 与 UI 文案。
- **反转的既有断言（3 处，均为「断言写着漏洞本身」，主开发已核准）**：`project_export_contributes_no_skin_words`、e2e「认证后词表不变」、冒烟「换皮词 0 个」——它们断言的正是任务 1 要修的漏洞。前三轮新增的 48 个测试无一被删除或 ignore。

## 5.5 F4e 换皮豁免收窄 + CLI 补齐（T13b 的 R1 / R3，Phase 1 最后一个开发任务）

> F4e 子 agent 在自验收扫尾阶段被用户中断（未交报告），产出由主开发逐项验收：代码、测试、冒烟均完整，六项门禁复跑全绿，按完成验收。

- **豁免收窄（修 T13b 发现的窄缝）**：F4d 的豁免按词面剔除，项目取名恰好等于某逆向外部游戏名（如「Kingdom Rush」）会让该外部名对本项目整体失效。现改为**豁免集合限定为「由当前存档的 ProjectExport 模板登记的词」**：`skin_scanner_for_project` 增收 `archive_id`，`skin_exemptions_for_project` 溯源模板文件的 `origin`（来源权威记录是模板自己的 origin，词表不再抄一份，避免双真相）；带快路径（项目名不在词表时不翻模板库）。四条钉子测试：① A 自己产物含 A 名不拦；② B 带 A 名被拦，且 B 冒用 A 的词面当项目名也拿不到豁免（豁免看登记的存档 id 不看词面）；③ 逆向外部游戏名两种视角照旧拦；④ **同名缝已堵**——项目取名等于外部游戏名时该词仍在生效词表（词表层 + 冻结门 `reference_name_hit` 行为层双断言），且词条同时有逆向来源登记时豁免立即撤销。
- **CLI 补齐**：新增 `sdk`（list/add/approve/reject）、`change`（list/add/set-impact/advance）、`deliver`（package/status）、`authoring add-option / remove-option / set-primary` 子命令组，全部只做转发与呈现（业务校验在服务层），中文 --help 与总用法已更新。冒烟新增段覆盖 SDK 三态（含重复审批负例）、变更流线性推进（含跳级负例）、交付清点、多选设主链路——T12 三视图与多选主选从此进入冒烟回归。
